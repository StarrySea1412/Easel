## 原因与修复

### 审查结论没有绑定实际交付文件

此前结构化审查冻结阶段交接文件，却没有冻结总目标明确要求的实际文件。交接说明未变时，实际HTML、CSS依赖被改写或删除，旧pass仍可能用于交付；缺失实际产物也可能收到模型pass。

- 审查契约内部schema升至2，冻结目标中明确file验收项的路径、状态与版本；复用现有文件核验和HTML/CSS本地依赖哈希，不增加另一套清单。
- 审查结束重新核对当前产物；目标文件缺失、依赖未通过或审查期间变化，不能标pass。材料不足仍可blocked或按现有限次机制revise。
- 派发前、后续阶段结算以及人工确认/重新核验入口检查已审查版本；交付阶段不能改写文件后沿用旧结论。变化后保留记录、等待重新审查，不自动重发。
- 文件不变时可跨TaskStore重启继续；最终仍等待用户质量验收。没有新增页面、角色面板或常驻解释文案。

绑定范围是目标明确声明的文件和现有核验器支持的本地依赖，不从模型正文猜造产物路径；哈希一致不保证语义质量，也不提供操作系统隔离。

### CLI主模型诊断误要求API Key

主模型选择Claude/Gemini CLI且命令可用时，普通doctor仍强制要求.env API Key。现复用既有CLI选择检测，明确显示“未验证登录”，由easel ping核对登录与模型可用性；保留OpenClaw路由、API及安装模式检查，不读取或迁移凭证。

### 当前运行契约回归

迁移重复准入、停止结算、超展示上限旧生图、HTTP/raw正文与思考、Codex历史输入、技能列表/附加要求、审查规则版本、健康探针和安装守卫的旧替身。保留重复请求无副作用、原请求不变、原身份取消、账本结算、内容去重和数据保留断言，没有恢复废弃产品API来迎合测试。
