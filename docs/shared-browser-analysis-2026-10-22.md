# 网页分析与人工操作共存：Codex 对照与 Easel 诊断

日期：2026-10-22。状态：诊断已完成，并已实施0.13.3修复；本地隔离验收见[实施回执](shared-browser-0.13.3-2026-10-22.md)。未验证或更新138运行构建。

## 1. 用户问题与结论

用户询问“codex是如何做到能够分析网站的同时，我还能操作网页的呢？我发现我的那个是并不可以的”。截图展示Codex浏览器里的138登录页及站点信息菜单，证明用户可以操作浏览器界面；不证明模型正持续读取页面，也不能从截图确定桌面壳实现。

核心区别是用户面对的网页视图是否独立于Agent读取/推理运行，以及人工输入是否具备直接通道。模型得到某一时点的页面证据后分析，不要求页面在整段推理期间锁住。用户继续导航后，后续结论和动作必须重新核对页面版本；同页双向操作不意味着可以无约束地同时填写/提交。

## 2. OpenAI 官方资料实际说明什么

本轮读取 [OpenAI Docs：Browser](https://learn.chatgpt.com/docs/browser)（及同页Markdown）。官方说明：桌面内置浏览器让用户和ChatGPT共享网页与本地应用视图；可以手动打开页面、直接登录；Codex可打开、点击、输入、检查渲染状态并截图。常用浏览器的现有标签/配置需另一条浏览器扩展路径。

官方还说明开发模式可在授权后提供完整CDP用于DOM、样式、网络与性能诊断。不能因此写成“所有浏览器操作都必须完整CDP授权”，也不能据此认定桌面采用Electron/WebView2、公开了内部输入调度算法，或模型每时每刻看见用户操作。浏览器界面可交互、工具能读取、模型在分析三个事实要分开。

## 3. Easel 源码核对

| 范围 | 证据 | 判断 |
| --- | --- | --- |
| 交付分支0.11.2，`efd46138` | `ChatLiveBrowser.tsx`：截图`img`包在按钮内；`busy = Boolean(requestId || liveJob)`，`usable`要求`!busy`；`browser_api.py`无cast/input接口 | 不是可原生操作的浏览器视图；当前页面操作未结束时，点击、滚动和地址栏会受busy影响 |
| 已存在的0.13.2分支，`f3fb4561` | 同样的截图/disabled机制；`browserLive.ts`不存在，API无cast/input；后端Chromium默认headless | 新版本号本身并未带入实时输入实现；不是模型更换就能解决 |
| 独立实时分支，`C:/project/Easel-live-view`、`c9af58d6` | `Page.startScreencast`、`/tabs/{tab}/cast`、`/tabs/{tab}/input`、`browserLive.ts`均在位 | 曾有画面流与人工输入实现；但不在上述两个交付分支里；本轮只读代码，旧验收不算本轮通过 |

后端 `easel/browser_runtime.py:_command/_execute` 对同tab活动job拒绝重叠请求，`tab.lock`包住动作、可能的导航等待及观察；操作总deadline30秒。快照变化时旧snapshotId被拒。前端又用busy挡住人工动作，因此网页自动化等待时用户难以接手。这个锁跟浏览器job有关，**源码不能证明整段模型推理始终持有该锁**。

实时分支也仍有同tab锁：`_input()`在锁占用时返回409。所以仅移植帧流，虽能恢复点击输入体验，也不等于完成用户优先的接管机制。不能简单删除所有互斥或允许过期元素继续点击。

`git merge-base --is-ancestor c9af58d6 f3fb4561`返回1；两分支差异显示实时输入辅助文件在0.13.2缺失。能证明没有包含同一实现，不能仅凭该结果断言是哪次合并删除了功能。138本轮未查询版本、会话或浏览器面板，不把源码结论冒称线上复现。

## 4. 应如何补齐

1. Web交付先复用已有画面流与输入实现，明确迁移兼容性，不另起同名浏览器；桌面原生视图作为独立方案，普通iframe不能保证任意网站可嵌入。
2. 区分模型分析、页面观察、页面动作、人工输入四种状态。模型正在分析不是禁用人工页面的条件；画面流不等待模型返回。
3. 人工点击/输入触发用户接管，暂停新的Agent页面动作；当前动作有界取消/收尾后再接收输入。取消超时需重新对账，不能假称没执行；不要重放未确认点击。接管不应取消整个聊天分析。
4. 使用页面代次/版本及必要的DOM变化检测：导航、人工修改表单、切tab后，旧动作与旧结论的适用范围需重核；用户输入过程中不能自动观察抢焦点或改变页面。
5. 用户接管后Agent恢复动作前重新观察并确认当前页面。保留既有站点权限与会话/账号隔离；人工登录提供专用可信输入路径，避免密码进入模型正文、工具参数持久日志或截图证据。
6. 无真实数据时保留快照与loading icon，连接中断可恢复观察；恢复连接不等于重发点击、模型请求或发布。

## 5. 诊断时提出的验收清单（最终结果见实施回执）

- [ ] 模型分析期间，人工可点击、滚动、中文输入、粘贴与导航。
- [ ] Agent导航/慢请求中人工接管不会丢输入、相互覆盖、重复提交；取消副作用不确定时如实处理。
- [ ] 人工改页后旧元素引用拒绝执行，后续Agent观察同一实际tab；原分析可继续但标明材料时点。
- [ ] 切页、刷新、断线恢复、窄面板和键盘焦点正常；同账号/跨会话权限不串。
- [ ] 可信登录输入不进模型/日志；本地真实浏览器验证、隔离实例验证、138实际部署身份分别记录。
