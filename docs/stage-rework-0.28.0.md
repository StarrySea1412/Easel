# Easel 0.28.0候选：指定阶段重做

2026-10-26，基于e7bbdd03继续完整竞品对标和大版本迭代。本批补齐顺序角色协作中的人工返工，不替代完整历史清单；0.23定时任务、响应式、经验候选和共享上下文预算保留。

## 行为

任务工作区“进展与交接”的原阶段详情增加“从此阶段重做”。选择起点后显示所选阶段及全部后续阶段，填写原因并确认。服务保存旧阶段正文、文件检查证据、轮次、步骤与原验收快照，再创建新的目标版本：保留起点前已经完成的阶段，所选阶段及下游变为pending，原质量确认清除。文件与历史运行不删除，也不恢复成历史字节。

准备后目标保持paused，不调用模型、启动Agent或启用排期；在“验收与控制”沿用“继续目标”。已用轮次、时长、工具和图片预算保留；剩余轮次至少覆盖待重做阶段，否则需保留历史并新建目标。各阶段原角色契约及累计尝试次数保留，新轮次标记reworkId。

继续后，保留上游仍需通过原文件版本核验；各下游必须生成本阶段的新文件版本，旧文件存在不算新交接。重做原因和旧阶段回执（单段最多2000字符，完整正文在持久回执）作为已被替代的参考材料进入请求，不能冒充当前完成证据。语义质量、自动审查返工及并发/层级调度不属于本批；仍由用户做最终质量确认。

## 一致性与接口

- `POST /api/tasks/goals/{id}/rework`：stageId、revision、requestId和reason（3–1200字符）。同一请求重试返回原回执和当前目标；同ID不同参数或陈旧revision返回409。准备及回执处于同一SQLite事务。
- `GET /api/tasks/goals/{id}/reworks`：按需读取原阶段回执，Cache-Control为no-store；不将全部原文塞入任务列表轮询。界面默认折叠旧记录，不用当前工作文件链接冒充历史文件副本。
- active、completed、cancelled、已删会话，以及仍有queued/running/unconfirmed轮次、聊天占位或未结算图片时拒绝准备；仍未执行的下游无需再次重做。锁顺序与图片提交一致，先图片队列、后任务事务，保持核对期间图片队列稳定。
- 核对起点前的阶段均completed且文件版本未变化；变化时从更早阶段重做。重做后继续派发前再次核对。目标revision与stopEpoch递增，旧终态回调不改写新阶段，重复确认不消耗新轮次。
- 本批仅用于现有OpenClaw持久目标；不新增Codex目标调度、外部运行接管、后台云执行或电脑唤醒能力。周期计划本身不修改，单次目标的重做不表示计划结束或自动改变下次排期。
