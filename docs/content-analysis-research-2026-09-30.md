# Easel 内容分析：调研、产品设计与实施方案

日期：2026-09-30（Asia/Shanghai） · 状态：调研与设计，本文的新页面、数据模型与接口均为待实现方案。

## 1. 产品结论

内容分析应成为独立工作页面，回答三个连续问题：**哪些内容值得继续做，具体哪里可以改，下一篇怎样验证改进是否有效。** 账号中心负责连接、身份和授权状态；内容分析负责复盘与创作决策；运行记录负责 Token 和 Skill 执行证据。三者互相链接，但不能把运行成功当内容效果好，也不能把内容效果变化归因于某次 Skill 调用。

好的首版不是塞满七个平台的同款图表，而是让用户能从一条可信发现进入原作品、看到计算依据、形成可编辑选题，再在发布后回收结果。所有页面都应支持“资料不足但仍可做内容创意”的合理降级。

本报告与两个附录共同构成详细方案：

- [七平台数据审计与源码证据](content-analysis-data-audit-2026-09-30.md)：哪些字段目前能提取、样本上限、身份与历史缺口。
- [分析方法与验收规范](content-analysis-methodology-2026-09-30.md)：完整指标字典、样本规则、六维诊断、AI 证据契约、16 个验收场景。

## 2. 调研方法和证据边界

本轮并行完成源码审计、分析方法审查，并在真实浏览器阅读下面的公开官方页面。产品官网只能证明其公开描述的设计能力，不证明商业效果，也不表示本轮登录试用了付费后台。没有使用真实用户账号调用这些平台接口。

| 来源 | 实际观察 | 对 Easel 的启发 | 不可据此承诺 |
| --- | --- | --- | --- |
| [Buffer Insights](https://buffer.com/insights) | 跨渠道概览、单渠道下钻、指标定义与更新频率、标签、重点作品、周度行动建议与创作入口 | 概览控制信息量；每个指标解释口径；发现直接进入创作 | 官网示例数字、增长收益或其平台覆盖可以复制到 Easel |
| [Sprout Social Analytics](https://sproutsocial.com/features/social-media-analytics/) | Profile、Post、Tag、Network、Competitor 等报告；自然与付费表现分开 | 账号、作品、主题各有分析层级；投放是比较条件；筛选及报告复用 | 竞品数据完整可得、跨网络数字天然可比、营销文案中的 ROI 已被本项目验证 |
| [微信数据统计接口介绍](https://developers.weixin.qq.com/doc/service/guide/product/analysis_data/analysis_data.html) | 推荐保存已获取数据；前一天数据上午 8 点后查询；区分每日、期间概览和发表内容明细 | 本地快照、延迟状态、明确时间口径；少量活动缺失不能补零 | 总述页面的账号描述可以代替各具体接口适用范围 |
| [微信发表内容详细数据](https://developers.weixin.qq.com/doc/service/api/wedata/news/api_getarticletotaldetail) | 稳定 msgid、发布日期、stat_date、阅读来源、完成率、时长、跳出区间、关注等 | 公众号后续可做有依据的阅读结构和转化诊断 | 当前采集器已经拥有这些字段，或所有账号都有权限 |

微信细节必须按端点解释：总述里“小活动量不返回”的规则针对图文群发每日数据，不扩展到所有接口。详细数据页明确：查询日期范围仅 1 天，结束日期最大昨日；每篇只统计发表日起 30 天内数据；存储起点为 2025-11-01；返回 is_delay。页面适用范围列出企业主体已认证公众号和服务号，实际可调用性仍须按具体账号权限验证。detail_list 的统计值表示发表日期到 stat_date 的期间累计，不能把各 stat_date 累计值再次相加。

这些限制直接影响产品，而不是藏在开发备注里：例如“过去一年的逐日完读趋势”不能由该端点直接承诺；一个月前文章后续增长也不能靠它无限追踪。其字段 read_user 应保留官方定义，不能擅自宣称跨日去重规则。官方表格把 is_delay 定义为 boolean，示例却写字符串，适配器应显式处理已知类型并记录异常，不能让字符串 "false" 被当真。

## 3. 当前产品为什么还不够详细

当前多平台面板主要展示本次采集的概览、平台指标文案和有限作品；详细程度不同于长期内容诊断。

| 平台 | 当前代码能力摘要 | 第一优先补充 |
| --- | --- | --- |
| 小红书 | 账号隔离、JSON 导入、逐篇赞藏评、标题标签探索、证据入选题；当前页面最多 20 篇 | 发布时间和格式完整性、更多分页、同龄快照；“获赞与收藏”与点赞分开 |
| B站 | 第一页最多 6 篇，部分作品有播放/赞/评/藏/分享结构化值 | 通用账号身份、发布时间、分页、增量的具体周期 |
| 公众号 | 最多 20 篇输出，发表页阅读/点赞，部分趋势与分析文案 | 稳定文章 ID 关联；消除缺值变零；真实期间；合资格账号官方接口试点 |
| 抖音 | 最多 6 条标题与统计文案，首页近 7 日概览 | 稳定作品 ID、结构化逐篇数值、日期和分页 |
| 快手 | 最多 6 条，播放/赞/评文案 | 已发布状态过滤、作品 ID、日期、具体周期 |
| 知乎 | 最多 6 条，阅读/赞同文案，部分回答/文章链接 | 完整标题、类型、ID、日期和明确累计状态 |
| 视频号 | 首页有限指标与最多 8 条尽力匹配的链接 | 真正逐篇数据、链接类型、账号身份、时间范围 |

以上是代码提取路径，**不是七个平台当前真实采集成功率**。六个平台网页历史增长已被主动置空以防串账号，应保留这项保护，待稳定身份和历史归属落实后再开放。

优先修正的具体误导：公众号按标题合并导致同名文章错配；缺失字段输出零；最近 365 条日记录不一定一年；小红书关键词窗口是采集窗口而非发布时间；只有最近两次快照不能画全年每日曲线；管理页链接不应叫“作品原文”。详细代码位置见审计附录。

## 4. 用户任务与成功标准

| 用户问题 | 页面应给出的结果 | 完成动作 |
| --- | --- | --- |
| 最近内容好在哪里、差在哪里？ | 明确范围的指标分布、代表作品和反例，区分总量与单篇变化 | 打开作品和指标依据 |
| 什么题材值得继续？ | 可纠正的主题分组、覆盖篇数、同条件表现、待验证机会 | 保存主题或转选题 |
| 这篇为什么没有达到目标？ | 按实际材料诊断标题/封面/结构/评论；效果原因只写假设 | 生成修改草案 |
| 下一篇怎么写？ | 具体读者问题、角度、提纲、标题方向、素材需求和主指标 | 加入选题并编辑 |
| 上次改动有用吗？ | 预设目标、回收快照、可比结果与不确定性 | 继续、改方案或停止 |
| 数据靠不靠谱？ | 身份、来源、日期、覆盖、缺失、延迟和导入记录 | 补采集、导入或更正 |

产品自身衡量“能否完成这些动作”：从发现到证据展开成功率、建议采纳及人工改动、选题到发布关联成功率、按期回收率、错误引用率。不得把用户点了建议或多发了内容当作内容增长已验证。

## 5. 信息架构与页面布局

侧栏新增一级「内容分析」，账号中心保留「查看该账号分析」跳转。分析页包含五个页签：**复盘总览、作品分析、主题与形式、行动与实验、数据与口径**。单篇详情采用可直接链接的详情页；宽屏也可先用右侧抽屉快速预览，深度阅读再进入详情。

全局筛选固定为平台、账号、发布范围、观察口径、内容形式；高级筛选再放主题、投放状态、内容状态和资料完整性。默认单平台单账号，避免七张平台卡占据首屏。平台选择使用已有真实图标配名称，账号显示昵称和可辨识 ID。更换账号立即清理上次结论的呈现，异步返回必须核对账号版本。

### 5.1 复盘总览

```text
内容分析                             数据更新于…   更新数据   导出
平台 ▾ 账号 ▾ 发布范围 ▾ 观察口径 ▾ 更多筛选
已覆盖 N 篇 · 可比较 M 篇 · 缺失 K 篇 · 查看范围说明

目标指标       对应阅读/播放      收藏或分享       发布数量
数值/中位数    实际口径           根据平台选择     与单篇表现分开

表现趋势（约 2/3 宽）             本期值得关注（约 1/3 宽）
明确日期、缺口、样本量             最多 3 条发现 + 证据入口

值得复盘的作品                    下一步行动
代表作 / 待改进 / 异常             动作、理由、资料要求、转选题
```

首屏只放 3–4 个与目标相关的指标，不按平台字段数量堆卡片。默认目标可选“沉淀收藏”“促进讨论”“扩大触达”，有合格数据时才提供“关注转化”。系统不能因为缺曝光就偷偷把目标改为点赞。

趋势允许切换原生期间数据和快照变化，标签明确不同口径；缺数据处断线，鼠标和键盘可查看同样的提示；提供数据表视图。混合量纲分图，不用双轴制造相关感。比较期开关仅在两个时间段和口径真实可比时可用。

### 5.2 作品分析

默认紧凑列表：封面、完整标题入口、平台、发布日期、观察年龄、主指标、参考指标、资料状态。列可选择，排序说明是“累计数”还是“发布后 7 天”；不可比较项移到独立分组并解释，未知不能排作零。

搜索针对已采集标题、标签和可用正文，显示搜到的是哪个范围；不会误称全平台搜索。支持选 2–4 篇并排比较，这是产品初始交互设定；列出不同年龄、格式、投放、主题干扰，用户可看原始数但不生成不合格的优劣结论。

单篇详情从上到下：作品与原文入口 → 目标与同口径表现 → 发布后快照 → 内容六维诊断 → 评论样本 → 修改建议 → 关联选题/实验。封面原图加载失败有独立状态，不用空图片继续输出视觉分析。

### 5.3 主题与形式

主题是可编辑分组，不是把分词结果当行业赛道。每组显示标题、定义、代表内容、有效样本、同龄中位数、分布与反例。允许多标签，注明组间作品可重复，组总数不可相加。

形式包括图文/短视频/长视频等实际类型；时长分组仅在有时长字段时出现。标题特征、内容长度、发布时间都属于探索筛选，不直接叫“成功秘诀”或“最佳发布时间”。缺少充分分布时展示历史分布，提示先补样本。

### 5.4 行动与实验

列出待考虑、已加入选题、待发布、待回收、已复盘。每张卡显示改什么、为什么、引自哪些作品、主指标、复盘时间及当前阻碍。进入详情可编辑假设、控制条件、成功标准、制作成本和停止规则。

不默认提供“自动发布”。保存选题后明确显示保存位置并可跳转；失败保留草稿。实验完成允许“未支持”和“证据不足”，不能只展示成功案例。

### 5.5 数据与口径

集中展示采集任务、导入预览、账号核验、字段覆盖、缺失原因、时间线、指标字典、原始与规范化值、导出范围。普通用户在主页面看到一句简洁摘要，复杂字段按需展开。

## 6. 视觉与交互细则

延续现有纸色 #faf9f6、墨色 #292823、陶土 #a85f43 和 8–12px 圆角；不要新增一套亮紫色大屏风格。标题、筛选、数据、解释、操作分别建立层级：建议页面标题 26–28px、正文 14–16px、数值 24–28px，实际以可访问性和密度试验调整。

数字右对齐并使用等宽数字；表头写单位；比率同时保留分子分母；正文不滥用红绿。上涨不一定好，例如负反馈上升；状态颜色根据业务语义。图表除颜色外配线型、标记和文本，不用无意义饼图填空。

宽屏采用主内容与行动栏，1100px 以下收为单列；760px 以下筛选分行、作品表换信息卡，详情独占页面。沿用现有断点习惯，最终验收至少覆盖 1440、1024、720、390px。筛选变化保持滚动合理，键盘焦点回到触发处；弹层支持 Esc、明确标签和焦点约束。

数据状态必须区别：

| 状态 | 显示与下一步 |
| --- | --- |
| 未连接 | 说明分析用途，按钮去账号中心，回来保留平台选择 |
| 已连接未采集 | 显示账号身份与“获取数据”，不展示虚构统计 |
| 采集中 | 显示真实阶段和已取页数，可取消；不估算假百分比 |
| 部分成功 | 保留结果，标明漏掉的页/字段，可从游标继续 |
| 没有符合筛选的作品 | 清除筛选入口；与平台真无作品分开 |
| 登录失效 | 旧数据保留采集日期，入口重新连接，不能显示实时 |
| 数据延迟 | 显示平台标记与已知截止日，不以抓取时间充当最新 |
| 模型失败 | 事实统计仍可用，解释模块单独重试 |
| 样本不足 | 给个案与资料建议，禁用稳定规律判断 |
| 功能未支持 | 解释所需字段/权限，给可用导入路径；不展示永远旋转的加载态 |

## 7. 分析必须深入到内容本身

| 分析层 | 需要的证据 | 应交付的具体内容 |
| --- | --- | --- |
| 主题与读者问题 | 标题、标签、正文或字幕 | 内容主题、解决的问题、场景、重复覆盖与空缺；人工确认分组 |
| 标题 | 原始标题及同条件表现 | 对象/场景/收益/约束是否明确；3 个不同角度改写及适用情境 |
| 封面 | 实际封面图片 | 主体、文字层次、可读性、信息重复；明确区域引用与改版说明 |
| 正文/视频结构 | 全文、字幕；视频诊断另需视频画面或时间码 | 开场承诺、论证、步骤、实例、结尾；引用段落或时间码后提出修改 |
| 互动与需求 | 评论原文、采样方式、作者回复标记 | 重复问题、误解、补充需求、下一篇答疑；显示样本偏差 |
| 阅读/转化 | 同窗口、可归因的阶段数据 | 在实际有数据的环节定位损失；缺阶段不强拼完整漏斗 |

标题、封面、正文之间还要分析“承诺是否一致”：标题说提供模板，正文是否真的有模板；封面强调 3 步，内容是否能核对出 3 步。此类结构检查可先做，且与增长预测不同。

没有封面时不能评价配色；只有字幕不能评价剪辑；只有热门评论不能推断全体满意率；没有平台曝光点击指标不能断言封面点击率低。AI 可以提供创作假设，但必须将“素材可观察事实”和“效果解释假设”分开。

## 8. 指标、可比性与统计规范

完整公式见方法附录。产品必须至少强制以下规则：

1. 每个数值有平台原名、定义版本、单位、聚合类型、观察日期和来源。获赞与收藏不改名点赞；日阅读人数相加不叫区间独立读者。
2. 未采集、无权限、解析失败、未提供、真实 0 分开存储；分母 0 时比率不可计算。
3. 比较默认同账号、同平台、同形式、同投放状态、同发布年龄。没有历史快照不能从今天的累计值倒推出发布第 7 天表现。
4. 24h/72h/7d 是建议采集目标，记录实际时间及偏差；错过不插值冒充实测。
5. 聚合事件率 = 有效同范围事件总数 / 对应有效分母总数；逐篇率均值是另一指标，不能混名。缺任一分量的作品按明确规则排除并披露。
6. 以作品为分析单位，显示有效 N/总体 N、中位数、均值、分布和异常值。播放次数不能当作独立实验作品数。
7. 多主题探索会碰巧产生“冠军”；预设假设或用独立下一批验证。样本门槛是产品初始策略，不是到达 20 篇就证明规律。
8. 累计下降保留为修正/异常；不截成零，不直接称用户流失。净增粉丝也不是某篇带来的关注数。

例如假设数据：同账号、同格式、同为发布后第 7 天，A 阅读 10,000、收藏 200，B 阅读 2,000、收藏 80。A 收藏更多，B 收藏率 4% 高于 A 的 2%；合并率为 280/12,000≈2.33%，不是逐篇率均值 3%。只有两篇只能提示不同表现，不能证明 B 的标题有效。若 C 阅读缺失、收藏 60，可报告其收藏数，但不把 C 纳入收藏率合并；缺失比例要显示。此例纯为公式说明，不是用户账号结果。

## 9. 建议卡和 AI 的交付契约

每条建议按以下结构输出，而不是“提升内容质量、保持更新”：

```text
观察：当前可比样本里发生了什么？
证据：具体作品、字段、计算、观察时间与有效样本。
解释假设：可能为什么发生；其他解释和反例是什么？
改动：下一篇具体改哪一个变量？
执行稿：角度、标题备选、段落提纲、封面说明、素材清单。
验证：主指标、同龄观察点、比较组、复盘日期、停止规则。
限制：材料缺失、投放未知、样本偏少等。
动作：查看证据 / 编辑建议 / 加入选题 / 建立实验。
```

数字全部由确定性统计服务生成，AI 引用 calculation_id；原文片段引用 evidence_id 与段落/时间码。服务端拒绝不存在的引用、错误账号、无法复算的数字及虚构外部热点。模型输出中的百分比置信度不当作真实概率。

素材里的指令仅视为待分析文本，不能改变任务、发消息或读取凭据。发送给配置模型的是此次分析所需材料；Cookie、令牌和无关私人数据不进入输入。报告保存规则/模型版本、输入摘要和引用，支持失效标记与重算。模型切换后旧报告仍保留版本。

## 10. 数据模型和后端边界

建议将当前“每个平台返回一块任意 metrics 文案”逐步升级为以下实体；保留旧接口适配，避免一次性重写采集器。

| 实体 | 关键字段与约束 |
| --- | --- |
| Account | platform + external_account_id、identity_source、verified_at、generation；昵称不作主键 |
| Content | account_id + native_content_id、类型、状态、原始/绝对发布时间、规范链接、标题；标题不作主键 |
| Material | content_id、body/transcript/cover/comment、完整性、版本哈希、来源；素材与指标分开 |
| MetricDefinition | native_name、normalized_key、unit、aggregation、unique_scope、适用格式、定义版本 |
| MetricSnapshot | content/account、definition、value/raw_value、missing_reason、window_start/end、observed_at、source、quality_flags |
| CollectionRun | account/generation、collector_version、起止、分页游标、complete、延迟、失败原因、覆盖范围 |
| AnalysisRun | 固定输入快照、筛选、规则/模型版本、计算表、结论引用、生成状态 |
| Experiment | hypothesis、主指标、比较规则、目标观察点、停止规则、idea/draft/published_content 关联、结论 |

UTC 存储时间，前端按声明时区显示；无时区的原始日期另存，不强行精确到秒。导入时间不能覆盖原始观察时间。每次导入校验账号、字段映射、日期、重复、样例后预览；重复导入幂等，同一时间冲突版本保留审计。

旧的无账号归属数据放隔离区，不能仅凭当前昵称迁入。历史保留策略应按容量配置，关键实验快照固定保留；现有每篇最近两次策略不足以支撑长期实验，需迁移后才开放趋势。任何清理不得悄悄破坏已引用报告，应保留必要证据或标明引用已不可用。

建议接口（尚未实现）：GET /api/content-analysis/capabilities；GET /overview；GET /contents；GET /contents/{id}；POST /collections；POST /imports/preview 与 /commit；POST /reports；GET /reports/{id}；POST /experiments。具体前缀按现有路由风格统一。所有查询强制账号范围，异步任务校验 generation；接口直接返回能力、缺失和覆盖，不让前端猜“是否支持”。

## 11. 采集与平台优先级

优先选合法授权的官方接口/导出；已有浏览器采集保留，但受页面变动和权限影响。没有接口时可提供结构明确的人工导入，不绕过访问限制，不把页面只取一页写成全量。

第一批以小红书完成产品闭环，因为已有证据隔离与选题关联；同时修正公众号明确的数据语义问题。第二批 B站补身份、日期、分页，以其结构化指标验证通用模型；公众号面向具备权限的账号接官方数据，首轮对照平台原始页面。其余平台按“身份→稳定内容 ID→发布时间与状态→分页→结构化指标”的顺序接入。

能力注册表分别记录：字段原生支持、适配器实现、当前权限、当前采集质量。某平台缺完播率不代表全页坏掉；某账号登录成功不代表所有统计权限齐全。定时采集需明确配置运行环境与任务状态，不能默认用户关闭应用后仍会执行。

## 12. 创作闭环、报告和导出

发现 → 选题 → 草稿 → 发布记录 → 平台作品 ID → 观察快照 → 实验复盘，每一步保留 account/content/evidence 关联，并可反向打开。Skill 执行记录可挂到草稿，说明用了什么能力、花了多少 Token；其执行成功与作品后续表现分别呈现。

导出默认包含范围摘要、指标定义、有效样本、发现及反例、建议和待补资料。CSV 导出稳定列名、单位、缺失原因、时区和口径版本；报告导出使用冻结的 AnalysisRun，防止导出时数值变化。表格公式前缀按文本安全处理。原始材料与评论导出作为单独选项，默认避免携带多余个人信息。

## 13. 分阶段实施和完成条件

以下阶段是依赖顺序，不是假定工期；数据审计附录有更细的数据专项顺序，统一以本表作为整体验收分期。

| 阶段 | 交付 | 完成条件 |
| --- | --- | --- |
| P0 可信基础 | 指标字典、缺失状态、账号主键、公众号错配/周期修正、独立分析页与真实空态 | 不能串号、不能补零、不能伪造历史；界面如实显示已有能力 |
| P1 可用复盘 | 小红书完整闭环、作品列表/详情、可比规则、覆盖与快照、B站通用模型验证 | 可从统计打开原始证据，真实账号数据逐字段核对；分页中断可恢复 |

首版不承诺全网热点、用户敏感画像、自动爆款预测、七平台统一排行榜或因果归因。以后若加入外部趋势/竞品，需要独立数据源、覆盖声明和功能入口，不混入本人账号历史。
