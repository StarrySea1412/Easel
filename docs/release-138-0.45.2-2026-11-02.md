# 0.45.2 · 插件执行目录与主动生图

承接用户已授权的彻底修复和138正式更新。0.45.1已实际升级正式8444和隔离8445；本补丁修复收尾实测暴露的执行目录问题，并落实用户对小红书卡组主动调用生图的要求。安装器不发布，其他工作树0.46分页WIP不纳入。

## 根因与改动

OpenClaw 2026.9.6捕获插件到`plugin-captures/.../package-0`后加载，原插件按`import.meta.url`向上寻找项目根。结果交付子进程调用了临时目录中不存在的`skills/shared/scripts/present_artifact.py`。同一文件、凭据、会话直接脚本及直接ESM调用均成功；完整原生CLI调用失败，不能归咎Markdown不受支持。该定位方式也影响图片队列提交和目标保护脚本。

- 四个插件统一从运行环境的代码根目录定位，校验项目标记；源码直接加载仍可按模块路径回退，不从模型参数选择目录。应用子进程显式传代码根，数据根保持独立。
- 保留本轮ticket及runtime会话校验、相同请求幂等、图片供应商收费与重放保护。普通文档支持登记下载，不要求改HTML。
- 用户截图对应原文“帮我做「小红书卡组」关于问界的”。实际记录使用render_card.py，没有生图。原技能把卡组当HTML排版，运行提示又要求明确选择AI配图，两条规则压住主动调用。
- 图片成品任务在原数量/费用授权内主动使用专用生图；明确的纯文字/数据排版、网页和真实素材约束保留。车型实物及事实须有可核实来源，不能用生成图冒充；缺配置/调用失败如实保留未完成，不能静默回HTML。移除素材参考中“一律HTML”的冲突。
