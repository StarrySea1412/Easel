## 已改变的行为

- 图片队列在子进程提交前保存请求检查点，异步供应商返回任务号后立即保存原任务身份；检查点不含密钥和签名下载地址。
- Web观察者断开或图片进程退出后，支持查询的原任务可自动有界接回；手动「接回原任务」只查询和保存原结果，不重新创建。当前远程恢复协议为既有`apimart-v1`，同步通道仅能接回已经保存的本地文件。
- 跨进程锁覆盖提交、查询和保存。原进程尚存时，恢复进程不重复处理，解除占位也会被拒绝；解除占位另写持久结束标记，阻止尚未启动的迟到子进程提交或查询；原结果已保存时引导先接回。
- 下载采用流式临时文件和原子替换，单图64MiB、解码64M像素预算；请求多张时必须全部实际存在并可解码，部分结果不会报整批完成。保存清单以文件哈希核对原结果。
- 工坊与对话产物卡显示接回、保存和待核验状态。待核验继续观察，阻止本工作区及同标签其他工作区重复提交；404不再提示用户重新生成。
- 独立执行服务身份文件与图片回执的原子替换补有界本地重试；复现的Windows WinError 5发生在身份文件发布，重试本地落盘不重启后端、不重发外部请求。
- 恢复worker继续遵守原通道并发上限，避免多个待核验任务同时接回挤占资源。
- 服务器任务取得执行槽位时读取容器/主机内存。低于保留预算则返回结构化`server_memory_pressure`，不发送模型/工具请求；图片新任务保持排队并显示资源原因，内存恢复后按原队列处理。原图片的查询恢复仍可进行。

## 故障边界

供应商已经受理但任务号尚未成功保存的窗口无法凭空对账，仍保留待核验。旧版本未保存供应商身份的任务不自动补造身份。不支持查询、渠道身份改变、记录不匹配或费用未确认时，不自动创建替代请求。原子替换的权限冲突最多8次本地尝试、累计约1.58秒退避，持续失败保留原文件并明确失败；这不改变文件权限。自动恢复普通失败最多3次并退避；原进程仍存活时在30分钟观察窗口内等待其锁。手动接回可重新开启查询预算，绝不重新授权创建。

内存保护是派发前的容量判断，无法预知任务峰值或替代资源隔离。Linux从cgroup及`/proc/meminfo`取证；无相应数据的环境返回unknown，不编造可用容量。readiness仍明确`modelInference: not_probed`。
