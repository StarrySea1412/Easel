## 现场与覆盖缺口

用户再次报告编号`28c95386`。正式0.45.3 / `1001448c8982a6d4790be42c280955f135e867f6`的原轮次耗时160708ms，供应商返回`524 status code (no body)`。原生持久会话与运行账本均为失败；四次空assistant终帧，无模型输出、无工具调用、未提交图片任务。不能把这次归为旧版本或残缺工具参数，也没有证据认定参考图片大小或图片能力是原因。

## 本次改动

- 仍仅注册于`happycoding/deepseek-v4.1-flash`，工具与纯文本请求均受保护。仅适配器明确的HTTP524/504错误、没有正文/思考/工具流事件，允许一次原请求恢复；原上下文、模型、认证、工具定义及此前回执保留，不附加参数修复指令。
- 参数修复与请求恢复各一次，当前prepared runtime内共享；每个模型请求及其恢复/修复共用90秒截止时间。取消优先，即使供应商忽略AbortSignal也结算、禁止迟到工具派发。90秒是此目标模型单次请求的产品边界，不是整轮所有步骤的总时长，也不是跨进程持久预算。
- 持续失败、已出现部分输出、预算耗尽不再交出空error；使用明确失败标记及非空诊断，阻止OpenClaw继续叠加silent/transient重试。状态保持error；不伪造模型回答、成功回执或用户取消。已有原生401/429等分类保留。
- 恢复后仍执行schema/终态/大小校验；与此前成功工具完全相同的调用被拦截。传输恢复可首次提交新的生图任务，参数修复仍禁止生图/发布/任意命令。图片已入队则保留原任务，不借模型恢复重新提交。
- 后端将原始524及本次耗尽标记归为`model_provider_timeout`，说明本轮未完成、已停止自动恢复。安全审计保存requestId、尝试、HTTP状态、耗时、结果，不写提示词/密钥/工具参数。

此前源码对照和公开依据见[agent loop研究](agent-loop-reliability-0.45.3.md)。本次直接针对138实际OpenClaw发行循环验收，不修改node_modules或依赖私有打包文件名。
