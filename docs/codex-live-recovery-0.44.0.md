## 协议与实际边界

已重新读取[官方App Server文档](https://developers.openai.com/codex/app-server)，并核对本机已审计的CLI 0.147.0生成schema。对正在运行的线程，`thread/resume`重新加入原线程；本机隔离合成模型实证同一轮完成且只发生一次模型请求。官方明确App Server命令及WebSocket传输仍属实验能力、不支持生产工作负载；本批是可选本机候选验证，不能推称其他CLI版本或生产场景均受支持。OpenClaw仍为默认引擎，Codex保留用户原有可选开关及版本闸门。

原生服务由应用自己的`outputs/_codex/runtime`管理，只绑定127.0.0.1，使用独立随机连接凭据。客户端关闭只断开观察，不杀原执行器；Web服务退出后，原生轮次及其原有权限仍可能继续执行。用户明确停止时才中断精确原轮次。私有目录、凭据及日志不提交Git；同操作系统账号并不因此成为强隔离边界。

## 实现契约

- 运行快照保存独立执行器实例、原生线程、原生轮次和工作目录；接回必须全部匹配，并确认线程已在原执行器加载。原轮次缺少实例身份或原连接不可核对时，保留待核，不重发`turn/start`。
- 订阅先于`thread/resume`：实际CLI会在resume响应之前重送待处理请求。审批/提问重新显示，仍由用户决定；不自动授予权限。已回复工具回执在发送前持久保存，原请求重送时仅复用相同身份及完整回执。前次副作用已开始而回执尚未落盘的情况不盲重做，可精确停止原轮。
- 活运行按原生完整历史快照恢复正文与执行记录，不重放历史命令、动态工具、文件交付或用量增量。后续可按原线程/轮次停止、引导和观察；终态复用既有写前结算日志，保持事件前缀和幂等恢复。
- 断开观察不等于供应商结束；原轮次终态不等于后台终端全部结束。后台任务按原生线程核对，明确停止时仅终止属于原轮次item的processId，不向操作系统PID盲发终止。后台证据缺失或仍有任务时不确认资源释放。
- 现有状态栏在原SSE结束后继续轮询已接回的运行及执行记录，提供精确停止；完成后写回原消息。没有新建卡片、嵌套面板或常驻说明。
- 连接超时不触发替换。只有原端点连接失败且操作系统确认原进程不存在，才允许为后续新请求新建执行器；带原实例身份的恢复永远不借此改绑新执行器。
