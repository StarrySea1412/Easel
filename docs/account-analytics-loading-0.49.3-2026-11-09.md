# 账号分析持续加载修复 · 0.49.3

用户明确纠正为“获取特别久，一直在loading”。本次修复采集等待和加载终态，不调整作品日期或排序。

## 根因及变化

- 138排查时七个平台快照均在21–67ms返回，`running:false`，没有遗留采集子进程。近期请求主要是连接检查，不能把旧快照日期当成请求耗时的原因。
- 工作台原来把连接状态unknown当成一直进行中的检查；现仅实际检查和采集显示加载，失败/未确认显示原因与“重新检查”。平台和账号状态图标同样区分待确认与正在检测。
- 列表重新加载会改变局部请求版本，导致采集finally无法清除busy。现统一使用按账号范围隔离的共享采集状态，切页保留任务、换号丢弃旧响应，重载后可以继续重试。
- 工作台与内容分析只检查当前选择的平台，避免其他账号浏览器检查挡在前面。内容分析的账号列表10秒退出等待，“刷新状态”主动重新检查，未知状态结束转圈。
- 后端连接检查45秒，超时终止进程树并回收；采集90秒，超时停止浏览器并保留原结果。前端采集105秒、快照10秒独立结束等待，覆盖传输或响应体不响应abort的情况；迟到结果不能写回缓存。
- 窄屏状态卡把操作按钮排到下一行，避免状态说明挤成竖排。
