# 账号分析持续加载修复 · 0.49.3

用户明确纠正为“获取特别久，一直在loading”。本次修复采集等待和加载终态，不调整作品日期或排序。

## 根因及变化

- 138排查时七个平台快照均在21–67ms返回，`running:false`，没有遗留采集子进程。近期请求主要是连接检查，不能把旧快照日期当成请求耗时的原因。
- 工作台原来把连接状态unknown当成一直进行中的检查；现仅实际检查和采集显示加载，失败/未确认显示原因与“重新检查”。平台和账号状态图标同样区分待确认与正在检测。
- 列表重新加载会改变局部请求版本，导致采集finally无法清除busy。现统一使用按账号范围隔离的共享采集状态，切页保留任务、换号丢弃旧响应，重载后可以继续重试。
- 工作台只检查当前选择的平台，避免其他账号浏览器检查挡在前面。
- 后端连接检查45秒，超时终止进程树并回收；采集90秒，超时停止浏览器并保留原结果。前端采集105秒、快照10秒独立结束等待，覆盖传输或响应体不响应abort的情况；迟到结果不能写回缓存。
- 窄屏状态卡把操作按钮排到下一行，避免状态说明挤成竖排。

## 验证与边界

- 后端账号采集、身份生命周期、分析同步和资源限制相关检查已通过；前端增加挂起超时、保留旧结果、去重、迟到响应、账号切换、真实列表重载和重新检查回归。
- 真实Chromium使用受控API数据，检查1440/390px、键盘重新检查、超时结束和重试成功。此层验证页面交互，不代表真实平台采集成功。
- 生产构建与lint已通过（既有警告保留）。Dashboard测试聚合运行触及Node默认4GiB堆上限，已完成的用例通过，剩余账号用例按名称分组运行通过；不将内存中断记为全套通过。
- 当前源码版本0.49.3；固定提交、138实际版本、资源与真实平台耗时在部署后补充。隔离测试环境保持0.49.1；本地/隔离账号`gaojitest / gaoji`仅用于隔离入口，不植入正式环境。
- 平台网络与登录状态仍可能导致明确失败；此修复保证状态有终态和重试入口，不承诺所有平台都能在固定时间成功。未运行真实模型、付费生图或投稿。
