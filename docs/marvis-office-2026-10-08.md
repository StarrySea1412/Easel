# 办公室体验：腾讯 Marvis 调研与落地边界

日期：2026-10-08。对应用户需求清单 R16、R17、R19。

用户希望办公室具备清晰的多 Agent 协作体验，并能够中断、指定渠道和模型执行。这里把可观察的任务、成员、步骤、过程与产出入口放在优先位置，3D 场景用于帮助理解成员状态。

`winterBI/marvis-office` 是个人学习 Demo，不是腾讯官方源码。本轮没有复制该项目或腾讯的角色资产，也没有把个人 Demo 当作官方实现。

## 本轮界面实现

- 场景前新增复用组件 `OfficeTaskFocus`，直接选择成员并查看其任务、状态、已上报步骤与最近回执，访问过程和产出位置。
- 成员模型与执行控制前置到任务区，避免藏在 3D 场景、工作流和角色卡编辑的下方。主会话任务输入与停止接入同轮 R17 的统一执行链路。
- 已有工作流继续展示明确上报的成员关系、调用记录和交接示例；没有记录时保留缺失状态，不用推测补齐“完成度”。
- 产出入口滚动并聚焦到真实工作区文件区。文件路径来自已有文件元数据；该清单覆盖工作区，不能自动归属于当前会话或当前成员。
- 页面、工作流、产出和工作预览按办公室实际容器宽度调整列数和控件布局，包含会话侧栏展开后的剩余宽度；会话和成员选择继续使用共享 Select。
- 角色卡编辑的 portal 抽屉跟随实际办公室宽度切换紧凑布局，并保留同一个 3D 预览实例。过程面板在低高度窗口保留可滚动正文与关闭入口。

## 真实性与控制边界

1. 实时摘要只使用当前模式、当前成员的记录。相同 ID 的演示成员和回执不能进入实时摘要；缺失身份时不渲染成员控制。
2. 已收到回执不等于工具成功或任务完成。错误回执单独标示，不覆盖成员状态；没有回执也不能据此断定任务未运行。
3. 更新失败时明确显示“上次快照”。不显示猜测的百分比、阶段编号、依赖关系或“即将完成”。
4. 演示任务、示例产出和时间轴持续明确标为模拟；关闭演示数据后，实际模式及子组件同步使用实时数据源。
5. 停止与渠道模型功能的实际能力、回执匹配和本次模型限制由 R17 的后端与统一对话链路校验。配置登记、接口可达、离线测试和真实模型执行是不同的验证结果，不能互相替代。
6. 现有单成员控制只操作已核验的 Agent / 会话 / 轮次，不为缺少运行身份的成员编造“独立继续执行”入口。

## 验证记录

本文件随实现维护。新增摘要测试覆盖来源隔离、成员切换、回执归属、失败回执不改写成员状态、历史快照提示、空身份控制限制和过程/产出入口回调。

办公室定向行为测试 **64/64 通过**，涉及任务摘要、办公室页、外观编辑、工作流与过程面板；其中新增 7 项回归。外观编辑测试还模拟可用宽度从 1080px 变为 720px，再恢复 1100px，确认 portal 布局状态跟随变化、草稿与 Scene 实例保留。上述新增组件与页面的定向 lint 通过。这些宽度模拟仅验证组件行为，不代表实际像素布局已验收。

页面布局、真实浏览器入口与 R17 执行链路的最终验证结果统一登记在 [用户需求与交付清单](user-requirements-2026-10-08.md)。DOM 行为测试不证明 WebGL 渲染或手机排版；本轮不把网关离线环境写成真实模型任务成功。
