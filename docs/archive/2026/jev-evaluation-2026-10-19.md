# Jev 接入判断（2026-10-19）

**结论：有可选试验价值，当前不作为 Easel 核心依赖。优先完成浏览器与 Subagent 可靠性，随后可从内容质检的旁路评估开始。** 本轮仅研究官方文档与当前项目代码，未安装 SDK、配置凭据、调用模型或部署。

## 查明的产品与版本

- `jev-latest` 是 TypeSafe Jev 的浮动模型别名。它输入 `state + questions`，输出 `choice`、`score`、`noul` 等结构化判断；不生成正文、代码、自由标签或多轮对话。官方明确它不能替换 coding agent 的主模型。
- 2026-10-19读取的[官方模型表](https://docs.typesafe.ai/models)：`jev-latest → jev-1.13.0`，`jev-preview → jev-1.14.0`；[10月14日发布说明](https://typesafe.ai/blog/jev-1-14)称 stable 别名将在一周后切换。不得只因1.14已发布就推断 latest 已切换。若试验应固定具体模型版本，并记录响应的实际 `model`。
- 官方标准价格为每百万输入 token **$0.042**，输出免费。标准限制为总请求64k token、state加单个问题32k。可批量问多个独立问题，不等于具备多Agent调度能力。价格与别名都是本次文档快照，实际渠道价格、账户可用性及推理效果未实测。
- 官方称英文表现最佳，中文/CJK需自建评测；1.14声明改善多语言。图片、box定位与262k长上下文属于明确标注的实验功能，当前不作为本项目浏览器视觉操作依据。
- 官方原生接口为 `POST https://api.typesafe.ai/v1/systemone`，并非现有聊天的 `/chat/completions`；不能仅在 Easel 模型下拉框填写该名字就接通。

## 与当前 Easel 的匹配

| 项目位置 | 判断 | 接入边界 |
| --- | --- | --- |
| 爆款拆解/内容分析的质检 | 最值得先试 | 判断材料是否支持结论、是否缺数据却做效果归因等单一问题；只显示建议，既有逐字引用和材料完整性检查仍用代码 |
| 技能分类与固定候选任务路由 | 可选 | `web/skill_meta.py`已支持离线规则和现有模型分类。Jev可替换固定分类选择，但不能生成自由中文标签；是否值得由准确率、拒答/回退率、成本和延迟决定 |
| 子任务答复的语义检查 | 后续可试 | 可提示是否回答指定问题，但不能凭概率把任务标为完成；完成仍依赖产物、工具结果和验收条件 |
| 辅助对话、Subagent生命周期与资源结算 | 不解决当前主要差距 | 不提供子任务目录、持久化、追问、steer、停止确认或事件账本；这些仍需实现运行框架 |
| 浏览器DOM操作和页面布局 | 当前不引入 | 导航/快照/元素身份/真实操作结果由浏览器运行时核实，实验视觉模型不替代这些事实 |
| 主聊天、写作与代码生成 | 不适用 | 保留现有OpenClaw/Codex及生成模型链路 |

`web/skill_audit.py`已区分实际技能调用证据、产物验证与可选模型评审。Jev应沿用同一边界：机器事实由现有代码核验，模型只辅助语义判断。其概率与confidence不是“用户任务已完成”的证明。

## 建议的最小验证

先选择一个具体任务：对爆款拆解报告做旁路质检。收集50–100条人工标注的中文样本，覆盖正例、反例、信息缺失、含混表述和恶意指令；同一材料同时比较现有规则/模型与固定版本Jev。开发集调整阈值，独立留出集验收，记录误放率、误拦率、拒答/回退率、P50/P95延迟及真实计费。

试验结果只记录和展示，不自动改稿、发布、执行工具或改变任务终态。出现低置信度、超时、429或无有效响应时保留既有路径；先验证能够识别未知/信息不足，再考虑作为可关闭、默认关闭的判断适配器。仅发送该判断所需的材料片段。

现阶段不增加第二套Agent引擎，不为它先做通用供应商界面；也不把官方的低价/快速宣传当作本项目已测结果。是否正式接入，以中文业务实测的可重复收益决定。
