# 账号增长对比真实切换（0.10.2）

## 定位与设计

用户指出五个时段只能改变选中态。先核对 `DESIGN.md`、工作台指标/共享缓存、采集器及服务端快照，再沿用现有轻量分段按钮与状态色，不另加按钮或弹窗。前一项视图的官方 Carbon Tabs 调研保留在[视图记录](analysis-view-tabs-2026-10-21.md)。

根因：旧历史文件仅按平台保存，后端为避免混账号统一清空增长；服务端快照只保存一次成功结果；前端没有增长时不渲染增量行，空时段的说明也相同。累计数本来不应随时段改变，应切换的是增量和基准时间。

## 实现口径

- 成功采集在原 SQLite 库追加按平台、登录身份、稳定账号 ID 隔离的历史总览。累计指标只接受非负整数，缺失保持空，登录失败/采集错误不写历史。
- 较上次取早于当前采集时间的最近快照；其余分别以 1/7/30/365 天前为目标，取不晚于目标的最近快照。允许向前偏差为 1 天与目标跨度 10% 中的较大值；不拿数月前快照冒充昨日。页面显示实际基准年月日时分，不假装日历同期精确值。
- 同一采集时间重复读写不产生“上次”。真实零增量显示持平，下降为负向状态，某项未返回显示未提供；缺时段显示“较某时段 · 暂无该时段对比”。
- 已有同身份成功快照可在下次采集时成为基线；不混入仅按平台保存的旧 JSONL。没有稳定账号 ID 时不按昵称猜归属。
- 点击仅切换已保存的三项增量及时间，不重新登录、采集或推理。平台原生近7日指标保持自己的独立统计周期。
- 浏览器通过只读 snapshot 接口升级旧缓存，同采集时间也接受新增长结构，保留旧结果。
