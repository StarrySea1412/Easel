# 分析材料输入卡布局修复（0.10.4）

用户截图反馈“为什么这里那么乱的”。本轮先更新两份需求清单，再读取DESIGN.md、AnalysisComposerMaterial、共享PlatformIcon及现有材料Modal交互测试。

设计调研：实际读取[MDN容器查询文档](https://developer.mozilla.org/en-US/docs/Web/CSS/CSS_containment/Container_queries)，采用按组件可用宽度适配的方法，避免只用视口媒体查询导致桌面窄分栏失效。沿用项目冷灰表面、细边框、平台图标和共享按钮，不引入新的设计依赖。

当前问题：旧布局把装饰图标、账号标题、可换行平台信息及固定宽度按钮放在同一flex行；窄输入区标题只剩几个字符，平台与数量逐字换行，底部又重复显示材料类型。

布局决策：平台图标与账号标题为首行，标题占剩余宽度、一行省略并保留完整title；平台名和作品数独立为第二行，每个信息单元保持完整；最多两行作品预览；底部只保留采集日期与原有查看材料按钮，删除重复类型文案及装饰图表图标。底部允许换行，极窄容器把操作单独排一行。通过container query处理桌面窄分栏；全程保留完整材料、草稿与原Modal，不新增提示/按钮，不调用模型。

验证状态：待定向交互、构建、lint及本机资源核对。此前浏览器访问策略拒绝仍有效，不绕过；DOM检查不作为像素或真实浏览器验收。主工作区源码、main、138与安装器不变，历史未完成项保留。
