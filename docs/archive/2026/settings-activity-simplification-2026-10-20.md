# 设置页与运行记录页精简方案

日期：2026-10-20。下文保留基于0.4.0的原方案，便于对照；后续已按用户指令实施0.5.0，详见[实现与验收](settings-activity-clarity-2026-10-20.md)。用户最新纠正优先：运行记录默认直接展示全项目全部已记录用量，8项指标、渠道和会话汇总直接展开；原文“三入口、默认当前会话”的建议已被替代。供应商单项编辑器、按分类加载等未完整实施建议仍是后续项，不能视作已完成。继续不部署或重启138，不发布安装器。

## 判断

两页都有按需展开机制，问题主要在分类、默认展示量和重复导航。设置页需要让人直接找到“改模型、改协作、改偏好、维护数据”；运行记录需要先回答“目前什么状态、用了多少、哪里有问题”。首屏保留结论，配置表单和诊断证据通过明确入口查看。

## 源码核对

| 页面 | 现状与影响 | 应保留的既有能力 |
| --- | --- | --- |
| 设置导航 | “模型与渠道 / 更多设置 / 其他设置”分类含糊；环境、通知、员工角色藏在另一组中 | 具体渠道和模型的外部定位 |
| 对话模型 | 默认模型下接本机 Codex、导入、供应商编辑、批量检查，随后直接展示完整 Agent 协作表单 | 已保存默认与待保存选择分开显示；导入覆盖预览；密钥留空保留原值 |
| 模型编辑 | 供应商编辑已经折叠，但打开后会同时渲染全部供应商表单，内部再展开健康检查 | 渠道命名、枚举模型、单模型验证和故障信息 |
| 设置加载 | 环境检查和模型预设在设置组件挂载时读取；导入来源已按 importOpen 读取 | 未加载、失败与未知状态不能显示为正常 |
| 会话记录 | 顶层三入口；会话内还有用量/技能、会话/项目、总览/请求多层切换 | 会话/轮次精确定位、备份副本隔离、失败详情 |
| 用量首屏 | 默认四项指标，另有费用估算、两类速度、渠道表和轮次分布；缓存指标和请求细节已经按需展开 | 未上报字段保持未知，费用来源和分页范围明确 |
| 任务与问题 | 任务按来源展示卡片；问题已有列表、详情及复制诊断摘要 | 来源状态不混同、关联事件依保存编号、不采集敏感正文 |

## 设置页：四组固定导航，一次处理一件事

| 分类 | 默认显示 | 通过明确入口查看 |
| --- | --- | --- |
| 模型与渠道 | 保留六种能力切换；当前能力的默认模型与供应商紧凑列表 | 添加/导入、单个供应商编辑、连接验证、本机 Codex |
| Agent 与办公室 | 协作开关、已保存启动模型、办公室形象入口 | 并发数、单父任务数、嵌套层数、超时等高级参数 |
| 通用偏好 | 外观与界面偏好、通知状态及配置入口 | SMTP 配置和手动测试发送 |
| 系统与数据 | 环境状态、保存位置、会话备份入口 | 环境安装与诊断详情、备份导入导出、演示数据管理 |

### 模型页的具体改变

- 默认模型保留现有共享选择器，以及“已保存 / 待保存”反馈。无修改时无需占据整行的保存提示；有修改时在当前编辑区域显示保存动作。
- 供应商使用一行一个的列表，显示名称、模型、默认标记、配置/验证状态和“编辑”。状态未验证时明确写“未验证”，不从已有密钥推断可用。
- 点击编辑才打开该供应商的详情区域，同一时刻集中编辑一个供应商；先采用内联详情，后续若用侧面板，窄屏使用单栏并提供明确返回与回焦。
- “添加 / 从配置导入”收在列表工具栏。导入继续保留来源、覆盖预览、确认写入三个步骤，避免预览时写入。
- 连接验证放在当前供应商详情内；批量模型列表检查放在“更多操作”。涉及推理或计费的按钮仍须明确标识，不自动触发。
- Agent 表单移至独立分类，模型页仅留一行协作摘要及跳转；办公室角色卡也从这里进入。运行中的行为和进度继续由对话与办公室显示。
- 页面采用一层标题和内容区，减少外框套卡片；保留必要的错误、未保存状态和数据来源说明。

### 保存与加载

使用各配置区域自己的保存动作，避免把浏览器即时偏好、模型配置、SMTP 和 OpenClaw 同步包装为一个全局“保存成功”。成功提示须准确说明保存范围和生效时机；不能以配置已保存替代运行器已采用。

切换分类时保留未保存草稿；若实现涉及卸载编辑器，应将草稿提到稳定状态层或明确处理离开行为。外部指定模型时直接打开对应详情，不要求用户重新找入口。

环境完整检查可推迟到进入系统分类后读取；导航摘要未读取时显示“未检查”。导入已按需读取，沿用该机制。按分类拆分加载时保留请求取消与旧响应隔离，不让后台检测打断当前输入。

## 运行记录页：保留三个入口，压缩会话内层级

保留“会话记录 / 任务 / 问题记录”，默认仍进入当前会话。先复用已有来源及接口，不新增声称覆盖全部执行行为的统一历史。

### 会话记录首屏

- 顶部一行：会话选择、状态、打开原对话、筛选。选中会话名无需再用大标题重复展示；筛选展开后集中放搜索及状态条件。
- 摘要一行：已记录调用次数、总 Token、记录费用，附简短的数据完整性标记。未知显示“—”，部分合计明确标识；费用估算与实际记录费用分开。
- 当前已记录的失败紧接摘要显示，并提供问题详情入口；历史末轮错误不推断为整个会话的最终结果。
- 摘要下提供“调用明细 / 技能核验 / 项目用量”入口。进入详情后保留所选会话和返回位置；从对话带来的轮次定位直接进入相应技能记录。

去掉首屏同时出现的“用量/技能 → 本会话/项目 → 总览/请求”连续切换。会话选择负责上下文，详情入口负责内容，全项目用量仅在自己的用量视图内展示。

### 用量详情

- 调用明细默认展示紧凑请求行：时间、渠道与模型、Token、记录费用；展开一条才看缓存、推理、速度及补充字段。
- 输入/输出拆分、速度、渠道汇总与轮次分布移入用量详情的相应区域，不一起占满会话首屏。
- “按请求 / 按轮次”作为同一份明细的分组方式，避免同页重复放两套调用数据。使用已有分页时，筛选必须继续标明“当前页”，不能写成全历史搜索。
- 项目用量保留现有会话汇总和渠道汇总，不受单会话筛选伪装成项目级过滤。数据口径说明可按需展开，未知、部分上报及过期警示仍直接可见。

### 任务与问题

- 任务卡片改为紧凑列表：标题、来源、实际状态、原入口；必要说明在选中后显示。定时计划同时保留“启用状态”和“最近执行结果”，不能合成“运行中”。
- 只在已有来源提供可靠时间时排序，不能从数组顺序推断“最近任务”。本轮不增加完成率、全局成功率等缺少统一统计口径的指标。
- 问题沿用现有列表与详情。列表用人能理解的操作、平台、阶段、时间；详情顶部显示已知事实及复制诊断入口，HTTP、构建 SHA、路径和关联编号放在技术详情中。
- 错误分类未知时保留原代码及“原因未确认”，不能为了文案简洁生成未经证实的根因。记录有数量上限或已轮转时明确范围，空列表不代表从未失败。

## 实施顺序

1. **先整理层级**：明确设置四分类，移走完整 Agent 表单；记录页合并重复标题与工具栏。复用现有组件和数据接口，减少状态改动。
2. **再减少首屏内容**：供应商列表加单项编辑；会话摘要加详情入口；任务改紧凑列表，问题技术字段下沉。
3. **最后整理状态与加载**：按分类加载，保留草稿和外部定位，补充窄屏与键盘行为；归并历史叠加的样式规则。

产品实现时再按实际范围更新版本、双语说明及交付记录。本轮方案不改产品版本。
