# 138 图片卡片任务：接手交付与执行经验

记录日期：2026-10-16。本文是一次真实任务的脱敏复盘。图片交付阶段没有部署业务代码；之后按用户追加要求调整了 138 的模型配置，见下文独立记录。未修改鉴权或生产并发配置。图片、原始会话、提示词、密钥及个人产出不进入 Git。

## 交付和验收

用户要求在 138 的同一个原会话继续使用 8 张新图片，并在发生长时间等待后授权直接接手修改；必要时允许重新生图。

- 8 张原始素材均已生成；最终采用图片与文字分区的排版，直接离线重渲 8 张 1024×1536 PNG。原版和不合格初稿保留，成品使用独立版本文件名。
- 交付包含可编辑 HTML、可编辑数据/样式脚本、原始素材、预览、使用说明、带 SHA-256 的产物清单和完整压缩包。原稿固定的“不到40天”倒计时改为不易过期的备战提示，主要产品文案沿用原稿。
- PIL 解码/尺寸检查和 Chromium 实际渲染通过；逐页检查所有图片加载、文字矩形是否越界及栏目是否重叠，8 页均无相关问题；另查看了实际预览，未用像素规则替代视觉检查。
- 138 鉴权后的媒体 API 对 8 张成品、HTML、预览、压缩包和清单共 12 个入口均返回 HTTP 200；这证明文件交付，不代表浏览器完整交互、宣传数据、供应商实际扣费或模型质量已全部验收。
- 精确停止本次接续的 Gateway run，收到 `aborted=true` 和匹配的 run ID。没有停止整个 Gateway，也没有停止其他会话。
- 使用 Gateway 已有的 `chat.inject` 将结果以明确的人工接手交付标签写回**同一个**原会话。随后只读 SQLite，确认新增 assistant 事件包含全部 8 图、HTML 和压缩包链接。回写本身不调用模型。

原会话和产物的具体关联回执留在该会话的输出目录，本文不复制其原始消息和图片。

## 138 的实证与边界

| 事项 | 本次证据 | 应得出的结论 |
| --- | --- | --- |
| 视觉输入 | 接手前 `deepseek-v4-flash` 的渠道配置为 `input: ["text"]`；4 次 `read` 图片回执明确提示 `Current model does not support images. The image will be omitted from this request.` | 本轮模型没有看见这些图片。不能推断该模型在所有渠道都不支持视觉，也不能把文件读取成功说成已经审图 |
| 单次输出 | 接手前运行时模型目录的 `maxTokens` 为 8192；此前原卡片轮次的真实结束原因是 `length`，输出记录为 8192；原始配置文件没有显式填写该上限 | 这是单次输出触顶；目录补值不能冒充用户显式配置。与会话上下文窗口是两种预算，大型 HTML 应分文件/分批写入，末尾只汇报结果 |
| 长上下文 | 接续日志的估算提示词为 263006，`promptBudgetBeforeReserve=180000`；会话记录使用 200000；模型配置未声明 `contextWindow` | 运行预算和估算已经产生压力；这些值不能当作原厂上下文容量，不能据此武断认定模型本身容量只有20万 |
| 等待与重试 | 本次发生 `LLM idle timeout (120s)`，随后记录 `transient same-model retry 1/8`；摘要相关的 `gpt-5.6-luna` 请求也出现 503 | 页面等待包含运行器内部重试。超时不等于供应商一定未执行，不能承诺重试不会额外计费；不能仅凭上下文压力就宣称它是本次超时的唯一原因 |
| 视觉审计失效 | 旧初稿把白字直接压在浅色素材上；原像素密度审计显示 6 张通过、2 张失败，但通过的图片也明显难读 | 密度/空白带只能作辅助检查。通过规则不等于文字对比度、内容正确性或视觉效果通过 |
| 计费配置 | 接手前运行时模型目录的本地 `cost` 四项均为 0 | 目录估算值不代表真实供应商费用。缺少有效价格和账单时应表达未知，不能以0估算宣称免费 |
| 外部回写与网页 | `chat.inject` 已新增持久 assistant 事件；Easel 的 `/api/chat/last` 仍返回之前 Web 轮次的结果；网页会话历史保存在浏览器本地 | Gateway 的持久历史、Web 轮次快照和浏览器消息列表没有统一投影。不能把后台写入成功报告成网页已自动显示 |

## 图片接口经验

用户指定 `xjbh.lol` 只能并发 1；`image.mlgb7.com` 最多并发 4。两个通道的限制分别计算，不按发现的模型数量扩大请求并发。

- 模型列表可访问不代表当前有可用的生成账户。`xjbh` 曾成功生成一张，之后在 4 个已发现图像模型上均返回 `503 no_available_account`；切换模型名没有解决共享账户池不可用。
- 早先 `image.mlgb7` 有 HTTP 524；后续通过该通道的 `gpt-image-2` 补齐最后一张。524 只说明代理等待超时，不足以证明上游没有创建任务。
- 单个模型返回明确的共享账户池错误后，继续横向试遍同池模型的收益很低。后续应设置通道级冷却和有限尝试，保留失败类型、请求关联及已完成文件，不盲目重复整个批次。
- 本次已齐 8 图后，版式修复只使用已有素材和离线渲染；“必要时可重生”的授权不应自动变成重复请求。

## 建议按顺序补齐的执行能力（尚未实现）

1. **执行前核对输入能力与预算。** 审图任务需要实际可用的视觉输入；无法看图时明确转交可用的视觉执行路径。输出预算、上下文预算、摘要模型能力分别显示；缺少价格时标未知。
2. **按通道排队与限制重试。** 并发额度放在通道层，记录每张图片的 attempt/请求标识/终态/产物。区分 429、共享池503、代理524和模型无事件超时；超时后的执行与扣费未确认时保留“未知”，不直接记为未执行。
3. **把可编辑产物当作进度锚点。** 保存源码后再渲染；布局修改无需再次请求图片。恢复时先核验已存在文件，避免重复生成8张。
4. **让视觉验收独立于格式检查。** 除解码/尺寸外，检查图片加载、文字边界、栏目碰撞、对比度，并查看真实截图。像素密度评分不得自动充当质量通过结论。
5. **统一同一会话的消息投影。** Gateway append/inject、Web run ledger/快照、浏览器历史需要以稳定 message ID 去重、排序并恢复；支持外部完成结果进入原网页会话，且不伪造原 run 的正常完成或隐式重发模型任务。

这些是本次暴露的改进项，不是已部署能力。此前 ClawHub 展示/骨架屏、长任务恢复和其余未完成事项继续保留在[用户清单](../../user-requirements-2026-10-08.md)。

## 追加：切换 DeepSeek V4.1 Flash 与视觉能力核验

用户随后明确要求把模型改成 DeepSeek 4.1 Flash，并询问文本模型无法看图却继续判断的问题。此次授权针对 138 的模型配置，不扩展为整套业务代码部署。

- **准确模型名**：当前已保存渠道的 GET `/models` 实际列出 `deepseek-v4.1-flash`。列表只提供 ID，没有视觉、上下文窗口或输出额度元数据，因此没有直接根据名字推断能力。
- **一次有界视觉实测**：发送一张临时随机四色图，答案不在文字提示、文件名或元数据中；单次请求、25 秒网络超时、`max_tokens=512`，未配置重试或备用模型。HTTP 200，返回模型名 `deepseek/deepseek-v4.1-flash`、`finish_reason=stop`，4/4 颜色及位置匹配。该回执支持“当前渠道本次图片输入可用”，不保证所有视觉任务、视频/音频、OCR 或整套图片审美质量通过。
- **费用边界**：该探测接口报告 `prompt_tokens=279`、`completion_tokens=266`，共 545 Token；`usage.cost=0.0004029`。这是供应商该次回执字段，未与实际余额或账单对账，不把它等同已核验的美元扣费。
- **实际配置**：经 OpenClaw 配置校验后，将默认文本模型和 `agents.defaults.imageModel.primary` 均设为 `openai/deepseek-v4.1-flash`，两处 `fallbacks=[]`；仅在真实视觉探测通过后登记 `input=["text","image"]`。保留旧模型条目，当前渠道展示顺序先放新模型，鉴权、地址、并发和原产物未改变。
- **原会话保持不变**：通过 `sessions.patch` 携带原 `expectedSessionId`，得到 `ok=true`、匹配的 provider/model 覆盖回执；随后重新读取 `sessions.list`，确认同一个 session ID 已解析为新模型，且没有活动 run。没有重发旧任务，也没有假装旧任务正常完成。
- **运行验收**：Gateway `models.list` 已识别新模型并标为 `default`、`image`、`available=true`；138 鉴权后的 `/api/status` 返回 HTTP 200、`gateway=true`，`/api/agent-office/models` 返回新默认模型和相应选项。网页浏览器本地的显式旧选择仍可能覆盖默认值，未修改用户 localStorage；这些 HTTP/RPC 检查不冒充真实浏览器验收。
- **没有扩大预算**：原始新模型配置不臆填 `contextWindow`、`maxTokens` 或单价；旧会话的 20 万运行额度与旧上下文压力不会因换模型自动消失。后续仍需渠道窗口确认和长上下文恢复。部署启动脚本只在没有 provider 配置时导入初始模型，本次保存配置不会在普通重启时被该初始导入覆盖。

### 避免再次“看不到图却给结论”

问题不应归结成“非多模态模型不能做 Agent”。文本模型可以规划、写代码和制作 HTML；需要看图片内容的判断必须有实际视觉输入和证据。本次已经修正当前模型/看图工具配置，但以下强制约束**尚未实现或部署**，不能以一段提示词声称已彻底解决幻觉：

1. **按任务能力预检。** 用户上传图片、工具读取截图或进入视觉验收时，检查当前渠道、模型能力和近期探测指纹。缺少视觉能力时，停止该视觉步骤并明确说明；只有用户预先选择并授权的视觉模型才可转交，不自动调用更贵模型。音频、视频分别核验，不把 `image` 当作全部多模态能力。
2. **运行中保留输入证据。** 将 `image omitted`、模型拒收和超时记录为结构化失败。图片未送达、视觉请求失败或只有 OCR/文件属性时，不得生成“已看过、视觉检查通过”等状态；可保留并完成不依赖视觉的部分。模型切换后重新核验，不复用旧模型的探测结论。
3. **把产物验收交给独立规则和实际审图。** 将文件/尺寸、DOM 越界/碰撞、文字对比度、事实与文案、视觉内容分别记录。没有视觉证据就保留“未审图”；不能由同一个文本模型把自己的产物宣布为全部通过。视觉输出本身也可能出错，重要结论仍需交叉核验或人工验收。

脱敏探测、模型切换和原会话回写的具体回执保存在原产物目录，凭据与原始会话不进入仓库。
