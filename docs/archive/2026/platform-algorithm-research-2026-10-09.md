# R42 平台算法边界、账号诊断与题材推荐调研摘要

日期：2026-10-09（Asia/Shanghai）
状态：公开资料调研与产品设计；不代表已登录任何平台，也不代表平台接口或模型已经验收。

## 1. 调研结论

账号分析需要回答三个可以核对的问题：

1. **这批作品实际暴露了什么问题？** 例如标题承诺与正文不一致、开场信息出现得晚、同龄作品的收藏率较低、评论反复询问同一信息。
2. **系统为什么这样判断？** 每个数字必须带平台原名、指标定义、观察窗口、账号、作品、来源和缺失原因。
3. **下一篇应该验证什么？** 题材建议必须来自当前平台和账号的作品证据，写出样本、比较条件、主指标和回收时间。

平台公开资料通常只说明可见的数据项、创作者工具和社区规则，并没有公开可复现的权重、阈值或“提高推荐量”的保证。产品应把内容分成三层：

- **平台事实**：平台创作者中心或官方开发文档直接显示的指标、定义、时间范围和状态。
- **本账号可验证假设**：在同一平台、同一账号、同一形式和相近作品年龄内，用快照数据检验的相关模式；不能写成算法因果或承诺。
- **编辑建议**：根据正文、封面、字幕、评论等素材提出的可执行改稿方案；没有对应素材就显示缺口。

## 3. 推荐机制的可验证假设

平台没有提供可用于本项目的公开权重表。以下是可以用本账号快照检验的假设模板，不是平台事实：

| 假设维度 | 需要的平台数据 | 检验方式 | 结论边界 |
| --- | --- | --- | --- |
| 触达→观看/阅读 | 曝光、播放/阅读、实际窗口 | 同平台、同形式、相近发布年龄比较中位数和分布 | 没有曝光分母不能写点击率或封面问题 |
| 观看质量 | 完播率、平均观看时长、阅读完成率 | 只在平台提供定义和分母时比较；视频长度分层 | 不能从视频时长或总播放推算完播 |
| 互动需求 | 点赞、收藏、评论、分享及其原生定义 | 以主指标预先登记；报告事件数和合并率，不混用逐篇率均值 | 互动上升可能来自外部流量、争议或样本选择 |
| 关注转化 | 作品归因新增关注、访问/观看分母 | 仅使用平台明确归因的新增关注；按作品年龄对齐 | 账号净增粉不能归因到单篇作品 |
| 负反馈/质量风险 | 不感兴趣、举报、隐藏、审核状态（若平台返回） | 仅展示平台直接返回或人工记录的事实 | 没有字段时不声称负反馈低 |
| 分发来源 | 推荐、搜索、关注、私域等来源（若平台返回） | 分来源保留原生名称和窗口 | 不把来源占比改名为“算法偏好” |

建议以“假设卡”呈现：`假设 → 证据作品 → 指标/公式 → 样本 N → 时间与年龄条件 → 反例 → 下一轮单变量实验 → 不能说明的部分`。样本小、窗口不齐或缺分母时，状态为“证据不足”，不生成方向性结论。

## 4. 平台定向的诊断重点与题材建议

平台重点是编辑检查方向，不是算法权重。只有相应素材和指标存在时才启用。

| 平台 | 优先回答的作品问题 | 题材建议如何产生 | 首选回收指标 |
| --- | --- | --- | --- |
| 小红书 | 标题/封面是否说明使用场景；正文是否给出可收藏步骤；评论是否出现重复求助 | 从标签、标题和评论聚类候选场景；至少 2 篇同类作品，按发布年龄对齐收藏数/收藏率；给出“继续验证”而非爆款断言 | 收藏、主页访问或平台提供的曝光→互动分母 |
| 抖音 | 开头承诺是否在前几秒兑现；字幕/画面是否支持连续观看；评论问题是否可转成下一条 | 以同主题短视频分层，比较完播/平均观看时长与分享/关注；缺时长或完播字段则只给脚本建议 | 完播率/观看时长（有定义时）、分享、归因关注 |
| B站 | 选题是否有清晰问题和章节；长视频是否在关键段落流失；评论/收藏/投币是否指向系列需求 | 按视频类型、时长和发布时间分层，提取高频弹幕/评论问题，形成系列题材候选 | 留存/观看时长、收藏、投币、评论；累计播放单独展示 |
| 快手 | 作品状态是否有效；经验是否具体可执行；评论和分享是否形成关系型需求 | 按同类内容和相近年龄比较评论/分享/关注，结合评论中的场景词生成候选 | 播放、评论、分享、归因关注/完播（实际有字段才用） |
| 视频号 | 内容是否适合转发场景；开头是否说明受众和用途；新增关注与分享是否同窗 | 从分享、评论和关注相关作品中提取受众场景；缺逐篇详情时只显示账号级机会 | 新增播放、转发、评论、净增关注，明确期间与延迟 |
| 知乎 | 是否回答了明确问题；论证、引用和结论是否完整；评论是否暴露未回答的追问 | 以问题/专栏类型分组，聚合追问和收藏意图；同类型同龄作品比较阅读、赞同、收藏 | 阅读、赞同、收藏、评论、归因关注（若有） |
| 微信公众号 | 标题与摘要承诺是否一致；正文阅读完成和跳出发生在哪个阶段；转发是否来自明确场景 | 按文章主题、长度和发送场景分组；必须保存 msgid/stat_date，30 天边界内观察 | 阅读、完成率、平均时长、分享、关注；is_delay 单独提示 |

题材候选不应只显示一个词。每张卡至少包含：平台/账号、候选题材定义、引用作品、有效样本 N、实际观察窗口、同龄比较组、主指标及分母、缺失比例、反例、建议素材、下次观察日期和停止规则。无真实作品时显示“暂无数据，先连接或导入”，不填演示数字。

## 5. 账号分析页面改造建议

### 5.1 平台与账号切换

- 全局查询上下文固定为 `platform + account_id + account_generation + filters`。切换平台先清空上一平台的统计、作品、诊断和题材卡，再请求新上下文。
- 请求和响应都带 `scope_generation`；旧平台晚到响应直接丢弃。切换账号、退出登录、清除数据时递增 generation。
- 页面首屏明确显示“平台、账号、来源、覆盖篇数、最近观察时间、完整度”。平台变更后这些字段必须同步变化，不能只换图标。
- 作品详情、导出、建议保存和实验预填都携带同一 scope；不允许把 A 平台作品带入 B 平台建议。

### 5.2 “我能分析什么”能力卡

按平台列出能力矩阵：标题、封面、正文/字幕、评论、曝光分母、观看质量、互动、关注归因、主题聚类。每项显示 `可用 / 需导入 / 平台未提供 / 当前缺失`，并给出补齐入口。这样用户在没有数据时仍知道下一步，而不是看到空图表。

### 5.3 证据和假设分栏

每条发现固定显示：事实（原生字段和计算）、解释假设（可反驳，带反例）、行动（只改一个变量）、验证（主指标/时间/比较组）、限制（账号权限、样本和窗口）。算法说明卡提供来源链接和“最后核对日期”；没有公开权重时明确写“平台未披露，以下仅为本账号待验证假设”。

### 5.4 题材工作台

题材页默认只在当前平台/账号内排序，按有效样本和证据完整度过滤；跨平台只并列展示，不合计播放/阅读/互动。推荐排序优先“可解释、可执行、样本足够”，而不是一个黑箱分数。保存题材时固化引用作品、指标定义和窗口，后续采集变化只生成新版本。

## 6. 最小可实施数据契约

```text
AnalysisScope(platform, account_id, generation, identity_source, verified_at)
MetricFact(content_id, native_name, definition_version, value, unit,
           aggregation, window_start, window_end, observed_at, source,
           missing_reason, coverage)
DiagnosticFinding(kind, observation, evidence_ids, hypothesis, counterexamples,
                  action, primary_metric, compare_rule, review_at, limitations)
TopicCandidate(platform, account_id, label, definition, evidence_ids,
               sample_n, age_rule, metric_ids, window, missing_rate,
               rationale, experiment_id, status)
AlgorithmClaim(platform, claim, class=fact|hypothesis|editorial,
               source_url, checked_at, evidence_ids, validation_status)
```

服务端拒绝跨 scope 的引用和保存；前端不可根据缺失字段补零。统计默认同平台、同账号、同形式、同作品年龄比较，且显示有效 N/总体 N、中位数、均值和分布。跨平台只比较明确同义、同窗口且有独立定义的指标，否则并列原值。

## 7. 验收边界

本调研没有执行真实账号登录、平台后台采集、真实模型分析或真实发布。后续验收需要分别记录：

- 模拟数据：切换平台/账号后旧响应不覆盖新结果，题材引用和指标定义正确。
- HTTP/浏览器：每个平台入口、平台/账号选择、能力卡、作品链接和导出可达；390px 与键盘操作通过。
- 真实采集：授权账号、原页面字段、覆盖篇数、窗口、延迟、缺失和作品 ID 逐项对照。
- 真实模型：只验证模型是否按给定事实和引用输出，不把模型自称的算法权重当平台事实。
