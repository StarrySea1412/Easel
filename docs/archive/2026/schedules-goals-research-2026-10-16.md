# 定时任务与目标：ZCode 调研和 Easel 方案

日期：2026-10-16。状态：**本篇保留实施前的调研快照；后续首版已实现，见[实施与验收](schedules-goals-implementation-2026-10-16.md)**。本轮只读取官方公开资料、固定源码和本机能力目录，没有创建定时任务、启动目标、付费调用或修改138。

## 建议先明确三个对象

| 对象 | 回答的问题 | Easel 示例 |
| --- | --- | --- |
| 定时任务 | 什么时候执行，按什么规则重复 | 每个工作日9点，检索跨境侵权热点并整理5个选题 |
| 目标 | 做到什么程度算完成 | 做出8张可读的图文卡片，交付可编辑HTML和预览，逐项通过检查 |
| 运行 | 这一次实际做了什么、花了多少、结果如何 | 10月16日9点触发，使用指定模型，交付选题报告，3条证据待核实 |

定时任务可以只执行一次指令，也可以生成一个有预算的目标实例。目标可以手动立即启动，也可以在指定时间启动。周期任务每次创建独立目标实例，不能把昨天已完成的目标直接改回运行中。多个日期的结果可归入同一个对话，但每次运行有独立身份、模型快照、费用和产物版本。

先做可验证交付，再做运营指标。诸如“本周完成3篇图文”属于交付目标；“涨粉1000、转化率提高20%”属于需要真实账号、基线、观察窗口和归因边界的指标，达成与否不能由Agent自评。阶段产出完成与运营指标达标分别展示。

## 已核实的 ZCode 机制

实际读取[目标模式](https://zcode.z.ai/cn/docs/goal)、[自动化](https://zcode.z.ai/cn/docs/automations)、[闲时任务](https://zcode.z.ai/cn/docs/idle-time-tasks)。同时只读获取官方仓库，固定提交为 [`aac4755666d09fdcd70272fcf063c077a639015f`](https://github.com/zai-org/ZCode/tree/aac4755666d09fdcd70272fcf063c077a639015f)，未安装依赖或运行竞品。下面的源码行为仅针对该提交，不代表所有已发行客户端。

| 机制 | 官方文档与源码证据 | Easel 取舍 |
| --- | --- | --- |
| 会话目标 | `/goal`设置、查看、替换、暂停、恢复、清除；一个会话一个当前目标。目标与轮次、耗时、Token预算持久化 | 借鉴；更改标准产生新revision，已完成和已取消记录保留 |
| 单独验收 | 每轮后另做一次校验；输出`passed/reason/nextAction`，未完成才自动续跑 | 借鉴；先做确定性检查，再让模型评价语义质量，证据不足不通过 |
| 可恢复时间线 | 目标、工作轮次、验收生命周期分开存；验收记录锚定被检查的assistant/turn，待办保留首次出现轮次 | 借鉴；不把每次SSE重连或每条工具事件计算成新一轮 |
| 主动停止 | 文档说明停止同步暂停目标；源码在验收取消时同样暂停，并在续跑前重读目标身份与状态 | 必须实现到后端；晚到的校验不能越过停止/替换屏障 |
| 定时任务 | 项目入口、配置/历史、原会话投递、立即运行；源码用SQLite事务认领，手动运行共用single-flight锁 | 借鉴；任务定义、一次派发和真实执行结果分开，立即运行不改变日历计划 |
| 漏跑 | 文档说明睡眠/应用退出不执行，错过的一次性任务跳过，历史可查 | 借鉴默认跳过；可选新鲜度窗口内合并补一次，禁止醒来批量补生图/发布 |
| 配置 | 模型留空可跟随项目默认；本地时区；最多20条任务 | 我们默认显式冻结模型和时区；不照搬20条业务限制 |
| 闲时任务 | 文档描述依赖个人Coding Plan资格、专用免费通道、排队和分段续跑 | 不能把普通API低优先级队列称为免费算力；Easel暂不做这项承诺 |

两处差异值得保留：

1. **验收故障不能标完成。** 固定源码中，验收请求非取消报错、错误工具调用或不可解析JSON会走`failOpenGoalCompletionVerification`，返回`passed: true`，运行层据此更新为`complete`。这是竞品明确的容错取舍。Easel建议记录`blocked / verification_error`并停止自动派发，保留已有产物，让用户单独重验；避免把失败当成功，也避免因为失败无限重做。
2. **官网与当前源码存在行为差异。** 官网说运行中不能设置目标；该提交的V4实现允许`sendGoalCommand`作为独立命令排队，恢复仍有运行屏障。Easel首版采用“运行中修改要求进入待应用队列；停止立即生效；下一轮采用新revision”，以实际入队回执说明何时生效。

本机OpenClaw包版本为**2026.9.6**，实际WebSocket握手同样返回该版本，能力目录包含`cron.add/get/list/remove/run/runs/status/update`等接口。本次仅握手读方法目录，没有调用新增/运行/修改接口，没有读取或改动真实任务内容。支持方法不等于Easel已经有完整产品接入。

## 产品入口：自动化管理，目标留在对话

工具栏增加“自动化”工作区，首版两个标签：**定时任务、目标**。不挤进设置，也不新增第三列侧栏。遵循已有侧栏规则：首次/刷新双列折叠；主动点“对话”才进入聊天并展开会话列，回到自动化保持原会话和草稿。

定时列表展示下一次具体时间与时区、最近结果、执行模型和预算；“启用中”与“本次执行中”分别显示。详情分配置/运行历史，可立即运行、暂停未来触发、停止当前轮次。立即运行复用同一准入锁，不改变原计划、有限次数或结束日期；仍占用本日/总费用预算。

目标总览用于找任务、看阻塞，不再做一套独立聊天。原对话顶部放可折叠目标卡：目标、验收清单、当前动作、已完成证据、已用预算和暂停/停止。每轮输出后显示简短验收行，例如“6/8项已验，2项待检查 → 检查第7、8张文字边界”，可展开回执。图片/HTML继续在原轮次预览，点击文件打开当前产物版本。

进度按真实通过的验收项计数，优先显示“6项已验、2项未验”，不按时间编百分比。实际完成项和用户待审项分开；文件被修改后，绑定旧哈希的验收证据标过期，重新检查。长任务等待供应商/工具/用户时如实显示等待对象、最后事件时间与可用操作。

在会话中说“每周一9点整理热点”或输入`/goal`可以生成配置草稿。缺时区、模型、预算或发布范围时明确补齐；如果用户已经明确授权且字段完整，可直接保存启用并回显实际计划。不要把自然语言解析出的猜测直接当用户选择，也不每次运行重复询问已经授权的只读/草稿步骤。普通指令“这个目标怎么做”只进入讨论，不自动启动付费目标。

## 一次目标执行的闭环

1. 保存目标描述、验收项、范围、预算与模型快照，绑定`sessionId`和`goalRevision`。同一会话首版仅一个可自动推进的目标。
2. 服务端事务认领一次工作轮次，生成稳定`turnId/runId`，复用聊天执行服务。自动续跑提示有明确系统来源，不伪装成用户新发了“继续”。
3. 工具结果、实际费用/Token及子任务归属写入账本；产物按`artifactId/revision/hash`登记。尚有后台Agent、图片job、外部提交结果待确认时，先等待/对账，不启动同一工作的新副本。
4. 确定性检查先验文件存在/格式/尺寸/文本边界/链接等；语义、视觉质量由显式选定且能力匹配的验收模型检查，必要时交给用户。几何检查通过不等于审美合格，看不到图片不能给视觉结论。
5. 验收输出结构化`passed/failed/unknown`、证据引用、缺口和具体下一动作。全部必需项有效通过、资源及交付已结算后才完成；已要求的用户验收必须真的获得确认。
6. 未完成且存在有效下一动作、状态仍active、预算与能力允许时才派发下一轮。连续两轮无新增有效证据或同错反复出现，默认阻塞并提示缺口；可读重试同样有次数和退避上限。

目标建议状态为`draft/active/paused/blocked/completed/cancelled`，`active`下显示queued/running/verifying/waiting，阻塞原因包含budget/model_unavailable/verification_error/no_progress/unconfirmed/permission_required。**运行成功、目标完成、公开发布成功三个结论不能互换。**

操作语义必须明确：暂停目标禁止新轮次、当前轮次到安全边界收尾；停止任务先持久暂停目标和取消版本屏障，再请求精确run及后代停止。后台未确认前显示“停止中/结果未确认”，不能释放未知外部请求的槽位。暂停定时任务只关闭未来触发，不冒充当前已停止。清除目标用归档/取消保留历史与账单。

用户插话优先于自动续跑；新要求记录为待应用的revision，当前轮次证据仍归原revision。晚到的验收必须核对`goalId/revision/turnId/stopEpoch`，不得恢复旧目标。计划模式仅讨论，不自动执行。重开浏览器恢复视图；服务重启先对账，不能把恢复界面等同于重发已扣费请求。

## 定时与费用的默认规则

| 项目 | 建议首版规则 |
| --- | --- |
| 时间 | 一次性、固定间隔、每日/工作日/每周；保存IANA时区和UTC触发点，展示接下来3次具体时间。每24小时与每天9点分开；月末/夏令时自定义规则后续补齐测试再开放 |
| 离线/休眠 | 界面显示执行位置及是否在线。默认漏跑跳过并留痕；只读汇总可在用户选定新鲜度窗口内合并补一次；已提交未知的任务不属于漏跑，必须先对账 |
| 重叠 | 同计划/同会话最多一个活跃执行；后续触发按用户选择跳过或合并待跑一次，有到期时间，禁止无限排队和与人工消息争锁 |
| 模型 | 保存主模型、验收模型、推理档位和工具/子Agent/图片配置引用及指纹；默认无隐式fallback。配置变更或模型不可用转阻塞，用户可以明确更新未来运行 |
| 预算 | 同时限制单轮、单次目标、计划日额度及项目总额度，覆盖主模型、验收、子Agent、自动压缩、重试和图片/视频。取最紧约束，并原子预留，不能等全部完成才统计 |
| 未知价格/用量 | 价格为0或未上报不当作免费。仍强制Token、模型请求数、时长、图片数量和并发上限；人民币硬上限只在价格及用量足够可靠、或供应商支持额度控制时提供，不能承诺精确账单封顶 |
| 默认试运行 | 候选默认：一个目标最多5个工作轮次、20分钟，子Agent关闭或最多2个且须显式模型；实际阈值经本机验收后再确定。单轮包含多个模型请求，每次工具循环也要检查额度；验收和压缩请求另计入预算 |
| 重试 | 已接受/可能已扣费请求不因超时自动重发；确定未派发的队列操作可有界重试。无幂等凭据的外部发布/生图先核对原任务；续做只处理缺项 |
| 发布 | 定时检索、整理和生成草稿可在已有授权内执行；自动公开发布要有对应账号、内容版本、时间窗口与范围的明确授权，改内容/账号后原授权失效。结果不明时不得重复提交 |
| 通知 | 完成、失败、阻塞、需确认才提醒；无变化监测保持安静。通知带原会话、run和产物目标，不把每次tick变成新通知 |

时长/Token限制只能阻止后续请求和请求取消，供应商可能已产生的消耗不能回滚；预留计费还需处理缺失用量及未结算后代。对外展示实际账单、供应商上报、估算和未知的来源，沿用当前用量真实性要求。

## 后端选择：一个调度权威，复用现有执行器

两条路线都可行：直接代理OpenClaw cron最快，但原生调度会绕过当前Web准入/账本，且要专门接合预算、消息投影、停止和Codex；在Easel增加轻量领域调度服务需要更多接线，却能统一上述边界。

**建议新建的Easel任务由Easel统一拥有触发和派发状态，OpenClaw/Codex负责执行。** 不重造模型内部工具循环，也不同时给同一个计划注册OpenClaw cron和Easel timer。既存原生cron以后可只读展示为“OpenClaw管理”，显式迁移时先停旧计划、核对活动run再启用新归属。未来若采用OpenClaw作为触发适配器，必须证明经同一准入队列且另一调度器已关闭；不作为首版捷径。

拟新增小型SQLite领域存储，主要包含：

- `automations`：指令/目标模板、版本、时区、规则、执行位置、模型/权限/预算快照、nextAt、漏跑/重叠策略。
- `goals/goal_criteria`：原对话、目标revision、状态/停止版本、验收规则及证据版本；每次周期生成独立goal。
- `automation_runs/goal_iterations`：计划触发点、来源、工作/验收阶段、稳定turn/provider关联、费用预留与结算状态。
- `dispatch_outbox`：事务内建立派发项，唯一`(automationId, scheduledAt)`；手动运行使用独立requestId。单次重投仍使用原runId，重启不能据lease过期创建新付费attempt。
- `automation_events`：递增序号、状态变更和验收事实，支持SSE续订/快照；不要把提示词和密钥塞入事件。文件内容继续保存在现有产物服务。

认领用事务、lease/heartbeat和fencing token；会话锁、预算预留、启停/删除与认领必须有跨进程冲突处理。数据库幂等不能保证外部操作exactly-once：派发后崩溃必须核对provider/job原身份，未知则占位阻塞。`claim → enqueue → accepted → resource_settled → verified → delivered`分别留证；通知投递失败不能触发重新生图。

从`web/app.py`提取可被HTTP和后台worker共同调用的运行服务，统一模型/能力校验、预算、取消、持久事件和产物绑定；不要让定时worker伪造浏览器SSE请求或再启动一套无账本CLI。模型健康和发布核实的专项worker先保留，不为统一入口冒险改变现有限额与重试。

预算有一个实施前提：一个Gateway turn内部可能有多次模型/工具循环，外层在轮次结束后读Token无法实现逐请求硬闸门。P0必须先核对并接入引擎的模型请求准入、工具和子任务创建边界；没有可用拦截点时，先只承诺工作轮次数/墙钟取消/工具数量等能够执行的限制，把Token与金额显示为已上报值或估算，不能宣称硬封顶。长期上下文采用保留证据引用的有界检查点，压缩本身也计费；不能每次续跑无限附加完整历史。`stopReason=length`只说明这次输出截断，已有产物需逐项核对，不得直接判目标完成或无条件再发一轮。

运行位置要明确到本机实例或138实例；同一个计划只能有一个执行owner，不跨机器同步启用两个副本。普通浏览器关闭不应终止已授权运行，但本机后端退出/睡眠不能执行；部署到138可常驻仍需独立部署和停机恢复验收，本轮不变更。
