# 按实际模型身份重建办公室角色：设计审核稿

更新：2026-10-02（Asia/Shanghai）。状态：官方参考核对、概念图审核阶段；尚未替换运行中的角色。

## 目标与范围

用户希望从 Agent 办公室直接看出哪个模型在工作。品牌角色需要覆盖完整厂商体系，不能以三款示例冒充最终覆盖，也不能将豆包等已有官方人物重新设计成无关动物。

第一轮完整设计清单为豆包、DeepSeek、Qwen/千问、Kimi、GLM/智谱、MiniMax、腾讯混元、讯飞星火、文心、OpenAI、Claude、Gemini、Grok、Mistral，共 14 家，另加通配角色。后续按新增实际使用厂商扩充注册表；这不是“所有全球厂商已实现”的声明。

厂商决定角色身份，具体型号显示在名牌；岗位影响工位和设备；实际执行状态决定动作与表情。同一厂商多个模型共用品牌角色，不把品牌与岗位固定绑定。

## 上轮建模经验

1. 先看轮廓和坐姿。头部特征应在桌面、椅背遮挡后仍可见，不能只依赖颜色、胸牌或背后尾巴。缩小到办公室实际尺寸、隐藏文字和灰度查看后仍需可区分。
2. 共享交互规范，不复制角色脸型。统一单位、朝向、骨骼和握点；原办公室朝 −Z、独立 GLB 样板朝 +Z，需要在导入边界统一。
3. 手部围绕真实接触制作。拇指朝内，腕部跟随纸面；笔保持固定长度，以握点和笔尖约束反解手臂，不能通过缩放道具掩盖接触错误。
4. 肩、肘、腕和颈部保持连续。优先验证脚底、座面支撑和桌面可达，避免低头露缝、抬肘、横折手腕及前臂穿笔座。
5. 神态服从状态。保留中性、专注、思考、等待、完成、错误；未知不虚构忙碌，终态不持续敲键。
6. 性能独立验收。现有独立 GLB 样板约 1.91 MB、44,116 三角形、72 个蒙皮网格，不应直接复制满办公室。正式资产需要合并网格、复用材质、远近细节等级并测多人场景。

## 如何确定正在工作的模型

当前 `OfficeAgent` 没有模型身份字段。模型控制的 `currentModelRef` 优先取配置覆盖，保存明确作用于后续调用；它不能证明正在执行或已经结束的任务用了该模型。

后续实现需分开 `observedModel`（调用记录证据）和 `configuredModel`（后续路由）。每条身份包含厂商、模型 ID、渠道 ID、来源类别 `observed/configured/unknown/demo`、观测时间。模型名映射仅确定记录声称的品牌，不保证中转服务底层执行可独立验证。

- 优先读取匹配会话、轮次、运行身份的 assistant 消息 `model/provider` 元数据；沿用办公室轮次边界，不与另一套统计哈希强行关联。
- 子 Agent 独立核验。父级模型、派发参数或已保存设置均不能证明子级实际用了同款模型；无匹配回执保持未知。
- 模型厂商与接入渠道分开。例如中转渠道的明确 `deepseek-chat` 可显示“记录标识：DeepSeek”；只有 `openai-compatible` 协议不能显示 OpenAI 角色。
- 对不透明 `ep-...`、自定义别名、冲突数据采用通配；允许后续明确配置映射，并标“手动映射”，不把渠道域名、提示词或任务文案当证据。
- 单独显示“已配置：供后续调用”；修改设置不改写历史角色。运行中切换或回退模型，应按有时间戳的实际记录更新并保留历史。
- 来源未确认与尚未观测要有文字说明。通配角色为稳定中性形象；同一未知身份可用稳定编号或小色标区分，不能伪装成已有品牌。
