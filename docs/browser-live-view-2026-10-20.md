# 辅助面板实时操作（CDP 画面流）实现与验收 · 0.7.0

日期：2026-10-20。分支 `codex/browser-live-view-2026-10-20`，基线 `5a5fde56`（源码 0.6.2），本轮升 `0.7.0`。

## 背景

此前辅助面板是"快照+指令"：网页渲染成一张截图，点击/滚动/填写都是后端回合，且：
- 用户点中新窗口链接时，弹窗被静默关闭，界面"点了没反应"；
- 点中输入框后无法在页面上直接打字，必须去"查看页面元素"逐项填写；
- 任何一次失败都会让快照过期，之后点击被拒且没有自动恢复。

对照 ZCode（Electron `<webview>` + 主进程 CDP）见 [研究记录](zcode-desktop-browser-pane-research-2026-10-20.md)。本轮按其中"路线3：不动交付形态"落地最小可用版本，同时修掉上述三个 UX 问题。**没有引入 Electron 或 WebView2，交付形态不变。**

## 实现

### 后端（`easel/browser_runtime.py`、`web/browser_api.py`）

- **画面流**：每个标签页按需 `Page.startScreencast`（JPEG, quality 70，`maxWidth/maxHeight` 取当前视口），帧缓存在内存；`GET /api/browser/sessions/{sid}/tabs/{tab}/cast` 以 `multipart/x-mixed-replace` 推送新帧（版本号递增，客户端断线即停）。15 秒无客户端自动 `Page.stopScreencast`；关闭标签/会话/浏览器时一并停止。
- **输入通道**：`POST /api/browser/sessions/{sid}/tabs/{tab}/input`，批量事件 `click|move|wheel|key|text`，直接映射到 `page.mouse` / `page.keyboard`，**不要求 snapshotId、不等待观察**；浏览器侧做面板尺寸→CSS 视口坐标换算与边界校验，仍受会话/标签归属与"同页单一操作锁"约束（页面正在执行另一项操作时返回 409）。
- **输入后同步**：每次输入结束 0.9 秒内触发一次受控观察（同一标签锁内），让元素列表、正文、日志与状态栏跟上真实页面。
- **新窗口链接不再静默**：`page.on('popup')` 捕获地址后关闭窗口，并在**当前标签页**继续打开；点击若在 0.35 秒内没有弹窗或导航，会留一个 3 秒的兜底——晚到的弹窗照样在该标签页续开（前提是标签页没有自己跳走）。回执 `notice` 如实说明"链接默认在新窗口打开，已在当前标签页继续"。
- **点中输入框时的引导**：坐标点击命中可见的 textbox/combobox 时，回执带 `focusRef`，前端直接切到元素列表并选中它，用户输入后点"填写"。
- **失败后自动恢复**：任何失败（快照过期 409、敏感信息 403、元素变化、导航超时等）都会在页面仍存活时自动重新观察（最多3次短重试），把新快照随回执返回（`recovered: true` + `notice`），前端以中性提示条代替红色错误条，面板可立即继续操作；**绝不重放**失败的动作。
- **`_validate_url` 消息修正**：内网/回环地址的拒绝不再被同一函数的 `except (socket.gaierror, ValueError)` 吞掉后误报"网页域名无法解析"（`BrowserError` 继承 `ValueError`）。

### 前端（`web/frontend/src/components/ChatLiveBrowser.tsx`、`lib/browserLive.ts`）

- 工具栏新增"实时画面"开关（闪烁图标，按下态高亮）。开启后以 `multipart/x-mixed-replace` 的 `<img>` 显示 JPEG 帧流，上面覆盖一个可聚焦的输入层：左键点击、滚轮、Enter/Tab/Escape/退格/方向键/空格逐键转发，可打印字符按 `text` 发送，粘贴整段文本。坐标按**页面 CSS 视口**换算（与帧像素解耦）。
- 输入以 40ms 合并成批、单请求在途，失败时给出"实时输入未被接受/连接中断"提示；退出实时画面自动回退到快照并重新观察。
- 状态栏区分"实时画面 · 点击画面聚焦后可直接输入"与快照态；新窗口/输入框提示以 `role=status` 提示条呈现，可手动关闭。

- 后端定向：`tests/test_browser_runtime.py` 18 项（含新增 5 项：新窗口续开、输入框引导、409 自动恢复且不重放、实时输入打字与点击、帧流 JPEG 且关闭后停止）；与 `test_browser_remote_runtime.py`、`test_browser_codex.py` 合并 24 项通过。
- 前端：全量 `node --test` 1196 项通过，含新增 2 项（实时画面帧流+输入转发、提示条与元素列表联动）；`npm run build` 通过，`npm run lint` 0 错误（20 个既有 warning）。
- 真实运行：本机隔离实例（7899、临时数据目录）用当前源码启动，浏览器面板对 `example.com` 出帧 719×597，实点链接后进入 `iana.org`；应用内实时画面实点百度"意见反馈"后页面真实跳转、快照同步更新到新页面。
- 边界：Windows 本机 Chromium；百度等站点会把自动化会话导向验证页，这是站点反爬，未绕过。站点"允许 Agent 操作"开关的行为未改。138 未部署/未重启，未发布安装器，未调用付费模型。

## 已知限制

- 帧率取决于 Chromium screencast 与网络，通常 5–15 帧/秒；快速拖拽/滚动时画面略滞后于实际操作，输入本身是即时下发的。
- 帧流是"看"，可访问性树/截图分析仍以观察快照为准（元素列表、正文、日志保持原行为）。
- 实时模式下文件上传/下载、右键菜单、新窗口的"在面板新标签打开"仍未支持；需要这些时用系统浏览器。
- 3 秒兜底窗口外的迟到弹窗仍只记录地址、不自动跳转。
