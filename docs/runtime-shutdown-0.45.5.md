# 0.45.5：停机排空与原任务结算

用户的持续目标是稳定对话、稳定生成与专业运营结果；本补丁只交付其中的服务退出可靠性。截图问题28c95386已在0.45.4记录为供应商524、零输出与零工具，不能改称停机导致，也不能把此次停机修复宣称为DeepSeek渠道已恢复。原任务未重放。

## 发现与改动

138实际OpenClaw 2026.9.6发行源码的`gateway-shutdown-budget`定义325秒总退出、10秒收尾预留；`run`的stop路径先排空活动工作，超预算才中断。此前Easel supervisor收到SIGTERM直接调用执行服务shutdown，并同时给网页和Gateway发SIGTERM，30秒后强杀；Compose仅40秒。执行服务又立即退出，后台聊天生产者不在Uvicorn的HTTP收尾集合内。上述设计可能截断在途回执，不是供应商524的根因。

现在SIGTERM/SIGINT处理只设置停止标志。supervisor先通过带私有token与实例身份的控制请求关闭执行受理；暂停目标调度和新的图片队列认领，已经受理的聊天、分析、图片与响应继续在原执行者中收尾。后台图片保留原供应商身份、文件和登记；尚未提交的下一张留在原队列。持久未知记录不当作会自行完成的本地进程，但继续保持待核验与防重复提交约束。

执行排空最多300秒，执行进程退出另留60秒（Uvicorn HTTP关闭预算仍30秒）；之后关闭网页观察者（10秒）及原生Gateway（330秒）。Compose为720秒，覆盖全部阶段与余量，空闲退出不固定等满预算。服务更新可能等待在途任务；超过预算仍可能需要强制结束，不能保证无限运行任务完成。无法验证执行owner或超时强杀会记录不完整退出，绝不猜PID、删除锁或重发业务。

到期关闭时显式等待独立聊天生产者保存回执。OpenClaw与API/通用harness的非用户中断保留`unknown`、`service_shutdown`、`execution_service_shutdown`与未结算占位，不报成功或用户停止；用户明确停止仍保留其原语义，已提交的完成回执不被收尾取消覆盖。关闭实例恢复后仍根据原生结果和持久材料核验，不新增外层重试。
