## 行为与边界

保存分析报告后，服务核对该报告对应的正常完成轮次，再提取明确“经验候选”或“Experience candidates”章节内的原文列表。格式为 `- [作品ID: n1] 观察、行动与局限`，引用必须属于该分析保存的作品；单项20至1000字符，最多3项。代码围栏内和普通正文不提取；缺明确章节不猜测，不复制整篇报告，也不再调用模型。分析提示只在有依据时请求该章节，不能保证真实模型一定产生合格候选。

所有新条目均为pending，不影响现有有效经验，人工在画像“经验沉淀”确认后才可召回。候选保留原文、字符起止偏移、文本哈希、作品ID、来源材料/报告哈希及原轮次；偏移按Python Unicode字符计，不是UTF-8字节或JavaScript UTF-16索引。新分析由服务固定原画像名称与profileId，提取不随当前界面的画像选择转移；画像删除重建后拒绝旧来源。旧分析没有绑定画像时继续手工选原文，不自动补绑定。

Web按轮归档快照或最近标记、Codex按轮状态核对正文与正常终态；存在Web SQLite运行账本时，还需该轮completed且settled。运行中、中断、缺终态、正文不一致及原对话已删除时延后或拒绝，不将保存报告等同正常运行完成。旧轮有独立归档时不受新轮最近标记覆盖影响。本批只核对本地保存事实，未验证全部引擎的原生恢复或提供商远端状态。

提取指纹包含来源绑定/版本/轮次、方法`analysis-explicit-section/1`与适用条件，在同一SQLite事务中保存候选及不含报告正文的回执。重复/并发重试返回原回执，整批失败回滚；同版本已拒绝/删除的候选不会因重试重建。回执是当时的结果，新增数量不会随之后的删除而重算；实际条目状态以画像管理页为准。来源更新会形成新版本候选，旧记录保留、来源状态重新核对。来源库与经验库是两个数据库，本批不声称跨库分布式事务：写前复核一次，之后的变更由正常source_status暂停注入。

格式规范化相同的同来源条目复用；新回执selections保留复用条目的原文位置与哈希，不改写原条目版本，旧回执不重写。跨版本或不同来源、同范围同条件的pending/active条目可得到最多3条字面比较引用。NFKC、大小写、空白及末尾句号规范化，或至少8个词项的Jaccard重合度达到0.85，仅作为文本比较提示，不是语义理解、质量验证或自动合并。正文变化、数量、否定与因果关系仍需人工核对。比较只保存条目ID与版本，界面读当前正文并标注版本；删除后不保留比较副本。

## 入口与失败处理

- 自动：分析结果成功保存后调用共享服务，失败不撤销已保存报告，返回简短延后回执。
- HTTP：`POST /api/persona/{原画像}/memory/extract-analysis`，参数bindingId、可选sourceHash/profileRevision/conditions；成功重试回执也写回仍匹配的报告，迟到回执不注释新报告。
- CLI：`easel memory extract-analysis --profile "原画像" --binding "分析来源ID"`，使用同一服务与数据目录，不请求模型或自动激活。
- 界面：原分析辅助面板的“保存画像经验”默认折叠，里面提供提取按钮及短回执，原手工候选草稿保留；画像页“相近条目”也默认折叠。没有新增常驻说明卡。

读取与候选开关独立；关闭保存候选时不写入新条目。未托管旧经验需要原有人工导入流程；此版本不会自动托管。报告同一轮/同正文重复回填保留原时间；正文或轮次变化则形成新结果，旧提取回执不会误挂到新报告。
