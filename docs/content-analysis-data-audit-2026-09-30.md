# 内容分析数据能力审计（2026-09-30）

## 结论与证据边界

本报告为代码静态审计，未登录七个平台，未进行真实浏览器、HTTP 或真实后台采集验收；测试文件的存在不等于此次运行通过。平台页面是否改版、当前账号是否有权限、指标是否实际返回，仍需独立验收。

Easel 已有七个平台的采集入口，但不能称为七个平台等深度内容分析产品。小红书具备账号归属隔离、逐篇证据、本地保存、JSON 导入、探索性词语建议和加入选题的闭环；其余六个平台目前主要是本次登录会话的指标及有限作品列表展示。网页后端主动删除这六个平台的历史增长结论，这是保护数据可信度的正确降级。

定位应为“账号数据复盘与证据辅助选题”，不是“全平台智能归因/爆款预测”。源码文件开头的概述、注释中的近七日或多窗口描述，不应替代实际字段、实际窗口与路由行为。

## 需要优先处理的数据正确性缺口

1. **公众号按标题连接数据有错配风险。** `_parse_analytics` 使用 `by_title[title]`，同名文章会覆盖，且发表页 metrics 保留阅读/点赞，stat 却被另一响应阅读/分享替换，可能出现两种口径同时展示。应以平台文章ID（如biz、mid、idx或稳定URL映射）连接，并保留各端点/周期，无法唯一匹配就并列为未关联证据。
2. **公众号分析页缺失值仍可能变成0。** `int(info.get(...) or 0)` 及粉丝回退解析中有此模式。尽管发表页 `_count` 已区分零与缺失，分析页 fallback stat 仍可能制造“阅读0/分享0”的文案。需要与结构化字段采用同一个严格缺值函数。
3. **公众号期间数据不等于自然期间。** `_tendency_metrics` 取最后N条，字段缺失时合计已知子集；即使有统计天数，也缺明确完整性、连续性、去重说明。应返回 actual_from、actual_to、expected_days、observed_days、missing_days、metric_coverage。
4. **“ready”不等于分析充分。** `build_analysis` 的总体missing只检查四个通用概览字段、是否有notes/metrics，未把逐篇缺失传到总体状态；一些平台原生就没有following/likes而长期partial，一些全概览存在但逐篇数据缺失也可能ready。应改为平台能力期望值+实际证据完整度两层，ready不承担业务可分析认证。
5. **通用字段名与真实定义错位。** 小红书 likes 是赞藏合计；知乎 likes 是赞同；B站 total_fans 在标签中叫“涨粉”却可能是累计；统一标题“播放/阅读”不代表统一 metric 定义。必须保留native_metric、definition、aggregation、unit。
6. **较低成熟平台的作品标识不足。** 抖音按标题去重，快手无ID，知乎截断标题，视频号仅链接。不能直接泛化当前小红书证据模型而以标题当主键；先补稳定ID、状态、绝对发布时间，再补分页和指标。
7. **累计数与增量、时间窗口不可互换。** B站的value为累计而comparison来自未知窗口增量；平台界面“近7日”和后台观测间隔是两种时间对象。统一仪表盘需显式区别“累计值”“平台期间值”“本地快照差值”。
8. **格式安全验证不等于链接可用。** `safe_link` 仅校验https、凭证、允许域；小红书证据链接剥离访问token后也未验证平台能否直接打开。应分别展示“平台原文/管理页/根据ID构造”，记录最近浏览器验证结果。

## 产品层可承诺与仅属规划

可以如实承诺：七平台发起采集；显示当次返回数据及缺失原因；小红书范围明确的本人/导入证据浏览与静态探索词；B站有限逐篇结构化数据；公众号有限文章及每日合计；失败不冒充空账号；非小红书历史增长主动禁用。

本次审计代码中尚未实现、只能进入路线图：全量历史作品分页；七平台账号归属隔离统一化；完整逐篇日趋势；稳定的曝光→阅读/播放→互动→转粉漏斗；完播、点击率、粉丝画像等跨平台统一能力；主题/形式/长度/发布时间分组对照；实验登记与结果追踪；统计显著性；因果归因；自动爆款预测；跨平台总互动排行榜；除小红书外的证据建议入选题；七平台离线导入映射；定期自动采集与采集质量SLA。

这些功能有些可能存在于技能说明或其他产品规划，但不能由本次账号分析实现推断已经可用。特别是通用大模型写作/洞察技能不等于经过账号数据证据链约束的分析引擎。

## 防止跨平台口径混合的具体数据与界面设计

建议最小事实表一行一个指标观察：`platform, account_id, identity_source, verified, content_id, native_metric, normalized_metric, metric_definition_version, unit, aggregation_type, is_unique, window_start, window_end, timezone, observed_at, published_at, source_endpoint, coverage, raw_value, value, missing_reason`。时间或去重未知直接unknown，不填默认“7日”。

筛选器按平台→账号→指标定义→实际窗口限制可比范围；默认只在同平台同账号同指标同窗口比较。可跨平台汇总的是发布工作量等明确定义的运营事实，互动/播放/阅读等指标默认并列，不能自动求和排名。对“阅读人数日合计”和“区间去重阅读人数”用不同指标ID；对“累计获赞与收藏”和“点赞”同样分开。

卡片固定显示：数据来源、原生指标名称、累计/期间/快照差值、实际日期与时区、账号核验状态、采样页数/篇数、更新时间、缺失项。作品排名要求结构化指标、稳定作品ID、同类作品与同龄观察窗口；没有曝光分母时不显示互动率；样本缺字段时不把未知排成0。

增长图优先使用相同起止时间的原生平台值；只能使用快照差值时明确“距X天前观察值变化”，显示真实since_days并拒绝包装成自然周环比。跨平台对照可看“各自相同规则下的历史分位”等派生值，但需独立基线与足够样本，目前数据尚不支持。

## 建议实施顺序与验收

P0：修复公众号连接键/缺零/期间语义；定义指标字典；统一所有平台账号主键与来源；延续旧未归属快照隔离；将ready/partial改为能力与数据质量双层。

P1：每个平台实现稳定作品ID、发布时间、状态、可核验链接和逐篇指标；分页必须返回page_count、cursor、has_more、total_expected、complete及中断原因；接入后再开放排名与同龄作品比较。

P2：导入映射向其他平台扩展；采集任务质量日志；证据快照导出；保存可重复统计窗口。每一步均与账号切换、登录失效、清除数据的并发控制一起验收。

P3：围绕具体决策建立建议卡：事实→解释假设→推荐单变量实验→成功指标→下次复查；先做描述性分析，后做对照与统计，不能从静态关键词均值直接跳到因果结论。

离线验收至少覆盖真实0/未知/负值/非法值；重复标题不同ID；重复日期不同scene；缺日期与日期不连续；缺字段的部分合计；导入/live隔离；账号A请求在切到B后返回；清除后在途请求；无数据与采集失败分离；分页中断与重复页去重。

现有测试证据：`tests/test_account_analysis.py` 六平台展示、缺失/0、登录失效、链接校验、路由错误；`tests/test_xhs_account_data.py` 归一化、保留两次、365天、空样本与失效；`tests/test_xhs_insights.py` 候选词、证据、缺失降级、去重与入选题；`tests/test_account_lifecycle.py` 身份失效/旧请求/缓存generation/退出。它们以离线及stub为主，不能替代真实平台测试。

真实验收应每个平台用已授权测试账号记录：登录身份、成功采集时间、平台原页面截图/合法脱敏响应与字段对照、样本总数及分页边界；逐项打开创作中心/作品原文/管理页/入选题等链接与菜单；分别报告浏览器交互结果、HTTP可达结果、模拟数据测试、真实后台核验，未测项明确“未验证”。
