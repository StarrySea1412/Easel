# 0.14.5 会话占用与重启恢复

用户反馈原轮次显示 `chat_supervisor_lost` 后，发送「继续吧」立即返回「该会话仍有运行」，同时 138 出现短暂 502。

## 已确认的原因

正式 0.14.4 的会话最近轮次已经 `done`，相同 turnId 的运行账本已结束，但 SQLite `chat_leases` 仍保留两小时占用。正常完成通过原进程的 `on_done` 回调释放；进程死亡后，`stop_orphan` 保存了终态却没有释放该占用，因此下一条消息被 409 拒绝，未提交模型。

2026-10-28 北京时间 11:50:50，内核日志显示应用 cgroup 达到 2 GiB，OOM 杀死 OpenClaw Gateway。11:50:51 监管程序检测子进程退出并重启容器；nginx 连接内部 7880 被拒绝，返回 502。容器主进程没有直接被 OOM 杀死，Docker `State.OOMKilled=false` 不能排除子进程 OOM。排查时正式实例已有临时 3 GiB 限额，但 Compose 仍为 2 GiB。

## 修改与边界

- 原轮次确认结束且终态保存后，按 sessionId + turnId 条件释放租约；重复停止已完成轮次可以补充释放。
- 新消息遇到占用冲突时，在跨进程会话锁内核对租约、最近轮次及运行账本。只修复身份一致、明确终态且执行/资源均已结算的旧记录，然后重新走一次正常准入。活跃、待确认、账本损坏、身份错配、另一进程持锁和本进程任务仍被阻止。
- 旧回调只删除自己对应的轮次，不会清除后续轮次的占用；不自动发消息、不重复调用付费模型、不删除原回复。
- Compose 默认 `EASEL_APP_MEMORY_LIMIT=3g`，可由部署环境明确覆盖，防止重建恢复 2 GiB。更高限额是本次 OOM 的容量修正，不是证明任意媒体/模型负载都不会 OOM。
- 监管错误记录 Gateway/Web、PID、退出码；信号 -9 提示检查内核 OOM 证据，不把所有 -9 都武断归因于 OOM。
