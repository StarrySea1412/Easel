# Easel 0.39.0 候选：经验归并与冲突提案

2026-10-27。继续完整竞品对标与大版本迭代。原Agent现在可以对本轮实际读取的经验提出合并或冲突修订；用户明确确认后才替代旧版本。定时页保持紧凑，不增加常驻解释区。138及安装器未更新。

## 行为与入口

“更多 → 画像 → 经验沉淀”保留原候选、独立读写开关及单条替代。手工提案在“适用条件与替代”中选择“经验归并”，勾选同范围、同条件的有效经验并填写原因。合并选择2至8条，冲突修订选择1至8条；不跨画像、平台账号或条件，不自动放宽条件。

原生Codex的`easel_memory_candidate`与OpenClaw的`queue_experience.py --proposal-file`沿用原提案通道，增加可选`consolidation`。原Agent根据本轮已召回条目判断语义关系，提交`kind`、`reason`和每条旧经验的`id/revision/contentHash/scopeHash/conditionsHash`。宿主按实际经验使用账本核对，不允许挑选本轮未读取的版本。文本、引文与条件沿用0.37.0契约，正常终态、资源结算和原回复引文核对后，只写待确认候选；不新增模型请求。API/其他Harness未接入原轮次提案链，不冒充支持。

语义建议是Agent的假设。原文匹配只证明出处；没有证明合并结论正确、冲突已解决或策略有效。既有字面相近提示继续明确标为字面相近，与语义提案分开。没有可信依据时保留分歧。

归并原因和引用版本默认折叠。确认弹窗同时显示旧文、原因和新文，用户点“确认归并”后，同一SQLite事务核对全部版本与来源、将旧条目全部标为已替代，再激活新条目。失败全部回滚，并发竞争只能一个生效；接口要求原UI来源及正文/范围/条件/归并哈希。模型工具和CLI不能确认。取消/Esc返回原按钮焦点；刷新不会偷偷把草稿改绑到新版本。

## 来源、删除与恢复

引用只保存ID、版本和哈希，不保存旧正文副本。待确认时引用必须仍是原有效版本；确认后只允许本次替代造成的那一次版本递增。原条目被删除、修改、恢复或其材料/原轮次变化时，相关归并经验暂停召回；兼容`memory.md`同步排除不可用来源。条件与账号经验仍只通过任务上下文读取。

永久删除清除条目及正文历史、保留候选墓碑和ID拓扑，晚到同源提案不能复活。删除中间正文也不能绕过恢复互斥。替代/归并连通组采取保守恢复规则：关联组已有有效经验时不能再恢复另一条；失效新经验不会自动重新激活旧经验，也不提供一键恢复全部原条目的操作。深度超过32的依赖链暂停读取，须人工重新整理。

应用使用者与Agent可能共享同一OS身份；UI来源校验不是OS级沙箱，不能防止拥有同用户任意执行权限的程序直接修改数据库。

## 升级与回退

版本单一来源`pyproject.toml`及前端package/lock为0.39.0。升级前结束并核对在途运行，关闭网页和空闲执行服务，备份完整数据目录及一致的SQLite快照，再更新同批后端与前端。新增`consolidation_links`表和条目依赖字段；原单条替代/历史条目兼容。

旧后端不认识新来源依赖，不能直接读取已升级数据作为安全回退。回退必须同时恢复升级前完整数据备份，不能仅删新表或退代码。138仍需单独部署、运行SHA、真实浏览器与业务验收，本批不发布安装器。
