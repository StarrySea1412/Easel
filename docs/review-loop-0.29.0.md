# Easel 0.29.0候选：结构化审查与限次返工

2026-10-26，基于22c2b4f4继续完整竞品对标与大版本迭代。本批将顺序角色协作中的审查建议贯通到返工，不将文件存在或模型建议通过当成质量验收。

## 行为与协议

聊天目标工具栏选择“协作”后，新目标使用独立的`reviewed-delivery`协议：研究→制作→审查→整理交付→人工验收。旧`research-delivery`目标继续使用原Markdown文件，不隐式迁移。现有指定阶段重做、定时计划、经验候选和共享上下文预算保留。

审查阶段写入`workflows/<goalId>/review.json`。运行器在认领该轮时冻结`reviewContract`，记录schemaVersion=1、目标ID、revision、turnId、上游stageId/turnId/条件与证据哈希，以及可返回的上游起点。JSON须包含且只包含：

- `contract`：原样保留该轮冻结契约。
- `decision`：`pass`、`revise`或`blocked`。
- `summary`：3至1600字符的实际结论与局限。
- `targetStageId`：返工时选已完成上游ID；其他结论必须为null。
- `findings`：最多8条，每条3至1200字符；返工/阻塞必须至少1条，通过时必须为空。

文件最多64KiB，严格检查字段和类型；重复字段、不完整JSON、错误轮次/版本、输入变化或核验期间文件变化均阻止交付。运行器再次核对真实上游文件和审查文件证据。契约只证明绑定关系，不证明审查模型确实发现了所有问题。

`pass`只允许进入整理交付。`revise`最多自动返回研究或制作一次：同一SQLite事务结算当前运行、保存原阶段/审查回执和验收快照、递增目标revision、重置起点及下游；保留上游、原文件、全部运行和累计尝试次数。具体问题进入后续请求，明确作为被替代的参考材料。后续阶段须重新生成并核验新版本，文件不会恢复为历史字节。

轮次、已结算时长、工具和图片预算不清零。自动返工次数按整个目标累计，人工修改或重做也不重置；再次返工或剩余预算不足时进入`review_rework_limit`，材料不足进入`review_blocked`，无效结论进入`review_invalid`。新协议创建和修改均须保留人工质量验收项；不能通过移除该项跳过人工检查。暂停、取消、删除或恢复未确认的旧轮不会自动重启。

## 页面与导航

原折叠阶段详情显示“模型建议通过/返工/暂停”、简短结论和具体问题，原始当前JSON从交接文件链接读取，不把整个契约重复铺在界面。原返工历史按需读取，保留当时问题和文件证据，不用当前文件冒充历史副本。

定时任务地址为`#/schedules`，支持刷新和直接打开；与任务`#/tasks/<id>`及发布回执地址之间的切换保留浏览器返回记录。该地址不包含新建/编辑中的未保存表单，刷新不承诺保留这些临时输入。
