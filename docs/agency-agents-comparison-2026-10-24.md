## 对标结论

- `agency-agents` 当前参考提交为 `4e3ac3ca6604c75113f52c695dbddcc7af928b46`。可借鉴的是角色职责、输入/输出、工具边界、失败回退和暂停条件的显式契约；角色提示词不能替代权限系统、任务账本或真实验收。
- Codex 的线程/轮次/事件、steer/interrupt 和恢复语义，适合继续对齐 Easel 的 `turnId`、SSE 重连、停止和账本；当前实现仍以 OpenClaw 为默认引擎，Codex 只按已检测能力提供入口。
- ZCode 的目标推进、记忆范围和逐轮验收提醒了 Easel 要把目标、阶段回执和证据分开保存；本轮没有把外部 Memory 当作 Easel 的共享记忆来源。
- DeepSeek Harness 的持久日志、任务 owner、子执行和 compaction 记录支持现有账本继续做“请求已接受、结果已完成、资源已释放”三段式状态；本轮未迁移 Cordis。
- Grok Bot 的命名角色、跨任务交接和例行工作流适合内容分析→创作→产物→发布准备的产品方向；账号、素材和浏览器权限仍按 Easel 的会话与任务范围控制。

## 本轮已落地

1. 修复 138 暴露的 Linux 聊天首个 POST 500：`easel/browser_bridge.py` 在进入 `shlex.quote()` 或 Windows quoting 前统一把 `Path` 转为字符串；续接接口随后出现的 404 是首个任务未建立的后果，不再把它当成独立根因。
2. 新增 `web/agent_roles.py` 版本化角色注册表和 `GET /api/agent-roles`。角色只描述职责、输入、交付、工具边界、回退和暂停条件，不携带凭据或权限。
3. `ChatRequest.roleId` 进入 OpenClaw/Codex 请求快照、角色契约、运行账本和最终 turn 记录。前端共享 `Select` 角色选择器按会话保存，普通发送、队列、重试、编辑分支、Codex 插话和刷新续接都保留本轮角色。
4. 角色状态与已有阶段事件、失败分类、停止/恢复边界一起展示；恢复不重新发送模型请求，未知终态会保留部分内容并暂停队列。
