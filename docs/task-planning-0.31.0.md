# Easel 0.31.0候选：结构化任务拆解与层级计划

2026-10-26，继续完整竞品对标与大版本目标。0.30固定并行图保留，本批增加按目标拆解的独立协议；不是完整大版本完成或138部署回执。

## 行为与使用

对话目标的原紧凑菜单新增“任务拆解”，对应`planned-reviewed-delivery`。定时计划在原“完成标准与执行上限”折叠区复用同组选项；编辑计划保留其执行方式和原轮次上限，不隐式降为直接推进。计划仍保存为暂停，不自动启用或请求模型。其他三种推进方式沿用旧协议。

先由编排轮生成`workflows/<goalId>/plan.json`，本轮不执行拆出的工作。运行器读取最多64KiB严格JSON，校验冻结的目标ID、修订、轮次、目标/验收条件摘要及总限额；计划、运行结算与工作图展开处于同一SQLite事务。缺字段、未知角色、重复字段/ID、无效路径、超限/变化/过期计划只阻塞，不派发子任务。运行器分配每个节点的独立交接路径，附加文件条件不能占用当前协作交接目录。

计划包含1–6个实际工作节点；剩余轮次还必须容纳审查和交付。最多4个分组、3层组归属，不接受空组、循环组、缺失引用或有环依赖。组只组织任务，显示在现有列表的短路径中，不另套卡片。工作节点明确目标、登记角色、依赖、read/write和最多3项附加文件/文字标准；独立交接文件由运行器强制追加。不能由计划取消最终人工验收，结构化审查、整理交付也由运行器统一追加。

调度仍由原TaskService和SQLite认领。同目标最多两个未结算工作会话；声明读取的分支可重叠，声明修改共享产物的阶段与其他全部工作阶段排他。访问声明控制调度和提示，**不是工具写入拦截或操作系统/文件权限沙箱**。工作会话仍共享作品目录；真实模型是否遵守声明和产物质量需要后续实际验收。没有开放模型直接spawn、嵌套计划或任意深度自主Agent树，也没有自动复制父对话完整历史。

总轮次、时长、工具和生图预算累计，不按节点复制。目标菜单默认16轮、1200秒、40工具、0图；16轮是上限，不要求填满6个工作节点。时长预留和未知占位沿用0.30；同供应商队列可能继续串行处理请求，不能保证真实模型并发、质量提升或成本下降。

## 返工、恢复与界面

统一审查引用实际依赖祖先及其文件版本；编排轮列为审查材料，不能作为自动返工起点。计划覆盖不足时审查应阻塞，人工可显式从“拆解任务”重做；其他可修复问题仍最多自动返工一次，之后需要人工处理。模型建议通过不能代替最终质量验收。

叶节点重做只重置其依赖后继，保留原计划、无关分支、分组/访问属性和旧回执。显式重新规划归档整个旧图与计划回执，只恢复编排入口并保持暂停；后续计划可以不同，旧节点ID复用时累计尝试次数保留。修改总目标同样退休旧计划。累计轮次、工具/图片/时长及自动返工次数均不清零，不删除文件或恢复旧字节。

暂停、取消、删除、未知运行和预算不足沿用已有屏障；规划轮的晚到结果也不能展开工作图。重启未知工作会话不会自动重发。内部工作会话仍只在核验/办公室检查目录中临时派生，回到对话指向父会话，不进入持久聊天列表。

原始计划JSON不作为长篇常驻说明或完整交接正文显示：现有折叠详情仅补任务/分组数量和文件链接。重做确认区分重新规划与叶节点返工，旧计划回执也保持折叠。紧凑132像素目标菜单、任务/定时页独立地址和响应式保留。
