# 0.45.9 输出触顶的有界安全接续

## 问题与根因

138正式问题`63eafc65f6d258cbb204919d55ed8474`发生于0.45.5 / build `747adfea1933`。`happycoding/minimax-m3`在单轮输出8192 tokens时以原生`stopReason=length`结束；助手没有正文，也没有工具回执。Easel只看到了Gateway泛化摘要`failed`，没有把本轮原生终态用于自动继续判断，因此自动继续没有触发。原请求没有重放。

本修复把精确会话/对话轮次的OpenClaw轨迹纳入恢复判定，覆盖Gateway没有传递终止原因的情况。第一次接续后，不会继续用原轮次的轨迹触发额外调用，避免把旧终态当作新轮次状态。

## 接续边界

- 必须显式启用当前对话的自动继续偏好；仍遵守每轮最多2次和用户停止。
- 只在原生轮次明确以`length`、`max_tokens`、`max_output_tokens`或`model_length`结束时按输出触顶恢复。
- 当前轮必须没有任何工具操作。发生过工具、生图、上传、发布或其他工具调用时，不自动再运行模型；保留已收到正文和失败原因，用户可检查后手动继续。
- 读取当前轮次的工具审计必须完整且无警告；待确认问题、未完成工具状态或取消均阻止接续。
- 接续继续使用原会话和所选模型，使用独立幂等ID与专用接续提示，不重发原始用户请求。
- 不提高模型单次输出上限。触顶的长任务仍可能需要用户拆分内容或手动续写。

## 验证

- 后端相关组合覆盖模型路由、执行轨迹、账本、恢复、失败诊断和Gateway运行器；源码当前为0.45.9候选。
- 精确回归覆盖“Gateway返回泛化`failed`、原生本轮轨迹只有`stopReason=length`”并确认只产生一次安全接续。
- 输出上限空正文、部分正文、连续触顶最多2次、用户取消、审计警告及已完成工具操作均有回归；有工具操作时确认没有第二次Gateway派发。
- 16个独立假Gateway会话并发，连续3轮合计48个触顶逻辑任务、96次合成RPC，0失败；校验会话身份、幂等ID和正文无交叉/重复。
- 没有重放原问题、调用真实模型或向138制造压测负载。合成测试不证明Minimax M3真实续接质量、供应商可用性或138生产稳定率。
