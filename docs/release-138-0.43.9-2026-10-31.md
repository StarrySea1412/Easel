# 138 问答等待与停写备份修复 0.43.9

## 变更

1. 停写备份使用当前已校验候选的 Compose 控制文件，避免访问闲置盘迁移后 root-owned 的旧发行文件。旧镜像回滚身份核验保持，不修改旧目录权限。
2. 原生 Gateway 注册 `on_tool` 不代表实际收到所有工具事件。所有 OpenClaw 传输均从本会话、本轮边界内的日志补齐执行账本，按原 call ID 合并，不重放模型、工具或副作用，终态不会被迟到事件复活。
3. 有效待答问题先于工具记录到达时，后到的 `ask_user` 仍继承等待标记；已回答/返回、失败及轮次结束清除等待。沿用0.43.6显式网关认证和未知状态保留问题卡片。

## 根因与回归

0.43.8隔离真实浏览器出现问题卡片、A选项提交和最终回复，卡片功能已通过；但相同轮次的执行账本 `operations` 为空，日志可读取 `ask_user`。原生连接有工具回调时跳过日志补齐，导致页面从日志显示工具而等待标记没有对应行。

修改前新增回归分别复现原生连接无工具帧时账本为空，以及问题先到时后到工具没有等待字段；修改后已通过。原生替身在运行中即检查持久账本，避免只用最终结果证明实时状态。
