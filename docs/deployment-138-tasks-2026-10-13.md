# Easel 138部署任务清单

日期：2026-10-13（Asia/Shanghai）。关联需求R110/R113，依据[部署评估](deployment-138-assessment-2026-10-13.md)。本轮交付任务计划；部署代码、发布包和138上线尚未完成。

## 交付目标和执行顺序

在192.168.0.138提供一个可认证访问、数据持久保存、可回滚的Easel工作台，保留AI-skills现有入口和业务。默认引擎OpenClaw；Codex验证通过才启用，不要求6.1 sol。首版是可信操作者的共享工作台，多人账户/独立数据空间另列后续任务。

执行顺序：D01→D02/D03→D04/D05→D06→D07/D08→D09→D10→D12。D11为可选Codex支线，仅在主体就绪后推进，失败不阻塞D12。这里描述依赖，不分派额外Agent。

目前只有R110研究已完成。下表所有实施任务均待开始；每项完成必须附实现提交、检查结果、环境和未验边界，不因出现源码/构建成功而自动勾选验收或上线。

## 具体执行与验收

### D01：先冻结可发布基线

- [ ] 将现有界面/网关等未提交修改与部署工作区分开，明确本次版本包含范围，不能打包后标称来自未包含这些变化的HEAD。
- [ ] 固定经过必要回归的Git提交；固定Python3.12、兼容Node24.x（至少24.16）、OpenClaw2026.9.6和可选Codex0.147.0。未知新版本另验协议。
- [ ] 发布当天只读复核CPU/可用内存、根盘/Docker盘、运行容器峰值和候选端口；2026-10-13的6核/9902MiB/16G余盘只是快照。
- [ ] 初始单活跃Agent/单重媒体任务；候选Easel总内存预算2GiB、CPU上限2核，按隔离实测调整且给现有服务留下余量。内存容器上限与应用限流都验证，不只写配置。
- [ ] 明确镜像、展开包和两版回滚占用；建议发布后可用磁盘仍≥5GiB，不足时先缩减/转移构建缓存，不自动清理其他项目镜像。

### D02：构建Linux镜像

建议代码交付位置`deployment/138/Dockerfile`、`deployment/138/compose.yaml`；实际实现可调整，但runbook必须一致。

- [ ] 多阶段构建前端，`npm ci`及干净dist；应用镜像包含web、easel、scripts、完整skills、静态资源和第三方许可。
- [ ] Linux安装Python、FFmpeg、Playwright Chromium及动态库、OpenClaw；不复用Windows便携运行时或.venv。
- [ ] 建立Linux锁定依赖与安装回执，量化镜像体积/冷启动/RSS，确认中文与空格路径。
- [ ] 非rootUID/GID与卷权限匹配；禁止.env、auth缓存、私人config、浏览器登录态、个人outputs、.git入镜像或构建上下文。
- [ ] 不运行宿主机全局安装setup.sh；不使用含PowerShell监听检查的start_workspace.py作为Linux入口。

### D03：监管服务和任务

- [ ] nginx与应用服务独立，Compose项目`easel`；应用容器内Web/Gateway共网，Codex走stdio。
- [ ] Web仅一个worker、供nginx内部访问，不发布Web/Gateway端口；Gateway仅loopback。
- [ ] 进程管理覆盖冷启动、子进程异常、退出清理、自动重启与有界日志；不能把gateway.sh的后台启动当作可靠容器PID1。
- [ ] liveness与readiness区分Web可达、Gateway状态和模型调用；Codex缺失不让OpenClaw主体失效。
- [ ] 对Agent、浏览器和重媒体任务做全局限流；满额明确排队/拒绝，不默默运行更多进程。停止及失败准确释放名额。
- [ ] 容器重启未终态任务标未确认、不自动重发；禁止宿主机Docker socket或AI-skills生产目录进入Agent可写空间。

### D04：持久化与迁移

- [ ] 代码`/home/ubuntu/Easel`与easel-data/easel-state/easel-secrets/easel-backups分离，容器路径固定/app、/data、/state。
- [ ] 显式配置EASEL_DATA_DIR、EASEL_OPENCLAW_STATE_DIR、OPENCLAW_STATE_DIR、OPENCLAW_CONFIG_PATH、EASEL_CODEX_HOME；独立Gateway端口/设备身份。
- [ ] 平台浏览器profile逐个查实际位置，覆盖账号登录、outputs/_login及工作目录；不用“卷存在”代替登录持久化验证。
- [ ] 重建与换目录后对照文件hash、会话/任务记录、配置和设备身份；迁移平台账号材料另需用户明确授权，不夹带ZIP。
- [ ] 浏览器本地草稿/会话列表按已有备份导出/导入路径验证；不同设备/Origin不自动共享，不把只读导入历史挂成活跃任务。

### D05：入口认证与HTTPS

- [ ] 候选`https://192.168.0.138:8444/`在上线当天检查未占用且访问规则明确；TLS证书有IP SAN并被访问设备信任。HTTP curl -k成功不算TLS浏览器验收。
- [ ] nginx可先用标准密码哈希的入口认证保护可信操作者；页面、API、SSE、媒体、下载、预览全部覆盖，无旁路。
- [ ] 生产使用独立凭据；隔离测试管理员gaojitest/gaoji仅供测试环境并验证登录入口，不植入业务源码或生产镜像。
- [ ] EASEL_EXTRA_HOSTS/ORIGINS按真实地址精确配置；校验转发头、无Origin请求和恶意Origin，访问认证不靠Origin判断。
- [ ] SSE关闭proxy_buffering/cache，配置心跳和合理超时，上传大小有界；生产静态文件和旧哈希模块兼容策略明确。

### D06：OpenClaw主体就绪

- [ ] 独立profile/配置/设备审批与准确网关状态，重建不换身份，不能干扰本机便携或AI-skills。
- [ ] 在实际运行容器验证DNS/TLS/渠道接口；此前aihub.top根地址15秒超时是需排查项，不当作模型接口必然不可用。
- [ ] 配置状态、可用模型与实际调用分开记录；缺Key/依赖时直达设置且保留草稿。
- [ ] 技能列表、读取指南、实际执行受控脚本、样本产物核验都检查；平台登录和发布能力按各自边界留待后续。

### D07/D08：发布与回退

- [ ] 发布脚本只取选定commit与对应前端构建，生成源码逐文件MD5/SHA-256和镜像/依赖清单，ZIP用SHA-256验证传输。
- [ ] 服务器以`Easel.new.$STAMP`/`Easel.prev.$STAMP`换目录，项目名easel固定；秘密和数据不随代码换目录。
- [ ] 候选目录先核结构/摘要/Compose/nginx/资源/镜像再切换，保留旧镜像digest；不能只校验上传ZIP就称运行代码一致。
- [ ] 备份data、state、相关运行配置与入口/TLS材料到受控位置，日志中不打印秘密；数据兼容性决定是否需要停止写入快照。
- [ ] 隔离环境演练启动失败、配置错误和重启中断，恢复旧代码+旧镜像；数据恢复与代码回滚分开，恢复快照前保留新产物。
- [ ] runbook包含确切服务名、命令、验收入口、版本清单、停止/回退步骤，不引用AI-skills worker清单为Easel操作命令。

- [ ] 真实模型、受控HTTP/模拟、浏览器、服务器进程和本地文件分别记录，不混成“全功能通过”。
