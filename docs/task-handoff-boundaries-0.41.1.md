# 0.41.1：阶段交接的共享文件边界

日期：2026-10-30。本批沿用现有任务、角色、原生Codex交接工具和作品登记，不新增界面面板或常驻说明。完整对标及大版本目标继续，不能把本次兼容修复视为全部完成。

## 已复现的缺陷

`easel_task_deliver`已经限制主文件必须属于当前阶段或允许制作的最终文件，但HTML/CSS关联资源也会被复制。原入口只保护其他阶段的声明路径及已完成阶段的依赖，没有把不允许当前阶段写入的最终产物及其资源纳入同一保护集合。

- 审查或整理交付阶段可以提交合法的阶段HTML，却通过其引用的CSS改写最终文件或最终网页的样式。四个角色/资源组合在修复前均没有拒绝交接。
- 另一个实际Windows目录junction回归证明：依赖通过不同目录名称指向同一个上游文件时，原来的字符串路径比较没有识别出覆盖。该回归在修复前同样失败，不是仅静态推断。

首轮四项测试因夹具错误调用不存在的`ArtifactStore.events`而失败；改为读取实际事件表后，才取得四项`DID NOT RAISE TaskConflict`的产品故障证据。Windows不能创建普通目录符号链接时使用临时目录内的junction，未放宽文件边界。

## 修复后的行为

1. 当前阶段以外的声明文件、当前不允许写入的最终产物及其现有HTML/CSS依赖，均纳入共享交接保护。
2. 依据解析后的实际目标路径比较，覆盖目录符号链接、Windows junction及系统路径大小写规则；不只比较提交的字符串。
3. 已受保护资源的字节完全相同时直接复用，不替换原文件；不同字节或原本缺失的受保护文件拒绝复制。
4. 全部提交文件先检查完成，再开始原有复制流程；被拒绝的批次不写入前面合法文件、不新增作品或交付事件。同一次交接中，实际目标相同而字节不同的资源也拒绝。
5. 制作阶段仍可以交付现行契约允许的最终产物及资源。原身份、停止/预算检查、阶段新版本要求、最终人工验收和原生工具观察上限继续适用。

本批保护的是`easel_task_deliver`和兼容交接回执进入共享证据目录的边界。它不是操作系统权限隔离，不表示原生工具无法在其已有主机权限下直接操作文件，也不新增整个文件系统的跨进程事务或活跃连接接管。
