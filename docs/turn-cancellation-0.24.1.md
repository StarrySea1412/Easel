# Easel 0.24.1候选：按轮取消与资源收尾

2026-10-26，基于c2f4d47e，继续完整大版本。本批修复现有停止链路，不新增调度器或界面容器。

## 行为与限制

- `/api/chat/stop`先保存精确会话/轮次的图片取消记录，再停止原聊天执行；普通聊天和现有Codex路径共用此入口。已排队图片立即结束，延迟到达的新图片请求被拒绝；原requestId重试仍返回原回执。
- 图片被认领后，在调用生成端前再次检查取消和目标状态，单次派发记录持久化。取消与派发事务以先获得数据库写锁的一方为准；派发准入已提交后仍可能提交供应商，所以停止请求不能保证阻止该图片或费用。
- 已认领、已提交或供应商状态未知的图片不因停止而释放占位。尚未派发的存活worker确认取消后结束；已提交图片的实际结果和文件仍保存。连接中断按原规则变为未确认，不自动重发；只能按真实结果或原有人工核对流程解除占位。
- 目标暂停、取消和预算耗尽都持久保留停止意图。资源不明不会将已取消目标改回可继续状态，预算收尾也保留。停止调用失败不撤销已保存的用户决定；执行进程失联进入未确认后，调度器按原轮次间隔重试，每次最多处理一个外部核对。
- 删除对话补查所属全部待结束图片，不依赖聊天占位仍然存在。目标核验查询整个所属轮次，不再使用最近100条/全局1000条的展示截断；回复优先读取逐轮快照，最近会话标记仅作旧数据兼容。
- 独立写作对话共享分析来源，不属于原分析的子运行；停止原分析不会递归取消独立写作。浏览器仍沿用现有会话归属，通用子Agent调度/取消、全部引擎恢复、经验自动提取/条件替代/统一预算、真实模型与平台业务评估继续保留。

## 升级与回退

产品和前端版本0.24.1。现有`outputs/_artifacts/image-jobs.sqlite3`增量创建`cancelled_turns(scope,requested)`表，原jobs表不变；JSON增加取消/派发时间。原TaskStore目标JSON沿用cancelRequested字段，不迁移或删除历史文件。

升级前先暂停任务并确认现有worker结束，停写后备份完整数据和SQLite一致快照，再启动同提交的前后端。旧worker不会执行新增的派发前检查，不能在混合运行时承诺取消已认领任务；旧代码也不理解新的取消表，回退须使用一致备份并重新核对未知供应商任务。不能删表、删记录或重新提交来解除未知占位。

不自动部署138或发布安装器；源码提交、开发预览与正式构建SHA分别核对。
