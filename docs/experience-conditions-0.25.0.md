## 使用与行为

- 画像经验候选可设置任务类型、必须包含的关键词和排除关键词；条件默认收起，不设置即沿用旧经验的无条件适用行为。任务类型可多选，关键词用顿号分隔。条件只对本轮用户正文作大小写不敏感的字面匹配，不执行表达式。
- 召回先核对画像、平台账号、有效状态、来源版本与适用条件，再按相关性和原有字符预算选择最多8条。未知任务类型不匹配限定类型的经验，不从“研究员/写作者”等执行角色猜测业务类型。关键词不能替代原有相关性筛选。
- Web根据已接收的写作来源确定writing，根据已保存账号分析会话确定account-analysis；其他普通对话类型保持未知。HTTP预览、CLI可显式指定其余类型。普通聊天与Codex使用同一经验服务；Codex在按轮去重后才构造来源、历史和经验参考，重试不重新绑定版本。不表示真实模型已读取或遵守经验。
- 新候选可选择替代同画像、同平台账号范围、完全相同条件的有效经验；不同范围或较窄条件不能移除较广旧规则。候选保存不改变旧经验。确认弹窗展示新旧正文，数据库在一个事务内确认新经验、将旧经验标为已替代并保存两边版本关系。过期版本拒绝确认，页面保留正文、条件和所选旧版本，不静默重选。
- 失效新经验不自动恢复旧经验。恢复必须显式操作，替代链中其他经验仍有效时拒绝恢复；连续删除中间正文后仍核对链关系，避免多个版本同时恢复。删除清除该条正文及修订；仅保留删除去重哈希和不含正文的关系ID/版本，画像整体删除清理这些关系。
- 条件参与候选去重、删除标记、确认身份和版本历史。用量回执保留选用条目的条件哈希和明确任务类型，不保存查询或正文。兼容memory.md仅投影无条件、当前画像范围的有效经验；条件经验和账号经验只能经服务筛选。

CLI示例（仅提出待确认候选）：

```text
easel memory propose --profile 示例 --text "摄影写作先演示成品" --task-type writing --keyword 摄影 --exclude-keyword 直播
easel memory context --profile 示例 --query "摄影教程" --task-type writing
```

HTTP沿用`/api/persona/{name}/memory`，候选增加`conditions`和可选`replaces`；`context`增加`taskType`。条件v1包含`taskTypes/allKeywords/excludeKeywords`，每组最多12项，每项1至80字。确认附条件哈希及可选替代绑定哈希；替代绑定固定原ID、revision、正文/范围/条件哈希。旧无条件条目与旧客户端无条件确认兼容。
