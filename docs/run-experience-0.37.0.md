2026-10-27。此前只有保存的账号分析中明确标注的经验章节能够自动提取，普通任务需要人工重新整理。本版让原执行Agent提出简洁概括和最终回复中的逐字依据，沿用画像经验管理的待确认流程；没有额外总结模型请求，也不要求用户回复增加JSON或长经验章节。

## 使用与依据

当前任务须选择已经托管的画像，并开启“保存候选”。普通Web OpenClaw和Codex提示词固定原画像ID、账号范围、已知任务类型和会话/轮次，未知任务类型不从角色猜测。原生Codex新线程提供easel_memory_candidate；旧线程和OpenClaw使用skills/shared/scripts/queue_experience.py或easel memory queue-run。工具不能指定其他来源身份、账号或active状态，每轮最多3条，概括和引文各10至1000字。

任务正常结束、完整结果快照和执行资源已结算后，服务逐字核对同一轮最终正文，保存来源摘要哈希与引文偏移。概括由当前Agent提出，引文匹配只证明出处，不证明结论正确、可泛化或真实效果。没有匹配的提案不写入候选，图片仍在执行时延后结算。用户在画像“经验沉淀”确认后才进入召回，条件、账号、来源可用性、版本与预算继续约束读取。

现有页面仅增加“任务提案 · 待复核”和“查看依据”，按需读取核对后的短引文；不在列表复制整段对话，不增加常驻说明卡。来源对话、编辑、拒绝、失效、版本与永久删除继续复用原入口。

## 一致性与恢复

绑定在派发前完成，原画像删除重建后旧轮不能补绑其他资料。提案幂等且有条数上限；结算在同一SQLite事务内写入候选与回执，前后再次核对来源，存储失败可重试。明确失败、停止、限长或删除清理暂存引文，关闭保存候选同时封存未结算绑定，重新开启不复活旧提案。拒绝/永久删除的候选也不会因重试重新创建。

OpenClaw监督器和原运行恢复在持久资源结算后尝试收件；Codex在客户端关闭且浏览器任务清理后持久确认资源，恢复只读取原生原轮次。断线未确认保持延后，不能当失败清空，也不能当成功提取。服务后台每30秒轮转最多50个暂存轮次，支持重启和图片结束后的重试；按画像读取也可重试。旧未结算运行不会永久挡住后面的来源。

这属于应用层约束，不是隔离同一操作系统用户的安全沙箱：无限制exec仍能修改本地文件或数据库。API直连及其他Harness没有本批同等资源事实，不声称已接通；无画像、未托管画像和关闭候选时不注入提案说明。没有自动语义合并、隐式用户偏好提取或自动激活。
