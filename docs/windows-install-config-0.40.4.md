# 0.40.4 安装、配置与发布兼容修复

## 变化

- Windows 分阶段安装恢复 `-SkipOpenClaw` / `-OpenClaw`。显式跳过时不执行 OpenClaw 安装、工作区同步或网关操作；新数据目录初始化 API 工作台，已有执行底座和 `.env` 原样保留。已有底座的安装与登录继续由用户核验。
- 安装检查点身份仍只由发行版本和安装目录决定；附加安装模式不再导致同版检查点全部重置。同版重复安装复查 system / gateway，切换模式重新准备 profile，后来补装 OpenClaw 可复用基础依赖与构建。
- doctor 按实际数据目录读取 API/原生底座选择，原生模式不再落入OpenClaw路由/认证分支；安装代码与用户数据分开时，不再误从源码目录读取并要求 OpenClaw。API独立数据目录故障回归在修复前误走OpenClaw；修复后同时覆盖API、Codex和OpenCode。初次两个扩展夹具误用了旧CLI接入ID，已改用现行底座ID，产品白名单未改变。
- Windows 网关启动器调用现有 Python 端口解析器，统一环境优先级、IPv6 和配置类型规则；不能解析时在操作服务前失败。此前 pwsh 会将 JSON 浮点 `19003.0` 当有效端口，后端拒绝该类型，两者可能错配。
- OpenAI、Anthropic、relay 及自定义渠道一致使用有效配置判据，示例占位 key 显示缺 key 且不给出假掩码；原始保存值、主模型 provider 身份和协议保持。
- 人工发布策略应用于补交短信验证码：即使原活动回执等待验证码，切换人工模式后仍拒绝回填，不写验证码文件。自动模式保留回执身份、状态和数字范围校验。

## 使用与升级边界

源码版本0.40.4。本批为兼容修复，不新增执行引擎、认证系统或界面说明块。此前聊天“补充”展开状态修复保留；本次没有再次修改其UI。

隔离或源码安装可使用 `powershell -NoProfile -ExecutionPolicy Bypass -File .\setup.ps1 -SkipOpenClaw -NonInteractive`；后续补装用原安装和数据目录，加 `-OpenClaw`。没有显式选择时，交互安装会询问，非交互默认保持原完整安装。源码构建和原系统依赖策略仍可能要求 Node/FFmpeg；本批没有承诺免 Node、自动安装原生 CLI 或迁移其登录态。

新增检查点模式元数据没有用户内容迁移；回退旧安装器可能重新核验安装阶段。回退前按既有流程备份 `.env`、安装状态及输出，保留用户数据。未自动部署138或发布安装器。源码提交、固定构建、HTTP/浏览器验收、真实模型质量成本与业务闭环分别记录；完整大版本目标和历史未完项继续。
