# aihub 推理能力声明修复（2026-10-12）

用户选择 `gpt-6.1-sol`，引擎 OpenClaw。实际便携版 aihub 渠道走 `openai-responses`，模型只含 id/name，没有 reasoning。OpenClaw 2026.9.6 把缺失值归一成 false，对该自定义渠道只提供 off；Easel 据此禁用强度。这是能力声明缺失，不能解释为 aihub 实测不支持。

## 修复内容

- 设置 → 对话与脚本 → 模型推理能力，可以对精确渠道模型保存支持、不支持或未声明。保存检查配置指纹并原子写入，不修改凭据、默认模型或其他模型。
- 快速添加渠道支持推理声明，切换模型时重置草稿声明。
- OpenClaw 导入保留来源明确声明的 reasoning、推理兼容字段和强度映射。Codex 来源保存非关闭的 model_reasoning_effort 时，仅为来源指定模型保留推理声明。
- 模型 ID 改变不继承旧模型能力；选择其他来源模型时不沿用原模型的声明。不会仅凭模型名或 Responses 协议启用推理。
- 输入框继续读取运行网关的 thinkingLevels，说明区分能力声明与调用实测。更高级别需来源明确声明且网关支持。

已给本机私用 Easel-fixed 当前 aihub 模型补 reasoning=true，原配置保存在该副本 data/backups。凭据及备份不进入 Git 或公共交付文件。

## Codex 与 OpenClaw 协作设想

Codex 本身可运行命令、修改文件和调用工具。可以让它负责规划，通过动态工具或 MCP 桥把某项操作交给 OpenClaw，再将执行结果交回 Codex 判断。

桥需要任务ID、结构化参数、操作权限、执行进度和结果。具有副作用的操作要去重，执行结果未知不能直接重试；OpenClaw 的确认请求要转回界面并继续相同任务。展示服务返回的推理摘要和工具活动，不保证能获得完整内部思考过程。

协作层尚未实现。原 Codex 接入保留 OpenClaw 默认、按会话选择引擎的计划，仍在独立分支验收；本次没有改成自动跨引擎回退。
