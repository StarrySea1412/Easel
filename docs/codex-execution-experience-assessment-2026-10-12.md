# Easel 与 Codex 的执行体验差距及实施规划

日期：2026-10-12。对应 R84，补充 [桌面与 Harness 评估](desktop-harness-assessment-2026-10-12.md)。本轮为调研和规划；不修改既有 Codex 接入计划，不实现新界面，不生成便携包或安装器。

## 结论

Easel 已经能显示部分思考、工具回执和文件差异，但尚未把它们组织成清楚、连续、可核验的执行过程。主要差距在执行事件接入、信息组织、进程状态与结果核验，不在是否拥有 Electron 窗口。

优先完善现有 React 工作台：用同一套执行视图展示 OpenClaw 和 Codex 的真实事件。聊天保留简短进度和关键操作，详情面板展示命令、输出、文件变化与产物；工作室使用同一数据来源。随后补齐实时更新、重启对账和浏览器操作。桌面框架选型继续按 R82 单独评估。

用户截图中的重复“思考 · 持续了若干秒”和截断长命令，说明耗时与原始命令不足以表达工作进展。本文不据此判定截图属于哪一个产品，也不把截图的耗时当作模型或应用性能基准。

- 原 Codex 接入工作区：只读检查 `codex/codex-runtime-integration-2026-10-10` 中的 `easel/codex_service.py`、`CodexRunPanel.tsx` 与类型。该工作区存在未提交实现，本轮不修改、合并或替它宣称验收完成；其接入计划保持原样。
- 随附 OpenClaw 2026.9.6：检查 `docs/concepts/agent-loop.md` 和实际 `dist/bash-tools.exec-runtime-DO1dSeBv.mjs`，确认公开工具事件、运行更新以及进程结果字段的来源。
- 真实独立无头 Chromium 打开源码 `http://127.0.0.1:7880/`，在独立浏览器存储中注入模拟会话并拦截执行快照响应。用于观察现有界面，不是真实工具调用；没有模型、付费服务、用户会话修改或产物创建。截图与 JSON 留在本地 Codex outputs，不提交仓库。

本轮没有同模型同任务的 Codex/Easel 成功率或速度实验，也没有验证 Codex 桌面内部的全部实现。官方协议支持某项事件，不等于任意模型或第三方渠道一定发送该事件。

## 当前实际差距

| 方面 | Codex 官方可核实能力 | Easel 当前证据 | 需要补齐 |
| --- | --- | --- | --- |
| 执行步骤 | `item/started`、`item/completed` 关联稳定 item ID | OpenClaw 聊天每 3 秒读取执行快照；Codex 接入工作区读取真实 item，但 UI 主要是折叠 JSON | 两引擎统一的操作卡、连续时间线与状态更新 |
| 思考与进度 | reasoning 摘要增量、分段边界；agentMessage 可有 commentary/final_answer 阶段 | 实际可见思考已接入且持久保留，但聊天将多个片段拼为大块文字；activity 是独立字符串 | 摘要分段，工作进度和思考分别展示，等待阶段不冒充思考 |
| 计划 | `turn/plan/updated` 有步骤与 pending/inProgress/completed | 本次聊天展示链未发现对应结构化计划视图 | 有真实计划事件时展示阶段和完成情况；模型写出的计划不自动成为执行证据 |
| 终端 | commandExecution 有 command、cwd、状态、输出、退出码、耗时及输出增量 | 命令作为标题；OpenClaw 执行类型只暴露有限字符串、回执状态和耗时，未保留 cwd/exitCode/process session | 操作摘要、独立命令/输出详情、进程结束与退出码、后台进程关联 |
| 文件操作 | fileChange 有 path、kind、diff；`turn/diff/updated` 聚合本轮变化；桌面审查可看文件/hunk | 部分工具返回 `details.diff` 时展示差异；普通 write 回执不会自动有 diff；diff 与 output 二选一 | 新增/修改/删除及实际回执；差异与输出同时可查；汇总变化、打开文件与反馈 |
| 搜索与阅读 | commandActions、webSearch 的 search/openPage/findInPage 能提供操作线索 | 聊天标题主要使用 command/path/name；工作室只保留工具名与回执 | 根据真实参数和事件展示查询、目标和结果；不为每条操作再请求模型解释 |
| 浏览器 | webSearch 可标识检索/打开网页/页内查找；这不证明 GUI 点击 | OpenClaw 随附浏览器能力已有资料，但聊天缺少一致的页面、截图、动作和下载展示 | 独立 browser.navigate/click/screenshot/download 操作类型，展示实际页面和下载回执 |
| 恢复 | thread/read 可读取持久会话，turn/interrupt 有明确终态 | 已有 SSE event ID、JSONL 续流、会话边界与结果落盘；工具详情仍另读 transcript | 结构化操作事件也进入持久日志；重启后与引擎对账，不能把网络续接当作进程恢复 |
| 交付 | 文件变更与执行可以独立于最终回答展示 | R81 已修复产物路径核验和实际保存；尚未与每项生成/下载操作统一关联 | 从工具→文件核验→预览/下载关联同一产物 ID，保留来源和失败原因 |

### 已有能力需要保留

`web/chat_execution.py` 已按工具调用 ID 匹配结果、限制本轮边界、隐藏凭据，并明确使用“已返回”而不是“成功”。`session_trace.py` 与工作室读取器已有 SQLite/JSONL 轮次校验；备份记录明确不冒充当前本机执行。R81 也已有真实保存和缺失链接提示。这些是可复用基础，不应为新的视觉设计删掉。

### 具体导致看不清的地方

1. `ChatExecutionPanel.tsx:16` 流式期间每 3 秒轮询；`:29` 默认只显示最近 3 项，`:30` 标题直接取命令、路径或工具名。`chat-execution.css:1` 标题区域仅 10px，`:6` 强制单行省略。模拟浏览器中 872 字符命令的内容宽度约 4,789px，标题可用约 721px；展开能看到完整模拟命令，省略问题发生在第一层展示。
2. `web/chat_execution.py:49` 命令最多 1,200 字符、路径 500；输出默认 4,000，diff 12,000，最终只返回最近 40 项（`:82`）。它们是合理的保护上限，但响应没有提供完整详情分页、被截断长度或明确省略回执。“查看全部”目前只展开这次快照，不等于完整历史。后续不能简单移除限额，应该增加有界分页与脱敏详情。
3. `ChatExecutionPanel.tsx:34` 有 diff 时不再显示 output。真实 Chromium 的模拟写入回执可展开，模拟修改差异可展开，但差异旁没有原工具输出。文件修改需要分别查看变更和工具回执。
4. `web/chat_execution.py:59` 主要按 `isError` 区分 failed/returned，没有解释进程状态、exitCode、cwd 或后台 session。OpenClaw 运行实现可上报 `details.status=running`、sessionId、pid、cwd；进程正常退出也可能携带非零 exitCode。因此工具返回、进程退出和任务验收必须分开。
5. `easel/gateway_agent.py:46` 的本地事件回调当前主要处理 compaction；`web/app.py:3834` 的 raw handler 主要提取正文/思考。随附 Agent loop 文档明确有 `stream: tool`。这是接入工具增量的候选来源，需验证当前网关版本、事件归属及权限后启用，不能宣称本机已经接通实时终端。
6. Codex 工作区 `_consume` 已累计 `item/commandExecution/outputDelta`、item 生命周期和 turn diff；展示仍以每 1.5 秒取快照、打印 item JSON 为主。这说明可以复用接入工作，但展示层还需要专门设计。
7. 当前 heartbeat 文案“仍在处理中，未卡住”超过了心跳能证明的范围。连接仍存活不证明模型或子进程一定正常进展。规划改为“连接保持中 · 暂无新进度”，另列最后真实事件时间与当前已知阶段。

## 建议的交互

### 第一层：聊天里的工作进度

默认展示一条当前工作状态、重要完成项和失败项，避免每个 token 或每次轮询新增一行。结束后保留本轮摘要与“查看过程”；用户主动展开的卡片在更新时不自动关闭。

示例只表达目标形态，不代表本轮实际发生了这些操作：

```text
正在检查文件保存逻辑 · 本轮已用 1分20秒
  已读取   保存脚本                     0.3秒
  已修改   artifact_store.py            +12 −4
  执行中   验证下载路径                   18秒   [查看输出]
  待核验   生成的 Word 文件
```

摘要来源优先级：引擎结构化动作→工具名称及参数→原始命令。Agent 显式说明的意图可以展示，但与实际回执分开。不能只因为看到 `echo`、某个文件名或一段自然语言就声称完成了检查。

### 思考：展示可见摘要，不能承诺完整内部推理

- 有真实 reasoning 事件时显示“思考摘要”，按 item/段落关联工具前后的片段；用户可查看全部服务返回的可见文字。
- 没有可见摘要时显示当前真实活动，或“等待模型响应”。不把整个请求耗时写成“思考 98 秒”，不合成虚构的思考进度。
- Agent 工作说明、阶段计划、连接状态与思考分开；请求的“自适应最高”是强度选择，不是已获得思考内容的证据。
- 本轮总耗时保留；各步骤有开始/结束时间才展示步骤耗时。没有显式阶段边界时不给思考单独估时；并行操作的耗时不能相加当作总耗时。

### 终端：看到命令，也看到它的结果

紧凑标题显示动作与目标，例如“检查输出目录”或“运行命令 · python”；未知语义用工具名，不伪造中文目的。展开后分为命令、工作目录、输出和状态，提供复制命令/输出与跟随输出开关。

- 有增量时追加脱敏输出，支持批量更新和长日志虚拟化，保留滚动位置；输出有界，截断明确显示，并能分页读取仍保留的内容。
- 命令 stdout/stderr 是否能区分取决于真实字段；来源混合时显示“合并输出”，不假分栏。
- 展示进程退出码、信号或未确认。工具响应携带后台 session 时关联后续 process 回执；“工具已返回”不终结后台进程。
- 请求停止显示“正在停止”，收到引擎确认才显示“已停止”。单个命令停止入口只在引擎确实支持且归属已验证时出现；不能将关闭 SSE 当作停止。
- 第一阶段无实时来源的 OpenClaw 操作仍可用轮询快照，但标明“回执更新”，不能把最后结果分字播放当作实时终端。

### 文件：明确读、写、改、删和交付

- 阅读卡：目标、查询/范围、真实返回的内容或错误。工具只返回文本时不编造结果数量。
- 代码/文本变更卡：新增/修改/删除、路径、真实 diff、修改统计和实际状态。拟议修改与已应用修改分别显示；“写入请求”不是“文件已保存”。
- 文档、图片、视频：优先预览/元数据和内容校验，不对二进制文件强行展示文本 diff。
- 文件差异和工具输出可同时查看。未收到 diff 时显示写入回执或“无差异回执”，不从模型参数生成一个成功 diff。
- 修改完成后按具体文件核验存在、非空和适用格式，关联 R81 内容库/下载链接。路径展示、实际数据目录和打开目标保持一致。
- 未来的回退/接受动作必须保护用户后续编辑，按变更版本校验；不在第一阶段用覆盖当前文件来模拟 Codex 的 Git 审查。

### 详情面板：过程、文件、产物、页面

复用现有布局，选择一项操作就能查看详情；窄屏使用抽屉。建议详情分为“过程”“文件变化”“产物”“页面”。聊天保留上下文，工作室成员点击进入同一 operationId，而不是另造一份日志。

首阶段先完成过程与文件详情；浏览器阶段再展示实际 URL、截图时间、动作结果和已保存下载。网页搜索、HTTP 抓取和 GUI 浏览器操作必须有不同标识，避免把检索事件说成打开并操作过浏览器。

## 数据与恢复规划

沿用现有引擎接入方式，新增外层事件规范；不重写 Codex 接入计划，也不要求全部引擎提供相同字段。

| 字段组 | 最少需要的内容 |
| --- | --- |
| 身份 | sessionId、turnId、engine、engineRunId、operationId；子 Agent 有 agentId/parentId |
| 顺序 | 持久 event ID、事件版本、增量顺序；并发操作独立 ID，不以时间字符串排序替代序列 |
| 生命周期 | started/update/completed；operation 状态和 turn 状态分别保存；失败、停止、拒绝、等待输入、未确认明确区分 |
| 类型与摘要 | reasoning/progress/search/read/command/file_change/browser/artifact；摘要标注来自 Agent 说明还是工具事实 |
| 工具证据 | 命令/参数、cwd、可见输出、退出码/信号、真实时间与截断情况；未知字段保持空 |
| 文件与产物 | path、changeKind、diff、artifactId、实际保存及格式核验回执；包含证据来源和版本 |

事件先脱敏并持久保存，再交给 SSE/前端。新的操作事件复用当前 event ID 续流机制，增量去重，结束 item/snapshot 覆盖权威终态；刷新和页面切换后依据持久记录恢复，不重复工具调用。

当前 `_read_job_events` 逐次读取完整 JSONL 是未来长记录的优化候选。结构化日志增长后应有索引、分页、体积和保留策略；没有保留的输出明确不可恢复，不将“加载更多”指向已丢弃数据。

进程重启时先向引擎查询原 run/turn 是否仍在运行，再对账快照。查不到终态则显示“完成状态未确认”，不能自动重发写入、下载、付费生成或发布；网络重连只恢复订阅。审批/用户输入复用引擎原请求 ID 与现有权限，不能为了展示授予更高权限。

Codex 映射使用实际 item 生命周期、reasoning summary、command output 和 turn diff；官方已弃用 `item/fileChange/outputDelta`，不将其作为新文件展示的数据来源。OpenClaw 先验证 tool stream，再用会话记录补全最终回执。事件缺失时保持“未上报/未确认”，不得补写成功。

## 实施顺序与验收

| 阶段 | 范围 | 完成判据 |
| --- | --- | --- |
| P0：现有信息先可读 | 统一操作卡和状态词；提升可读字号；短摘要与完整命令分离；diff/输出均可查；文件与产物关联；保留现有轮询 | 两引擎受控记录都能看清读写/命令/错误；不出现原始 JSON 作为主要用户界面；明确哪些是快照 |
| P1：真实过程持续更新 | OpenClaw tool stream 与 Codex item/delta 映射；稳定 ID；后台进程、退出码、步骤计时和真实停止确认；持久化去重 | 真实受控进程 stdout、非零退出、后台执行、停止均正确；刷新续流无重复；未知仍未知 |
| P2：审查与恢复 | 本轮文件汇总、文本 diff、格式校验、长记录分页、重启对账、失败定位与重试边界 | 60+ 操作可分页查看；超过旧限额明确完整/截断；重启不重复有副作用操作；变更关联正确轮次 |
| P3：浏览器与桌面协同 | 实际页面/截图/动作/下载展示；工作室/聊天/详情联动；桌面原型按 R82 推进 | 浏览器操作、检索和抓取区分；下载实际落到持久目录；成员入口跳转同一操作；桌面验证单独计 |

建议受控验收集：读文件/搜索、创建文本、修改文本、多文件变更、普通命令、exit 1、慢命令输出、后台进程、取消、并发操作、断网续流、后台重启、缺失/无效文件、超过限额记录、无思考摘要、未知工具类型、浏览器操作和下载。

其中进程、文件和本地 HTTP 场景可使用临时目录及本地服务真实验证；UI/协议场景使用明确标记的模拟记录；模型端到端和外部网站另列真实验收，不用模拟通过代替。实施阶段再设计必要回归，本次纯文档调研不重跑全量前后端测试。

候选质量指标：受控环境中事件持久化到画面更新 p95 ≤ 1秒；同一事件重放不增加操作；失败/停止状态与真实回执一致；390px、键盘与减少动态效果可用。指标是实施目标，本轮没有测得此 p95，也没有承诺特定开发天数。

## 本轮检查结果与剩余事项

- 官方页面实际获取成功，关键协议与审查功能已核实；OpenClaw 随附版本/工具运行更新有本地代码依据。
- 实际 Chromium + 模拟数据：默认显示最近 3 项、展开全部 4 项、长命令标题省略/详情可读、写入回执、diff、390px 无页面横向溢出已检查；无浏览器错误和非 GET/HEAD 请求。模拟例子的退出、文件创建和修改均未真正执行，不能用于业务成功证明。
- 本轮只交付评估与优先级，未实现上述 P0–P3；实际模型、实时工具链、停止、重启、浏览器执行、文件审查新 UI 和轻量桌面均待实施验收。新打包继续等待用户指令。
