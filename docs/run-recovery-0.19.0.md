# Easel 0.19.0 候选：运行恢复与停止确认

更新：2026-10-26。基于79c8210b，继续完整大版本P0-R；不部署138、不发布安装器、不调用付费模型。

## 行为与证据边界

重连仍按原turn读取正文事件；如果当前Web进程没有supervisor，先核对持久身份。其他Web进程仍持有会话OS锁时继续读取它的日志，不将“本进程没记录”判为后台结束，也不重发模型请求。没有活跃归属时，原生网关仅调用精确runId的`agent.wait`核对终态；只有用户显式停止才调用`chat.abort`。

后台已结束不证明完整回复已送达。原有完整成功快照可以保留；只有部分token/替换快照时，保留收到的正文和思考摘要，以中断失败结束，不因为网关返回ok就编造完整成功。回放末尾损坏或缺换行时，保留原字节并单独补终态；重复核对不重复追加结束事件。

普通聊天回复终态与资源结算分开。`resourceFacts.provider/browser`保存正向事实；后台与浏览器操作清理都成功、最终回放和快照可写后才释放对应聊天占位。浏览器清理失败保留占位和provider已结束事实，之后只重试清理，不必再次停止模型。独立生图任务仍由任务服务另行检查，聊天resourceSettled不替代图片资源结算。

普通聊天占位不再因本地7200秒到期就自动消失：时间流逝不证明外部运行结束。重复请求同一turn也不能取得并释放原请求的占位。新消息准入前可核对原占位，确认结束才释放；不支持或无法确认时仍冲突返回，不自动重发。该调整可能令旧遗留且无法核对的占位持续保留，应保留历史并使用新会话，不强行清空运行事实。

任务服务对失联轮次限速核对原运行，再从账本结算；最多每次tick检查一个外部运行，每轮间隔至少15秒。不会因恢复而再次派发，暂停/取消/版本变更不会被晚到结果重新启动。已核对为失败的失联目标显示run_failed，保留真实原因，不降为空闲。

## 接口与兼容

- 新增`POST /api/chat/runs/{turnId}/reconcile?sessionId=...`，校验账本会话归属，返回核对状态和是否已结算，禁止缓存；核对网关只读，但会保存已确认事实并完成本地清理。
- 已有SSE重连入口自动复用核对；仍在其他进程执行时继续回放，清理失败发送已有recovery_required事件，复用原停止/重试交互，不新增常驻说明块或嵌套卡片。
- 显式停止复用同一收尾路径；单独的旧done标记或settled=true不能证明resourceSettled，必须有对应运行/资源证据。账本provider身份优先于旧最近轮次标记，晚到结果不覆盖另一轮标记。
- 沿用0.18.0 SQLite schema 1，资源事实是可选快照字段，不新建全量事件系统。历史已经声明resourceSettled的账本仍保留原事实，本版不回溯证明所有旧清理结果。

只覆盖普通OpenClaw流式聊天与其目标调度。HTTP兼容传输已明确[DONE]的运行可结算；HTTP连接断开、无精确原生身份或不支持核对的传输不能借原生RPC冒充确认。Codex原生订阅接管、旧非流式路径、原标记已被另一轮替换后的完整跨轮修复、全部外部资源统一所有权及全系统回滚尚未完成。

## 升级与回退

沿用0.18.0停写、全数据目录备份、隔离副本升级/回退流程。普通聊天占位更严格，升级前应结束并核对在途运行；旧版会按时间忽略占位，也不知道新的资源确认语义，不能混跑或直接用回退证明资源已停止。SQLite在线备份只包含账本，不替代正文日志、任务数据库、文件及认证配置的完整备份。
