# 工作进度重新设计（2026-10-16）

## 用户问题

用户指出聊天中的“已收到，正在唤醒 agent…”和“正在思考…”过于像占位动画，无法判断后台实际做了什么。本轮目标是让工作进度只表达可观察的服务事件，并把未知状态明确留白。

## 交互与事件边界

- 后端首条事件改为“请求已接收，等待运行器确认”，表示请求已进入本轮事件流，不宣称 Agent 已被唤醒。
- 进入运行器后显示“已进入运行器，等待模型事件”；模型事件由服务实际返回后才加入时间线。
- 工具/模型往返和 Agent 协作各自形成有序事件，不再只保留最后一条活动文字。
- 心跳单独显示为连接提示，并标注“不代表新的工作步骤”，不会覆盖真实活动。
- 思考摘要独立于工作进度；没有服务事件时显示“等待首个服务事件”，不伪造“正在思考”。
- 历史消息使用可展开时间线，区分服务事件、备份记录、进行中、已完成、失败和已停止；备份文字继续标注“未经本机后台核验”。
- 断线恢复把“连接中断，正在续接”等状态加入时间线；恢复不会自动重发模型请求。

## 实现范围

- `web/app.py`：替换拟人化活动占位文案，保留服务实际可观察事件。
- `web/frontend/src/lib/store.ts`、`App.tsx`、`ChatPage.tsx`：保存并传递有序 `activitySteps`，隔离心跳和重连状态。
- `MessageBubble.tsx` 及样式：增加工作进度时间线、来源标识、终态和窄屏布局。
- `message-bubble.test.mjs`：覆盖事件顺序、心跳隔离、失败/停止终态。

## 已知边界

本轮展示的是服务已经上报的事件，不等同于模型内部思考可见性，也不承诺每个模型或网关都会提供更细粒度事件。缺少后台事件时页面会明确显示未知状态，而不是估算步骤或速度。
