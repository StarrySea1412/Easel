## 1. 推荐落点与基线

推荐沿用 OpenClaw、现有用量账本、画像和分析辅助面板，补成“度量 → 有证据的候选经验 → 用户确认 → 按范围读取 → 可复盘失效”的闭环。不引入 DeepInfer 推理集群，也不整套接入 Mem0、Zep 或图数据库。

本次对照的是 `codex/upstream-merge-0.8.0` 的 `08527edd`，业务源码基线 `5b6e8177` / 0.11.2；本机主目录在另一旧分支，两份需求清单的历史不同，只同步本轮新增内容，不整文件互相覆盖。138版本仅引用[上一轮发布回执](https://github.com/StarrySea1412/Easel/blob/codex/upstream-merge-0.8.0/docs/release-138-0.11.2-2026-10-21.md)，本轮未重新检查线上实例。

复用现有入口，不新增导航，也不把诊断文字堆到聊天输入区。

## 3. 第一阶段：可观测性与提示词边界（P0）

### 3.1 缓存指标

在现有 `summarize()` 返回中新增可选 `cacheReuse`，原统计字段不改语义。建议字段：

| 字段 | 含义 |
| --- | --- |
| `ratio` | 有效样本 `sum(cacheReadTokens) / sum(inputTokens)`，0到1；无有效分母为 null |
| `eligibleRecords` / `totalRecords` | 两字段均上报且计数一致、输入大于零的记录数 / 本组全部记录数 |
| `inputTokens` / `readTokens` | 只在这组有效样本内求和，避免字段覆盖范围不一致 |
| `missingRecords` / `invalidRecords` / `zeroInputRecords` | 分开统计缺字段、计数矛盾、合法零输入 |
| `unit` | 继承当前 `recordUnit`，Codex累计事件不能冒称供应商请求数 |

归一化后输入应含缓存：Pi/Anthropic 的普通输入需加缓存，OpenAI 的含缓存输入不能再加。缓存读必须是非负整数且不大于输入；缓存写已知时还检查读写和不大于输入；写未知不能擅自补0，也不妨碍在输入/读口径确实已知时计算读取占比。计数矛盾不修凑成合理数字；另计异常。

聚合始终从原始有效记录求和，不能平均各渠道、模型或各天的百分比。100/100与0/900两条记录合计应为10%，不是50%。不从占比推算账单节省金额或承诺性能，不把无上报当0%；总览显示部分覆盖时，标签应明确是“已上报样本”。

复用 `/api/usage` 和原账本读取；只做增量字段，不读取对话正文或新增真实推理探测。当前解析器的缺字段兼容也要覆盖，不能假设所有 OpenAI-compatible 渠道完全遵守同一口径。

### 3.2 消息组装与可信度

把 `_chat_message` 的输入先拆为可信策略、用户原文、引用材料、本轮运行差异四类。优先落内部组装接口，不先删除全部提醒。

- **可信策略**：产品固有文件交付、安全与技能使用规则；带稳定版本。共享源仍在 `agents/workspace/`，不能只改同步后的 `openclaw/workspace/`。
- **用户原文**：存储、展示和复制保持原样。现有 `test_persona_turn_message.py` 明确验证原文保留；不能为消除同名标记直接改掉用户输入。
- **引用材料**：网页、附件、历史快照、分析材料、经验正文均是有来源的数据；隔离序列化、处理定界符闭合，不将其中的“系统/内部”字样提升角色。
- **本轮差异**：当前画像、会话附件清单、浏览器页、已选Skill、数据目录和运行模式；只带当前范围，不能把这些塞进全局可变系统文件。

按传输能力分别接入：OpenClaw 先验证当前 HTTP/Agent 接口是否支持独立策略通道；没有证据就保留兼容路径并注明限制，不能假定与 Codex 的 developerInstructions 等价。`easel/codex_service.py` 有 developerInstructions 实现，但本轮不因研究建议启用未接线的 harness/direct_api 子系统。

**验收强度**：结构化输入可保证应用不把引用解析成策略，不能保证模型永不受诱导；真正的文件归属、发布授权、指定模型与写入权限仍在服务端和运行环境执行。使用合成样本覆盖同名控制块、闭合标记、网页越权写记忆、附件伪造系统消息；不把“模型没照做一次”当安全证明。

## 4. 第二阶段：统一经验服务与跨页状态（P1）

### 4.1 范围与优先关系

- 画像是跨平台人设；偏好与红线继续在 `preferences.md`，不迁移成一堆自动推断的“永久事实”。用户可随时改正。
- 服务为旧画像目录建立稳定 `profileId` 映射，显示名/目录名不作为永久身份；首次建立映射不自动合并同名或相似画像。路径仍逐次校验数据根目录、真实路径与软链接，不能只检查字符串中的斜杠。
- 经验条目必须有 `profileId`；账号效果经验还必须有 `platform + accountId`。昵称仅用于展示，不能充当作用域主键。
- 跨平台适用只在用户确认时明确选择，不因画像同名自动把A账号经验用于B账号。
- 当前用户要求优先于旧经验，经验不能覆盖用户明确修正；与已确认偏好冲突的候选保留待处理，不自动替换偏好。
- 未登录/重新核验的账号不会因此删除记忆或分析缓存；登录状态仍来自账号服务，记忆不能反向证明已登录。

### 4.2 最小数据契约（拟新增）

建议新建 `easel/profile_memory.py`，用项目已有 SQLite 能力实现，不增加独立数据库服务。候选、正式条目与修订放同一事务体系。

| 内容 | 建议字段 |
| --- | --- |
| 身份与正文 | `id`、`profileId`、`kind=experience`、`text`、`revision`、`contentHash` |
| 范围 | `platform`、`accountId`、`taskTypes`、适用条件；跨平台明确声明，不把 null 当任意通配 |
| 时间 | `createdAt`、`updatedAt`、`observedFrom/To`、`reviewAfter`；缺失为 null；复查日期不是自动过期删除 |
| 证据 | `sourceType`、`sourceSessionId/turnId`、`analysisBindingId`、`contentIds`、`receiptId`、`sourceHash`、`capturedAt`；按类型选择必填项 |
| 结论质量 | 事实/假设标签、样本量、观察窗口、局限；不编造置信度分数 |
| 状态 | 候选 `pending/accepted/rejected`；正式 `active/invalidated/superseded`；独立来源可用性与复查标记 |
| 审计 | 确认时间、确认操作标识、旧版本、替代条目；只保存必要信息，禁止密钥、Cookie、网页整篇原文进审计 |

推荐唯一事实源为 `<data_root>/memory/profile-memory.sqlite3`；`data_root` 使用 `easel.paths.data_root()`，不写只读 `/app` 或安装版本目录。`memory.md` 在用户确认导入后变为给旧Skill读取的兼容投影，不再作为可与数据库双向自由覆盖的另一份主库。候选不写入投影，失效经验不出现在有效投影中。

数据库提交后记录待投影版本，以临时文件原子替换 `memory.md`；投影失败保留旧文件并可重建，不能回报全部成功。读取按库版本重试修复，向旧Skill交付前校验投影版本；无法修复则不用过期投影。不得让断电产生“页面已失效、Agent还在读取有效经验”的静默分叉。

### 4.3 写入与确认

建议增加列举、提出候选、确认、修订/失效、读取上下文五类服务操作；Web、CLI、Skill 使用同一个实现，不各存一份。HTTP路径可在实现时确定，建议挂在 `/api/persona/{name}/memory/...` 下。

模型可提出候选，不能自签用户确认。确认必须绑定候选ID、正文哈希、画像/账号范围与当前版本，由现有受保护用户操作通道发起；来源ID和哈希由服务端按当前材料重算，不信任模型自填。API沿用现有认证、同源与写入保护，不能提供裸露的无需鉴权确认接口。

相同范围+正文+证据哈希的重复候选/确认幂等；候选变更后旧确认失效。并发编辑按 revision 冲突拒绝覆盖并保留草稿；拒绝不能被晚到任务复活。旧的画像整文件PUT在接入后必须将 memory.md 导流到同一服务，不能成为绕过版本与确认的旁路；其他维度兼容原接口。

写入/读取入口必须一并审计，避免只改网页：

| 入口 | 必须同步的行为 |
| --- | --- |
| Web画像文件API、`_write_baseline_profile`、`/api/profile/build` | 新建与已有画像完善不能覆盖受管经验；整文件编辑经过版本与差异确认 |
| `easel/persona.py:load_profile_text`、`easel/cli.py`、`easel/commands/skill.py` | 区分给用户导出的完整资料与给模型的预算内有效经验，不能继续不加区分拼接所有Markdown |
| skill-profile-manager、skill-profile-builder、skill-brand-onboarding | 创建/完善/记忆更新均使用同一服务；不能复制模板或直接exec写入绕开受管条目 |
| 分析对话、辅助面板、发布/归因后的候选 | 保持原会话与账号绑定，证据更新/来源删除有明确分支，不自动回灌为有效经验 |
| `agents/workspace`与OpenClaw同步、已启用的其他执行入口 | 同源规则、作用域和读取策略；不额外启用尚未接线的新子系统 |

**实施前必须解决的边界**：当前Agent可直接通过文件工具或exec写画像。单加API、确认字段或拦截write工具不足以形成强约束。受管数据库/投影需要受限写权限及不向Agent暴露的确认通道；逐一核对本机、容器、OpenClaw与其他已启用执行入口。若同一OS身份的任意exec仍可改库/文件，第一版只能声称有服务端确认流程，不能宣称已彻底防绕写。禁止用可被Agent复刻的字符串当审批凭证。

### 4.4 旧资料迁移

1. 首次打开只读识别旧memory.md，计算哈希，按旧模式可查看，不静默覆盖或批量调用模型。
2. 展示导入预览：保留旧文字为 legacy 条目；来源/日期未知则为null，不把文件mtime当事实日期，也不把导入时间冒充发现时间。已有明确日期与来源标签仅提取为待核实字段。
3. 用户确认后，在数据目录保存原文快照和哈希，事务导入为带 `legacy/unverified` 标记的经验；按范围与哈希幂等，支持中断重试。旧经验不自动升级为偏好、不自动标成“已验证有效”。
4. 导入前仍可沿用旧流程，但不能标为新服务已托管。导入后外部文件变动只进入待对照变更，不能自动覆盖库或回灌成有效记忆；检测不一致时阻止使用新旧混合视图。
5. 回滚时恢复迁移前原文及旧程序，数据库与历史保留备份；上线前独立演练，不把新投影直接留给不了解元数据的旧程序。

来源对话删除不自动抹除用户已确认的经验，但应显示“原对话已删除”，禁止跳到其他会话；材料更改标需复核，原快照引用不偷偷更新。涉及删除用户资料/敏感信息的明确操作须清理条目、投影、检索缓存和可访问的证据副本，不能以“保留审计”为由永久保留正文。

### 4.5 共享状态与事件

扩展 `workbenchEvents.ts` 的领域事件，例如 `domain: profile-memory`，带 `profileId/platform/accountId/revision/reason`，不带正文或密钥。保存成功后统一发布，画像页、辅助面板和上下文资料消费同一事件。

- 真相源在后端，事件只负责使缓存失效。缓存key必须含画像/平台/账号，不能只用页名。
- 页面重挂、窗口重新获得焦点或漏掉事件后按后端revision补读；纯window事件不会跨标签页/客户端，跨标签页可用BroadcastChannel通知失效，远端客户端仍靠版本回读或现有服务端事件通道。
- 请求与任务放共享服务，不跟组件卸载取消业务执行；同范围读取去重。切页后保留缓存，loading只覆盖更新部位；新旧账号请求用范围与请求代号校验，晚到结果不能覆盖当前账号。
- 删除/拒绝/失效发布明确版本与删除标记；旧后台任务提交前再校验，避免通知清掉后又被晚到事件恢复。
- 对话构建记录本轮实际使用的条目ID/revision，切换画像只影响后续轮次，不改已保存对话或已开始任务的绑定。

## 5. 第三阶段：经验按需读取、证据回填与评估（P2）

### 5.1 读取与提示词整理

先过滤画像、平台账号和active状态，再按任务类型/关键词取少量相关经验；预算由现有上下文预算模块统一裁剪，不先上embedding。经验不相关时不读，通用模式不借用任何画像。候选/失效/被替代条目不得注入；材料变化待复核的条目不能作为已验证效果使用。

`preferences.md` 的已确认规则保持可用，经验作为参考数据；不得把“过去某次有效”升级成“以后必须这样”。同步修改共享AGENTS、画像管理Skill、模板、后端与实际已启用执行入口，不能只改一处说明。

稳定提示词前移采用独立开关与策略版本。先测消息重复量，再按引擎支持提升稳定规则，保留短尾提醒用于长对话规则回想。长对话、压缩恢复、不同画像并发、文件交付与权限规则都通过后才启用；不为了追求缓存占比削弱规则或改变用户授权。

### 5.2 分析 → 候选 → 画像

复用 `AnalysisConversations` 的账号/作品/材料哈希和过期校验。模型回填内容分析仍是原有流程；生成记忆候选是另一受控动作，不把报告整篇塞进长期记忆。

效果经验至少附作品ID、指标口径、观察窗口、样本量与局限。`published`只生成发布事实；submitted/draft/unverified/failed不能冒充发布成功。没有可比数据时只保存用户确认的假设，界面不造增长结论。发布流程、人设评分、真实业务结果分别记载。

辅助面板支持查看原材料、提取选中结论、加入画像；接回对话只是增加引用，不自动发消息或重新调用模型。用户明确要求记住的偏好可以走明确保存操作，不强制再点一次同义确认；自动提案则需用户确认。

### 5.3 复盘与效果验证

复盘放在画像经验页，不给每次任务弹窗。展示待复查/来源缺失/冲突条目，用户选择继续保留、修订、失效或删除；不用使用次数或点击率自动淘汰红线。

离线评估先覆盖双画像双账号、偏好冲突、旧经验失效、材料更新、罕见红线、外部注入与缺来源。之后在同模型、任务和材料条件下比较不开经验/有经验的改稿轮次、是否遵守偏好、输入用量与可核验成本；发布时间、流量和用户选择会影响发布效果，不能把相关性宣称因果。真实模型评估需另记成本与授权，方案本身不触发调用。
