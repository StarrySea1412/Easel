## 本批实现

- `/goal` 模式增加“直接推进 / 分工协作”，复用共享选择控件；新建协作目标默认 8 轮、20 分钟、40 次工具，实际执行仍受已有保护器准入。
- 内置顺序流程：研究依据 → 制作结果 → 独立审查 → 整理交付。每阶段是真实独立逻辑轮次，角色契约通过服务端注册表进入请求，角色快照、轮次及核验结果写入原有 SQLite 任务账本。
- 每个目标使用独立的 `workflows/<goalId>/` 交接路径。阶段文件必须产生新版本，并通过现有文件及依赖核验；只说“已完成”或复用原文件不足以交接。文件核验只证明文件状态，不能替代事实、创意或业务质量判断。
- 下一阶段读取前序真实文件和带来源的交接数据；交接文本按数据标记，不授予指令权限。角色不改变运行权限、模型配置、预算或发布授权。
- 上游文件变化、缺失或依赖无法核验时阻止后续派发；最终验收会重新核对交接证据。已完成目标的证据变化也会撤回完成状态并保留历史。
- 阶段切换仅发生在已成功结束且资源已结算的轮次。停止代次和修订号继续阻挡晚到结果；进程失联保留 unconfirmed，不自动重发。
- 前端任务面板展示角色、阶段、交接文件、执行次数与核验记录；未核验文件不显示为可交付。完整流程后进入原有最终质量验收，而非自动宣布项目完成。
- Linux 浏览器桥接在 shell quoting 边界先把 Path 转为字符串，保留 0.14.2 已有的下载/鉴权规则。此前首个聊天请求 500 导致任务未建立，随后恢复 404 不能单独当作根因。

当前是同一个受保护目标内的**顺序角色执行**，不是并发多 Agent 调度。没有开放目标执行中的 `sessions_spawn`，也没有让“审查报告文件存在”等同“审查已通过”。

## 部署边界与回滚

该候选只交付源码与验证记录，不自动替换138。部署前需固定远端 SHA，备份并停写原任务 SQLite/产物/账号配置，以隔离环境核对登录、版本、构建 SHA、原有下载与导航，以及目标创建、阶段交接、停止、恢复和验收。未通过这些检查不能切换正式服务。

任务数据库不删除旧表，新增信息保存在已有 JSON 记录中；旧目标没有 `stages` 时沿用原有直接推进。回滚程序前先停止候选目标并确认外部资源结算，恢复配套备份；旧程序无法理解新的阶段契约，不能直接继续候选版本创建的协作目标。
