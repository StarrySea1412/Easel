# Easel 0.17.0 候选：持久会话删除

更新：2026-10-26。基于 `bc8c7bec` 继续完整大版本迭代；本批不部署138、不发布安装器、不调用付费模型。

## 用户可见行为

删除在线对话时，先由服务端保存删除事实，再移除本机对话。服务端失败时保留对话与草稿，允许重试；任务对话也可删除。删除会取消非终态目标、停用绑定该会话的计划，并尝试停止已知轮次。外部资源未结算时明确显示“后台停止待确认”，不以删除成功代替停止成功。

任务历史、迟到执行回执与已有文件仍保留；任务工作区展示“原对话已删除”，不提供失效的返回/继续/验收操作。只读备份的删除仅影响本机备份，不改在线身份。沿用0.16.0收平的聊天侧栏与紧凑目标菜单，不新增常驻说明区。

## 实现与边界

- SQLite `deleted_sessions` 保存会话ID、时间、事件修订号和待清理通知标记。删除事实、目标取消、排队轮次停止及绑定计划停用在同一事务中提交；重复删除返回同一标记。
- 会话读取在同一事务中排除删除记录并返回标记。前端跨页共用的快照按修订号单调合并标记；较旧响应或浏览器存储写入失败均不能重新加入已确认删除的在线会话。
- 新建目标、普通聊天准入、计划启用/触发、最终验收和工具/图片准入检查删除状态。Codex发送前及当前轮控制检查同一事实；删除时读取Codex持久轮次，覆盖普通聊天占用已释放后的运行/未确认轮次。
- 目标的迟到结果仍写历史，不将已取消目标重新激活。通知清理有持久待办，失败后由下一次tick或重启重试。
- 停止只覆盖已知轮次的有界请求；通知待办不是完整的外部资源停止重试队列。跨进程或失联资源仍需实际核验，不保证所有外部动作已经撤销。
- 只对本版服务端删除操作建立统一事实；没有把所有历史浏览器本地删除记录自动迁入服务端。没有物理清除全部历史、回收站恢复、全局隐私擦除或完整经验召回功能。

## 升级与回退说明

新增表由现有 `CREATE TABLE IF NOT EXISTS` 初始化，不改变旧表内容；当前没有完整的schemaVersion迁移/回滚框架。切换前先停写并备份整个数据目录（含任务/通知SQLite、会话、文件及认证配置），在独立副本验证再更新服务；本批未执行138切换。

旧0.16.0会忽略新删除表，直接降级可能再次补读已删除会话。不能将直接运行旧代码视为保留删除语义的安全回退；需要停写、保留新版本数据快照并专门核对删除标记兼容。恢复升级前备份会失去其后的删除与其他修改，不应静默恢复或自动清空标记。
