# Windows 交付验证记录（2026-09-30）

本轮版本 **0.2.5**，交付形态是 **图形安装器 + 网页工作台**。验证环境为 Windows 10 专业版 10.0.19045 x64 开发机的隔离目录，不是干净虚拟机。未执行 Git push 或公开发布。

## 用户入口

- `Easel-0.2.5-Windows-GUI.zip`：完整解压后双击其中的 `Easel-Setup-0.2.5.exe`。
- EXE 默认打开图形安装向导，选择位置、查看进度、失败重试，成功后点击“打开工作台”。
- 日常启动：安装目录的 `打开 Easel.vbs` → pythonw 图形启动窗口 → 浏览器工作台；错误和重试在图形窗口内处理。
- 设置保存位置后，再运行图形启动器并确认“重启并迁移”。取消确认只复用已有工作台；关闭浏览器不会自动停止后台。
- `Easel-0.2.5-windows.zip` 为源码载荷，保留命令行排错入口，普通用户使用上面的 GUI ZIP。
- 首次需联网下载依赖；不是完全离线包。测试版未签名、不注册系统卸载项，移除和恢复方法见 [使用说明](../WINDOWS-START-HERE.md)。

## 0.2.3 实装发现的退出缺陷（0.2.5 实装已证实修复）

最终原始 0.2.3 EXE 首次健康检查失败；直接与默认 HTTP 探测随后均返回 200，未证实代理故障。同一 EXE 原目录重试后 8/8 阶段完成，Web / 重复启动 / 参考图上传回读 / 实际内容迁移及备份哈希通过。但两个外层 EXE 停留在 Warning，临时目录仅剩 VCRUNTIME140.dll；读取该 QA Gateway 的已加载模块，证实 DLL 来自安装器 `_MEI` 临时目录。停止本 QA 服务后清理残留 EXE，不能将其记成正常退出 0。

修复：冻结安装器启动外部程序时临时 SetDllDirectoryW(None)，随后恢复自身 DLL 搜索目录，防止 Windows 子进程继承；doctor 健康探测最多 3 次 × 5 秒，间隔 1 秒，只接受真实 HTTP 200。新增回归包含异常启动时路径恢复、实际 HTTP 503→200、持续失败仍失败。


0.2.4 的首次升级在种子复制时拒绝了用户已配置的 outputs Junction，EXE 正常退出 1、数据哈希未变化。0.2.5 增加已记录保存位置的严格匹配，仅对内容根联接解析后复制缺失种子；未知联接、目标不匹配和子级联接仍拒绝。后续继续用同一个已迁移 QA 数据目录安装，不恢复默认目录绕过问题。
