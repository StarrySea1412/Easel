# 图片任务路由与工具错误提示 · 0.44.1

用户明确要求AI生图时，不能因用途是海报、封面或小红书而先制作HTML。本批修正推荐顺序、每轮执行规则与相关技能的默认流程，同时完成已有工具协议错误分类和开发依赖修复。当前是源码候选，138未部署此版本，安装器未发布。

## 原因与行为

原推荐规则将海报/封面的`poster-hero`排在`ai-image-gen`前；前者要求先写HTML再截图。小红书笔记技能也把`html_card`标为默认，并要求文字/概念卡统一渲染。每轮运行规则只笼统提示使用生图工具，没有明确限制这些默认流程。因此代码中存在将生图诉求带入HTML路径的冲突；本轮未取得用户所指具体失败轮次，不能声称已还原那次模型选择。

- 海报/封面默认优先推荐生图。明确要求AI生成且未要求后续代码排版时，不推荐HTML卡片/海报技能；明确要求HTML排版则保留渲染推荐。推荐只帮助选择，不自动发送或调用模型。
- OpenClaw及共用消息策略的工具引擎、CLI和可选Codex每轮明确：生图先用实际图片能力，不先交HTML草稿、SVG或代码截图；当前要求优先于已选技能默认和历史产物。Codex新建与恢复线程均包含相同规则。
- 纯API直连没有生图工具时准确说明能力边界，不能用HTML/SVG或虚构链接冒充生成结果。缺配置或生成失败不静默切换方式；原费用授权和幂等请求标识保持。
- HTML排版、确定性文字/数据卡与用户明确要求的代码绘图仍可使用既有渲染流程。图文合成先取得所需图片，再排版并交付实际图片。

这些是推荐、技能及模型执行指令的修复，不是对所有模型服从性的硬保证；真实供应商出图、用户所指原轮次和最终视觉质量尚未复验。没有借用聊天Key、替换模型或调用收费供应商。

## 其他兼容修复

OpenClaw明确返回`Provider returned an incomplete or malformed tool call`时使用`model_tool_call_invalid`，说明网关未派发失败调用、保留前序工具结果且不自动重放。历史错误显示使用相同分类；普通引用和说明文字不误判，不据此断言输出截断，不回显原始工具参数或凭据。

开发/测试依赖锁定happy-dom 21.0.4、vite 8.1.6、undici 8.12.3。本批最终锁文件在npm官方源实际审计为0漏洞。Node要求由依赖声明，138既有构建使用Node 24；未在服务器触发构建或切换。
