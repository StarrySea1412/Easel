## 1. 我的判断

这个页面值得重做处理流程。用户想完成的是：**把一条值得参考的内容交给AI，弄清它怎么写、哪些方法适合自己，最后带走能用的模板或选题。** 链接、正文、截图、字幕只是不同的材料来源，不能让链接决定整个功能。

建议保留“爆款拆解”这个熟悉的入口，副标题改为：

> 放入你想研究的内容，支持正文、分享链接和截图。先看清原作怎么写，再提炼适合你的模板与选题。

这里描述的是**目标能力**，上线时必须按实际完成的格式改文案，不提前宣传截图或视频已支持。结果页根据证据显示“内容拆解”或“附表现数据的拆解”，没有数据也能用；不强迫用户先证明它是爆款。

推荐流程：**输入素材 → 展示已取得的材料 → 拆解并引用原作 → 按用户方向生成模板/选题 → 保存与继续创作。** 优先让最常见的正文、分享文案、链接及截图顺畅完成，视频完整视听拆解后续单独做。

## 2. 源码里的真实问题

核查基线：独立工作分支 `54efd7ef`，并对照共享工作区相同页面。源码入口为[BreakdownPage.tsx](../web/frontend/src/components/BreakdownPage.tsx)，调用[runAgent](../web/frontend/src/lib/api.ts)及[后端聊天接口](../web/app.py)。

**当前源码并非只能输入链接。** 它是普通多行文本框，placeholder明确写“爆款文案/收藏的内容”，没有URL格式校验，按钮只判断输入是否为空。用户感到“只能输入链接”是需要解决的体验信号，不能通过一句“本来就支持正文”结束问题。

本轮只读访问本机7880时连接被拒绝，未观察真实运行页、未启动服务；因此不能断言用户看到的版本与当前源码完全一致。实施前需核对实际服务的构建身份、页面入口和输入限制。

| 已核实行为 | 为什么使用起来不顺 | 应如何改变 |
| --- | --- | --- |
| 任意输入直接拼进六段固定提示，调用通用Agent | 用户不知道链接是否读取成功、材料是否完整；分享口令也可能被当作正文分析 | 先识别输入，明确读到的材料，缺什么就在原处补 |
| 页面没有专用链接解析/预览，但Agent可能自行调工具 | 链接有效不代表AI看到了原作；正文、封面、评论、视频内容可能完全没取得 | 页面负责材料状态，工具成功回执及实际提取内容决定可分析范围 |
| 固定要求输出“为什么会火” | 没有播放/互动、账号基线或投放信息，也容易生成肯定归因 | 先做有原文依据的吸引力分析；传播原因作为待验证假设 |
| 只有textarea，没有上传、拖拽、粘贴图片或内容库选择 | 用户手机里只有截图或电脑上已有文件时无法顺畅输入 | 统一素材区接收不同格式，能力未配置时提供可操作替代方案 |
| runAgent只传message和persona，走非流式/api/chat | 页面没有传模型、执行引擎、附件、稳定会话/任务ID；与聊天执行体验脱节 | 新建拆解任务并绑定材料版本；复用可靠任务执行、流式进度和停止能力 |
| result只用字符串区分有/无，异常也放进result | 网络错误、Agent返回的“❌”文本都可能显示为拆解结果并允许保存 | 分开任务状态、错误、有效报告；无有效报告时禁用报告保存 |
| 结果只存在组件useState中，切页卸载后丢失本页状态 | 原稿、拆解和创作上下文难以找回；长任务离开页面后状态不清楚 | 草稿与任务服务端持久化，返回时恢复；清空表单不等于删除历史 |
| “存入选题库”保存整个报告，标题截输入首行24字符 | 输入链接时标题是URL；整篇分析与一个可执行选题混在一起 | 分开保存拆解、保存模板和选择具体选题；标题可编辑 |
| 保存没有独立saving/error或防重复处理 | 连点易重复，保存失败缺少清楚反馈 | 幂等保存、操作状态和明确落点 |

另一个不协调之处是：项目[内容分析方法](content-analysis-methodology-2026-09-30.md)和[现有AI分析模块](../web/content_analysis_ai.py)已要求真实材料、原文引用及推断边界，这个轻量页面却绕过了这些约束。优化应统一证据标准，而不是再加一份长提示词。

## 4. 页面怎么改，才能让人自然地用

### 4.1 新手默认只需要放入内容

用户纠正“你确定这样子的交互，真适合小白吗”。复核后，**不能将上一版三栏工作台作为新手默认，更不能凭按钮可点击就宣称适合新手**。默认流程修订为“放内容 → 看懂关键点 → 写自己的”；这三个阶段是用户心中的路径，不要求机械拆成三张必须点下一步的页面。

```text
爆款拆解
放一条你想参考的内容，看看哪些写法适合你。

┌─────────────────────────────────────────────┐
│ 贴入正文、分享文案或作品链接……               │
│                                             │
│ ＋ 添加图片/文件                            │
└─────────────────────────────────────────────┘
                     [开始拆解]
没有素材？看看示例
```

只宣传本期实际已支持格式。首屏不要求选择模式、分析维度、创作画像、模型或专业程度；“从内容库选择”放在添加材料入口中，保留键盘及触屏可达。示例必须与用户自己的历史材料分开标明，不能静默代替用户提交的内容。

“开始拆解”明确授权当前作品范围内的读取与一次分析；对可正常读取的单一来源，材料卡在同一页面持续可见，无须再点一次确认。取得材料不完整但足以限定分析时，明确说明范围；仅标题、材料冲突、登录墙或多作品等会改变分析对象的情况才停下来确认/补材料。不能为省点击把分享口令当全文，也不能自动购买服务、登录第三方或扩大成全网采集。后续额外分析的范围/成本另行说明。

读懂原作不需要画像。只有用户选择“照这个写法写我的”，才问“你想写什么内容？”，已有方向可预填并可改；仍有缺口时再问一个真正必要的问题。用户可停在阅读结果，不被强迫进入创作或保存流程。

### 4.2 不同输入，给出不同的自然反馈

| 用户放进来的材料 | 推荐处理 | 看不到的内容怎么说 |
| --- | --- | --- |
| 直接粘贴标题/正文 | 原样保留段落；展示正文预览；可以直接开始 | 只有正文就分析标题/结构，不猜封面、评论或播放数据 |
| 平台分享文案＋短链接 | 保留全部原文，识别URL并解析；分享话术与作品正文分开，提取结果可修正 | 分享文案可能只是标题/导流语，不当成已取得全文；解析失败仍可继续补正文 |
| 纯作品链接 | 后台读取并展示来源卡：标题、可取得的正文/封面/数据及时间 | 只取得元数据时标“仅标题”；不能因HTTP200就算读到正文 |
| 图文截图/封面图 | 支持图片顺序、预览、移除；OCR文字可编辑；具备视觉能力时分析实际画面 | 只有OCR时只分析文字，图片内容识别不足不补想象；截图中数据带截屏时间未知提示 |
| TXT/MD/SRT等文件 | 明确格式白名单，解析为正文或带时间戳字幕；展示截断/缺段 | 字幕只代表说了什么，不能判断镜头、配乐或真实完播率 |
| 内容库已有作品 | 选择当前有权限的素材引用，不重新传一遍；复制分析快照避免原文件被改后结果悄悄变义 | 无权访问/文件删除显示失效，不猜路径或自动扫全部目录 |
| 视频/音频文件 | 后续接入转写、时间轴、关键帧/音频线索，按能力启用 | 上传成功不等于已转写；只采样画面不宣称看完全部镜头 |
| PDF/DOCX | 后续验证提取质量、页码及扫描件识别后开放 | 扫描件可能无文字；不把空文本当空作品，不宣传通吃格式 |

一条作品可以包含“正文＋封面＋评论截图＋字幕”，这些是同一拆解对象的补充材料。默认不是把每张截图都拆成独立作品，也不把多个URL静默拼成一篇。发现多条作品时询问保留哪条或明确进入后续“对比拆解”，不擅自批量执行。

### 4.3 材料确认要有，但不能变成多一次无意义点击

纯正文不强制独立确认页：开始后即可进入拆解，随时查看原稿。链接/OCR/混合材料在同页展示取得范围和可编辑材料卡；用户已点击“开始拆解”且材料对象与覆盖正常时接着处理，不再重复要确认。若用户只点“读取链接/预览”，不等于授权付费分析；存在缺失、冲突或多作品等歧义时停下来补充。

例如链接读取后显示：

> 已读取：标题、正文、封面。未取得：评论和播放数据。你可以补截图，也可以直接分析当前材料。

失败时给“粘贴正文”“补充截图”“重试读取”，保留原链接与草稿。登录限制、短链接过期、网络超时、工具未配置分别给真实原因；不反复重试，也不把搜索摘要当原文。一个来源失败不使已添加的其他素材全部失效。

### 4.4 为什么上一版对新手仍偏重

| 上一版会让人犹豫的地方 | 本轮默认怎么收敛 |
| --- | --- |
| 初次就需要理解原作/结构/发现三栏的关系 | 默认单列完整报告，摘要后直接阅读正文；原作/结构/解释联动是辅助视图 |
| 先选综合、钩子、结构、封面和画像 | 由实际材料决定分析范围；首次不必做这些决定，后续用具体问题追加 |
| “机制假设、承诺兑现、证据状态”等术语密集 | 用“原文怎么写、可以学哪里、哪些还不知道”等白话；专业标签放在详细内容 |
| 让用户选证据并排或聚焦讲解 | 不要求用户理解或选择布局，默认一种阅读方式；已有双布局示意仅为设计探索 |
| 同时出现播放、切段、存报告、存模板、选题、继续创作 | 当前阶段只突出一个主动作；报告自动保留，其他动作放在对应内容附近按需出现 |
| 看起来有动画和勾选，就以为分析已被证实 | 关键限制始终可见；引文可展开，播放仅用于已完成内容的讲解，绝不代替核验 |

补充读取[GOV.UK官方表单结构指南](https://www.gov.uk/service-manual/design/form-structure)，其建议仅问必要问题、按常见场景分支、从每次一项信息/决定开始，再由用户研究判断能否合并。它针对表单，不能直接证明本项目分析工作台好用；本方案将其用于减少前置问题和阶段决策，这是设计取舍。两篇NN/g文章本轮请求失败，未作为已读依据。

## 5. 拆解结果应该回答什么

下面四类内容是分析主题，完整交付采用[报告骨架与深度标准](viral-report-research-2026-10-15.md)：研究对象与表现背景、定位与承诺、包装开头、全文结构、机制解释、表达与信任、迁移方案、验证与来源。**默认结果直接是完整报告，摘要后有正文，不用先进入高级模式。** 每章结论在前，依据与解释在后；长原文、机器明细和辅助工作台按需展开。不使用笼统“爆款评分”取代分析，也不以篇幅和章节数量冒充深度。

### 第一块：这条内容怎么吸引人

给一句概括和少量关键发现，每项都有**原作证据 → 采用的方法 → 可能的作用 → 使用条件**。正文引用定位到段落，截图定位到图片/识别区域，字幕定位到真实时间段。允许用户点开原材料核对。

例如以下是虚构示例，只说明输出形式：

> 原句：“租房厨房太小，我把备餐流程重新排了一遍。”  
> 观察：先限定具体人群和场景，再提出可观察的问题。  
> 可能作用：让有类似厨房空间的人更快判断内容与自己相关。  
> 迁移条件：后文应提供真实流程或前后对照；只换成更夸张的标题并不能补足证据。

### 第二块：把结构拆到能复用

| 原作部分 | 在做什么 | 承接关系 | 如何迁移 |
| --- | --- | --- | --- |
| 标题/封面 | 承诺、对象、冲突或信息缺口 | 是否与正文兑现一致 | 可替换槽位和不能夸大的事实 |
| 开头 | 场景、问题、反差、结果前置 | 让用户为什么继续看 | 用自己的真实情境替换 |
| 主体 | 步骤、案例、对比、反转 | 每段如何推进同一问题 | 需要准备的素材/证据 |
| 结尾 | 总结、限制、下一步、互动 | 是否回收开头承诺 | 与自己的创作目标适配 |

没有封面就不填封面分析，没有视频帧就不填镜头节奏。视频后续增加逐段脚本与关键帧时间轴，而不是沿用“前两行文案”的统一模板。

### 第三块：传播表现与待验证解释

分开“可观察表现”“内容机制假设”“还缺什么证据”。没有表现数据时仍可出完整结构拆解，只隐藏真实表现判断，不输出“已证明因为某钩子火了”。

有数据时需保留平台、指标原名、来源、观察时间、发布年龄、自然/投放是否已知，以及作者自身可比作品的基线和样本数。点赞、播放、收藏分别展示；没有播放不算收藏率，没有曝光不算封面点击率，截图手填值标“用户提供”。不能用粉丝数假装曝光分母。

同账号、同形式、接近观察年龄的作品才有初步比较意义；样本少或口径不同要降级。即使表现高也只形成机制假设，不能排除热点、分发、投放、账号积累等因素。现有竞品技能中“3–5倍即爆款”和“互动/粉丝”的建议需要按[本项目方法规范](content-analysis-methodology-2026-09-30.md)修订，不直接作为判定标准或跨账号排名。

### 第四块：转换成我自己的创作起点

- **模板**：以“适用人群—问题/承诺—论据/案例—方法/步骤—限制—行动”之类槽位表达，附适用/不适用情境和必要素材；支持复制、保存Markdown。
- **选题**：每条包含目标读者、具体问题、独特角度、标题方向、简短提纲、需要准备的事实与素材。默认给少量可编辑候选，用户可选择生成更多，不用固定三条充数。
- **继续创作**：选中模板或选题，明确进入现有聊天并携带当前材料版本、用户方向和已选结果。预填草稿，用户确认发送后执行，不丢现有草稿，也不顺带发布或调用生图。

“存入选题库”针对选中的具体选题；“保存拆解”保存整篇分析；“保存模板”保存结构框架。初期模板可存入内容库Markdown，不假装已有独立模板管理产品。选题标题由候选标题并经用户编辑确认，禁止直接截URL首行。

### 5.1 专业性要落在分析方法上

专业不是多几个术语或一张雷达图，而是能回答“结论来自哪里、适用于什么情况、哪些还不能确定”。建议按以下维度形成结构化报告；并非每条作品都强行填满，每项按实际材料启用。

| 分析维度 | 具体研究什么 | 结果如何呈现与核对 |
| --- | --- | --- |
| 受众与使用场景 | 作品面向谁、什么时刻的问题、已有认知与行动障碍 | 引用对象/场景表达；区分作者明确说明与分析推断，不凭语气猜精确年龄收入 |
| 核心承诺与兑现 | 标题/封面承诺什么，正文有没有兑现，是否存在信息缺口 | “承诺—对应段落—已兑现/部分兑现/材料不足”对照 |
| 钩子机制 | 具体场景、冲突、反差、结果前置、问题等如何建立继续阅读理由 | 标出实际句子/画面与作用假设；不把套了某种钩子等同于有效 |
| 内容结构与论证 | 问题、方法、案例、证据、限制、结论之间如何推进 | 可点击结构链；每段的功能、承接关系、证据充分性与跳跃处 |
| 信息与表达节奏 | 何时增加新信息、重复解释、切换话题或回收悬念 | 图文按真实段落/字数，字幕按真实时间段；重复/转折标记可回看，不伪造观看流失曲线 |
| 画面与声音 | 构图、标题可读性、演示画面、字幕对应、音轨变化如何协同 | 只在实际读取对应材料时开放；画面采样点、转写段和音频线索分别标明覆盖范围 |
| 信任与表达边界 | 案例/数据/演示是否支持承诺，是否遗漏条件或夸大结果 | 引用可疑论断与缺口；“原作声称”不等于事实已核实，外部事实核验另列来源 |
| 互动与行动 | 收藏理由、评论问题、后续行动是否与内容价值一致 | 原句、行动成本、与目标的关系；没有实际互动数据就不评价转化效果 |
| 可迁移条件 | 哪些属于通用结构，哪些依赖作者身份、素材、产品或平台环境 | 可复用框架、用户需补的证据、不可直接照搬部分及一个改写起点 |
| 真实传播表现 | 同口径数据是否突出，基线是否可比，有哪些混杂因素 | 仅在有来源与基线时展示真实数据；单篇材料无法证明因果，不输出“爆款概率” |

同一发现使用统一契约：**结论、原作定位、推理说明、证据状态、适用条件、可采取的动作**。证据状态用“直接观察 / 机制假设 / 材料不足”等可解释标签，不显示无校准的“置信度92%”。缺材料可以保持空缺和补充入口，不由模型补齐。

图文、口播、教程、剧情等形式有不同检查重点。用户可选“标题开头”“结构论证”“封面画面”等目标；默认综合分析由材料覆盖决定。深度分析可以追加外部事实核验或同账号可比样本，需要展示来源、范围和额外执行，不偷偷扩大成全网采集。

### 5.2 默认读完整报告，按需使用联动工作台

默认采用单列连续报告：标题与材料范围→结论摘要与目录→各章分析正文→创作方案→验证与来源。摘要帮用户选择阅读重点，正文就在下方，不再只给两条发现然后引导生成。每项重要发现写清具体结论、原作依据、怎样推得、创作用途与适用边界；后半段、例外和反向证据也要覆盖。完整内容见[人工编写样稿](viral-breakdown-report-sample-2026-10-15.md)。

短作品允许合并章节，材料弱时如实指出缺口；不强凑三条好话。摘要与正文使用同一组发现，不各自生成矛盾内容；“可以借鉴什么”与“原作取得了什么效果”分开，重要限制不藏在折叠区。长引文与机器检查明细按需展开，完整原稿随时可查看。

桌面目录帮助定位章节，窄屏可收起；“用这份方法写我的”在摘要和创作章附近，报告工具栏提供历史/导出，追问作为末尾辅助入口。原作/结构/解释三块联动属于用户主动使用的辅助视图，保留原阅读位置、草稿和材料版本：

```text
爆款拆解 / 当前作品                         当前材料版本 · 历史
材料范围：正文已读 · 封面未提供 · 无表现数据
连续报告（默认） | 来源与结构联动（辅助） | 有材料时的视听/表现

┌ 原作材料 ─────────┬ 结构地图 ─────────┬ 当前发现 ─────────┐
│ 标题/正文/截图      │ 场景问题             │ 结论与证据状态      │
│ 保留段落和位置      │    ↓                 │ 原作引用/定位       │
│ 高亮当前引用        │ 方法与演示           │ 为什么这样理解      │
│                    │    ↓                 │ 条件、缺口、可迁移点 │
│                    │ 结果与限制 → 行动     │ [提取为模板]        │
└───────────────────┴──────────────────┴──────────────────┘
                       [逐段讲解 / 暂停] [上一段] [下一段]
```

结构节点按实际作品生成，不强制所有作品都是四段；定位可以多对多。点击发现，高亮对应原文/图片区域；点击原文，展示关联发现。图示仅表达推理和结构，箭头不意味着已经证明因果。

默认报告先用摘要交代核心判断与材料缺口，再展开主要分析；新手无需使用多栏工作区就能读完。模板与选题有独立编辑区域；“追问这条发现”作为局部入口携带当前证据，不让用户为了看结构再向AI发一句话。没有画面/表现数据时，相关入口显示缺少什么材料及补充动作，不能展示空的假图表。

窄屏改为原作/结构/发现切换或顺序展开，保留当前节点与定位，不把三栏缩成无法阅读的小字。内容多时以点击联动为主，不在用户阅读时强行滚动整个页面。

### 5.3 动画怎么加才有用

| 位置 | 推荐动效 | 数据与操作边界 |
| --- | --- | --- |
| 素材进入与解析 | 素材卡加入/移除、真实阶段状态切换 | 只有真实后台事件才更新“读取/提取/分析/校验”；不播放假扫描、随机跳百分比或假思考过程 |
| 结构地图 | 点击节点时移动选择指示、强调相邻承接路径，并联动原作定位 | 节点内容来自有效报告；局部过渡约180–260ms，不连续闪烁 |
| 原作证据 | 引用区域短暂高亮，必要时在材料区域定位 | 高亮后稳定停留；不自动频繁切页或抢焦点，多个引用可以逐个查看 |
| 逐段讲解 | 用户主动播放，逐段切换当前节点、原作与解释，支持暂停、上/下一段、重播 | 这是已完成报告的阅读动画，始终标明；不是模型实时思考，也不是观众注意力/留存模拟 |
| 视频时间轴 | 随用户拖动/播放同步字幕、真实关键帧与对应发现 | 必须绑定真实时间戳；无视频只有字幕时称“字幕时间轴”，不假装播放画面 |
| 图表与保存 | 数据筛选后图形过渡、保存成功状态切换 | 仅对真实已取得数据绘图；报告可直接看全，保存反馈不制造持续动画 |

所有动画均可停止；遵循系统“减少动态效果”，提供静态等价信息。键盘操作与触屏可完成同样动作，不能只靠悬停出现结论；分析正文不逐字打字，避免等待和布局抖动。长解释逐段讲解时以手动下一段为主，自动播放也能随时暂停且不触发新的模型调用。

动效建议优先复用现有CSS/组件能力；需要复杂时间轴或布局过渡时再评估动画库，避免为了几处过渡引入重依赖。动效只消费任务状态与报告数据，不决定任务成功，也不改变材料版本。

上一版双布局动态示意保留为详细阅读探索，不能当作已通过的新手默认。追加的新手流程示意以虚构正文展示摘要、原句展开、主题填写和可编辑提纲；默认无自动播放，轻动效只跟随主动操作。所有示意不接后台、不运行模型、不保存真实选题。

### 5.4 分析到底靠不靠谱，先逐项验证

**目前不知道这个页面的结论正确率。** 现有六段提示和通用Agent调用没有本页专用质量评测；本次只做源码与方案调研，没有真实拆解样本。更专业的排版、更多术语、动画、模型自称专家或第二个模型赞同，都不能填补这个证据缺口。

建议把可靠性拆成可检查的层次，不在页首摆一个“可信度92分”：

| 层次 | 核查问题与责任 | 失败时如何处理 |
| --- | --- | --- |
| 材料身份与完整性 | 程序记录来源、版本、实际提取段落/页/时间、截断和缺失；用户可查看并纠正OCR。HTTP200不等于取得原作，字幕不等于看过画面 | 验证页/空壳不进入正文分析；不完整材料仍可做限定分析，显式说明没看什么 |
| 引用确实存在 | 程序核对作品及版本、段落/字区间/时间戳、引用文本；显示时使用保存的原文，而非模型重写的引号内容 | 找不到、引用跨作品或坐标越界则拦截对应发现；保持材料和其他已通过发现，不伪造替代引用 |
| 引用支持结论 | 模型检查可作辅助，人工评测核查解释是否过度、遗漏限制、误读反讽/否定/因果。引用存在只完成上一步 | 关键论断支持不足则删去、降为假设或列缺失；存在矛盾证据时并排呈现，不挑一句证明预设结论 |
| 数字可以复算 | 真实统计和比率由程序按指标字典计算，保留分子/分母、平台口径、观察时间与舍入；缺值不补零 | 无分母、不同时窗、口径不齐就不计算；不能让模型替缺数据生成漂亮图表 |
| 外部事实有核验 | 区分“作者说了X”“外部来源支持X”“尚未核实X”；需要时另做有来源的核验，检查来源是否独立且适用 | 原作的数字、身份、功效不自动升级为事实；搜索摘要或相互转载不充当多份独立证据 |
| 机制与因果有边界 | 文本中出现钩子是观察；它可能减少理解成本是解释；它造成播放增长需要额外证据 | 单条爆款的事后解释一律不能作为确定因果。没有真实表现就不认定“火了”，有表现也保留投放/时点/账号等替代解释 |
| 建议可用且有条件 | 说明建议适合的人群、目的、所需素材与不能照搬处；提出可检验的改写/实验，不生成假的个人经历或结果 | 材料不足时给补材清单；用户画像未知时不推定精确受众，不以模板固定数量充数 |

报告中每条发现至少分开显示三种信息：**原作观察、机制假设、可迁移建议**；“外部事实已核验”另带具体核验来源与时间。它们描述证据类型，不是从低到高的统一质量等级。“引用匹配通过”只放在来源详情中，不能用绿色总勾暗示语义已审核。

例如，原作写“改了封面，播放量翻三倍”：能确认的是作者写了这句话；没有同窗口数据无法确认倍数，没有合理对照无法确认封面导致增长。报告可以分析封面表达如何改变、提出待验证假设，不能输出“反差封面让流量提升200%”。虚构示意中的“台面空出一块”也必须标作原作声称，不能写成已测得厨房效率提升。

建议的检查链是：**固定材料快照 → 产生候选发现及引用 → 程序验来源/计算 → 检查支持与反证 → 有界修复 → 合法结果/限定结果/失败**。结构有效和来源定位通过只是机器检查通过；未人工审阅的报告保持“AI分析，未经人工审核”。第二轮模型审阅可优先找错并列反例，但与原模型可能共享偏差，不能改名为独立事实认证，也不默认每次用多个Agent增加费用。

拒答应具体到能力和结论。没有材料不能拆解；只有标题就只拆标题；只有字幕不评价构图和音乐；没有基线就不评“超常表现”。引用错或结构错可以一次有界修复，仍失败则不给该条结论。停止或失败保留草稿，已验证片段可查看但标记“部分完成”，未完成模板不能自动变成正式报告。

用户可在发现旁选择“引用错了 / 解释不成立 / 不适合我的场景”，补正确材料或说明。材料改动形成新版本，界面提示受影响的发现，历史结果保留并标为旧版；不能原地改原文却继续显示旧报告“校验通过”。删除来源或失去权限后，报告、导出及分享遵守同一权限与保留规则。

### 5.5 上线前如何证明比现在可靠

评测要先于“专业版上线”的宣传。本节为**拟议验收方案和初始目标，不是已有测试成绩、行业基准或准确率保证**。方法参考[OpenAI官方评测最佳实践](https://developers.openai.com/api/docs/guides/evaluation-best-practices#human-evals)：围绕具体任务建代表性样本、固定标准，采用随机盲评、处理人工分歧，并用人工判断校准模型评分；已读取正文，这里将其转化为Easel自己的拆解评测。只借鉴方法，不依赖该页提及的托管评测平台。

1. **先建样本与判定手册。** 初期建议60条开发样本、另留40条不参与提示调试的验收作品；正文/长图文/截图/OCR/字幕按本期支持格式分层，有不同题材、普通作品与高表现作品，以及缺材料、错误数字、否定反讽、广告/投放、互相矛盾、恶意材料等情境。未支持视频时不把视频样本“跳过”后报告全面多模态通过。数量只是起步预算，需要按覆盖与争议扩充。
2. **比较当前方案与候选方案。** 固定相同材料、分析目标和可访问数据，隐藏版本名称、随机呈现，避免评审者因新版动画或格式更好而给内容加分。分析正确性看统一的静态报告，工作台可用性另测。普通作品也要做，不能只用“已知爆款”倒推理由。
3. **两人独立判，再处理分歧。** 一人具内容研究/编辑经验，一人负责材料与数据核对；对每个可检查结论标记支持/不支持/无法判断、错误严重程度，对建议标记具体/有条件/不可行。保留分歧和复核理由，不能只保留最终赞同比例。模型评分可筛样，不能代替这次独立人工验收。
4. **固定版本与验收集。** 保存材料hash、模型/参数、提示/schema/提取器版本、工具来源与成本耗时；候选冻结后跑验收。若依据验收失败例修改提示，原验收集转回归集，再准备新留出样本，不重复使用后声称独立成绩。关键样本复跑观察随机性，模型/工具改版后再做对应回归。

| 指标 | 计算与初期发布规则（待首轮校准） |
| --- | --- |
| 严重错误 | 验收中伪造作品/引用/统计、串作品、无材料假装已读、把缺失当真实表现或作确定增长承诺，任一出现即阻断发布，修复后重验。测试中零例不代表线上概率为零 |
| 引用定位 | 所有被展示的来源定位在版本化材料中可解析；无引用的必要事实不能被排除出检查。自动门禁要求本次验收全部定位通过；这不是语义正确率 |
| 事实/解释支持 | 人工按原子结论判断：被证据支持的确定性结论数 ÷ 全部展示的可检查确定性结论数；无法判断按未支持计。初期目标≥95%，任一已支持格式低于90%需收窄范围或返工；至少审查200条结论并报告作品数、分层分母、错误例，而非只报一个百分比。结论聚集在同作品，不能当200个独立样本估计总体准确率 |
| 降级正确性 | 材料不足/矛盾/无表现等预设案例，是否准确限制对应判断；严重越界仍按阻断规则。另报误拒绝，防止靠不分析获得高正确率 |
| 覆盖与实用性 | 人工预标作品中可支持的核心发现，报告发现覆盖数/应覆盖数；建议的具体性、条件和可执行性盲评。与旧版逐作品比较，列出退步，不把保存率当正确率 |
| 运行与成本 | 成功/限定完成/失败分别计数；报告解析/模型/校验阶段耗时、P50/P95及每次费用，样本数不足以稳定估计时说明。有限重试、停止/重连不重复启动要有真实后台验证 |

95%/90%、样本数量是建议的内部起点，正式试点前冻结验收口径；不足时明确“未达到发布门槛”，不在看过结果后放宽门槛。安全关键或强事实结论不因平均分达标而放行，格式覆盖不足则只开放已验范围。

首批采用小范围试用，保留“实验性分析”和问题反馈入口，定期抽查真实失败。发布后的收藏、采纳和满意度反映价值，不能证明事实或传播因果正确；创作成效要在用户授权、同口径数据及合理对照下单独评估，不把改写后一条内容变好就归因于AI。产品可以承诺证据可追溯和错误可纠正，不能提前承诺爆款。

## 6. 底层怎么接，避免继续靠一段提示词

### 6.1 先统一材料，再调用分析

建议新增拆解领域对象，分开素材、解析版本、任务和报告。接口名称为草案：

| 操作 | 拟议接口/职责 |
| --- | --- |
| 建立/保存草稿 | `POST /api/breakdowns`，创建有归属的拆解对象 |
| 添加来源 | `POST /api/breakdowns/{id}/sources`，正文、链接、已校验附件或内容库引用 |
| 读取材料 | `GET /api/breakdowns/{id}`，返回草稿、解析状态、实际覆盖和历史有效报告 |
| 开始拆解 | `POST /api/breakdowns/{id}/runs`，绑定材料版本、persona快照、模型/引擎与分析目标 |
| 恢复与停止 | 复用项目已验证的任务事件和停止接口语义，按runId恢复，不靠页面loading变量 |
| 选题/报告保存 | 分别调用领域保存与现有选题接口，附来源版本及幂等键 |

材料记录至少包含来源类型、可访问引用、hash/版本、提取状态、正文分段/截图顺序/时间戳、提取器版本、观察时间及截断说明。模型输入和报告固定引用该版本，晚到旧结果不能覆盖新材料；修改正文后旧报告保留但标明基于旧材料，重新分析另起版本。

任务状态区分准备材料、读取中、需补材料、可开始、分析中、待用户操作、完成、失败、已停止。进度只显示真实阶段，不编造百分比；失败保留上一次有效报告，不把错误字符串包装成新报告。

先复用现有OpenClaw任务执行基础；当前非流式入口实际上走OpenClaw，不因为ChatRequest含engine字段就宣称所有引擎已接通。未来接Codex时单独验证模型/附件/停止及恢复契约。专用拆解仍应使用受限、可核对的分析流程，不让通用Agent为了解读一段正文任意扫描数据或执行无关任务。

### 6.2 能复用什么，需要新做什么

| 现有基础 | 推荐复用方式 | 必须补的工作 |
| --- | --- | --- |

| [内容分析证据与引用检查](../web/content_analysis_ai.py) | 复用材料引用、无依据输出拒绝、真实指标由程序展示等原则 | 当前校验严格禁止数字等，不能原样套到脚本时间戳/模板；按拆解schema校验，不放松既有账号分析约束 |

### 6.3 结果采用结构化契约

模型返回分块结构：材料范围、定位/承诺、包装开头、全文结构、机制/替代解释、表达/信任、迁移方案、验证计划与来源索引；报告摘要来自同一正文。[报告调研](viral-report-research-2026-10-15.md)细化各章字段。发现携带evidenceId和真实引用/位置、分析维度、观察/假设状态、适用条件；结构节点携带原文定位、段落功能与承接关系，视听结果补真实时间范围。指标与来源由程序提供。输出通过schema及引用检查后才形成可保存报告；动画读取通过结构与定位检查的数据，不把这些检查称为语义已验证，也不靠模型生成任意可执行页面代码。

引用文字匹配只能证明那句话存在，不能证明解释正确；视觉证据引用图片ID/区域也需要模型能力和人工核对，不能只验证ID存在就声称画面判断已验证。引用错、模型只返回错误或结构不合法时，说明失败并保留材料，不生成漂亮的虚构报告。可允许一次有界修复请求，不无限重试计费。

网页正文、分享文案、OCR及附件都是待分析数据，材料内的“忽略规则/调用命令”等不作为操作授权。链接读取采用现有受控读取设施，限制协议、重定向、响应大小/时间及私有地址访问，读取失败直接降级。短链接中的访问token仅为读取保留，日志、报告和Git不泄露敏感参数；不能为“规范化URL”先删掉必要参数导致作品不可读。

### 6.4 让执行记录与报告共用一份真实任务状态

借鉴DeepSeek Harness的事件投影思路，不照搬其插件系统。Easel建议由后端记录`runId、sourceVersion、seq、stage、status、startedAt/endedAt、artifactId、errorCode`等事实；读取、提取、分析、机器校验、完成/限定完成/失败/停止各有明确状态，人工审核另列，不能和机器校验混用。具体字段在实施时对齐项目既有任务契约。

页面先取得有权限的快照及事件水位，再续接增量；重复/乱序可去重，断线后对账，陈旧任务不能覆盖新作品。“活动”显示已发生动作、耗时和具体失败原因；“报告”只展示已形成的有效版本。两者不分别猜状态，也不按字符流量推算进度百分比。

补材料/改目标先说明是否影响当前分析：只改阅读视图不发请求；增加材料保存为新版本，原任务仍绑定旧版；用户选择重新分析才新建run并显示预计处理范围。停止要由真实后端确认，未知时显示“停止请求已提交，状态待确认”，不得立即假报完成；停止不删除已保存内容，也不撤销外部动作。

每个关键发现保留`claimId、sourceVersion、evidenceRefs、observation、interpretation、suggestion、limitations、validationResults`；机器校验、模型复审和人工审核分别记录责任与版本。发现纠错后只更新对应版本的关联展示，报告/模板导出同时保留来源范围和限制。前端渲染结构化数据，不能执行模型生成的任意HTML或脚本。

## 7. 推荐按什么顺序实施

| 阶段 | 做什么 | 完成标准 |
| --- | --- | --- |
| P0：材料与可信结果 | 正文/分享文案入口、明确链接读取状态、失败补正文、单作品材料卡、持久草稿/任务、引用结果、选题与报告分开保存；默认摘要＋完整报告正文＋创作方案，原作/结构/发现联动区按需使用；同步建评测样本与发布门禁 | 纯正文无需联网取材即可拆解；链接失败不编造；切页/刷新可恢复；错误不可存成报告；主要分析不用高级模式即可读，全文覆盖/摘要一致/建议具体性通过；点击结论能定位材料，减少动态效果可用；人工留出评测与范围限定达标后才能开放对应能力 |
| P1：截图与已有文件 | 图片粘贴/拖拽/上传、OCR可改、视觉能力检测、TXT/MD/SRT及内容库选择 | 配置支持时真的解析截图/文件；不支持时给补正文方案；正文/图像/字幕观察范围正确 |
| P2：完整视频与对比 | 本地视频/音频、转写/关键帧、时间轴；明确多作品对比和可比表现数据 | 有对应时间证据，采样/完整覆盖说明清楚；多作品不串材料；预算和资源受控 |
| P3：复用与回收 | 收藏模板、继续创作、选题落地、发布后按真实数据回看 | 原报告/模板/新作品关联可追踪；建议采纳不等于增长验证 |

产品目标图包含截图，实际建议尽快衔接P1，避免第一轮优化后仍只有一个“能贴文字的大框”。在P1完成前，首屏只宣传已可用格式；未实现入口说明即将支持或暂不展示，不能上传后才告知完全无法分析。

首轮不同时承诺跨七平台任意链接、私密页面抓取、无上限文件、完整逐帧理解和可靠爆款预测。先用有明确支持范围的链接＋随时可补的正文完成闭环，再逐个验收平台适配；无需为了拆正文强制登录社媒账号。

## 8. 评审与验收清单

实施时至少覆盖以下情境，区分模拟检查、真实HTTP、实际模型/解析和用户页面验收：

1. 无链接纯正文、长文、只有标题：能按已提供范围分析；截断有说明，不生成未读内容。
2. 小红书/抖音等分享文案含短链：保留原文；链接识别、解析与正文区分正确；不将口令当作品全文。
3. 链接超时、登录墙、404、HTTP200但仅验证页/空壳：显示真实读取状态；已有正文和截图保留。
4. 链接＋正文＋多张截图同作品：合并补充材料，顺序正确；存在冲突时让用户选择，不静默覆盖。
5. 无视觉模型、OCR错字、扫描件、字幕缺段：能力与材料缺失可见，不能宣称已看见画面或听见音轨。
6. 无表现数据、用户手填、旧截图、无曝光/播放、不同平台/发布年龄：不补零、不算假分母、不判确定因果。
7. 模型失败、无效schema、引用不存在：任务失败与报告分离；保存按钮只作用于有效报告/候选。
8. 分析中切页、刷新、断网、停止、快速切两条材料：可恢复到原任务，旧结果不串新素材，不重发模型请求。
9. 保存单个选题、连点、失败重试、编辑标题：幂等、反馈清楚；选题库入口可达，整份报告不会误当一个选题。

11. 删除来源、内容库无权限、跨用户访问：报告来源状态准确；接口、事件及导出采用同一归属范围。
12. 桌面与390px：拖拽有上传替代，图片顺序可用键盘调整，选择器沿用共享组件；Tab/Escape/焦点、历史拆解、材料展开、选题与继续创作跳转逐项检查。
13. 专业分析：每项发现有维度/引用/解释/证据状态/适用条件；原作声称与核验事实分开；无图像/音轨/表现数据不出现对应的虚构判断、雷达分数或留存曲线。
14. 动效与工作台：节点/原文/发现联动定位正确，逐段讲解可暂停/重播，不重发模型请求或抢输入焦点；减少动态效果、键盘与窄屏提供等价静态内容，真实任务阶段与报告阅读动画区分清楚。
15. 可靠性：原作声称与核验事实分开；否定/讽刺/相反证据不被选择性忽略；有引用但不支持结论时不能显示已验证。没有表现或对照时不生成确定增长归因。
16. 评测：当前六段提示与候选方案同材料盲评，按作品/格式给分母、错误和分歧；留出样本不参与调提示。发布门槛仅作拟议目标，未跑不报通过。
17. 任务与回放：同一run在报告/活动中的状态一致；重连、重复/乱序、停止待确认、旧材料返回、新版本重分析逐项验证，不靠动画补齐缺失事件。
18. 纠错与历史：修改材料/发现后明确新版本及受影响结论；旧报告不会沿用新材料的校验状态，导出保留来源范围和限制，权限变化不泄漏旧来源。
19. 报告深度：核心推进与结尾有覆盖，解释有原作依据、推导与边界，摘要忠实于正文；跨章不反复套话，创作方案说明动作、素材与条件；完整正文可直接阅读，导出保留证据与限制。
