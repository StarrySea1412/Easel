# 138 提问卡片修复与发布构建兼容候选 0.43.7

## 现场问题

138 页面中的 `ask_user` 长时间显示“执行中”，却没有可回答的问题卡片。0.43.6 已修复问答桥接的网关凭据传递和未知状态误过滤，但隔离发布尚未完成，因此线上仍看不到修复。

本次隔离发布的第一步又发现：闲置盘迁移后当前正式 release 目录由 root 保护，发布构建脚本读取旧 `deployment-receipt.json` 时触发 `PermissionError`，导致候选在镜像构建前停止。该错误与应用问答逻辑无关，也没有切换正式服务。

## 修复

- `deployment/138/build_image.py` 在旧 release 回执不可读时放弃固定运行时复用，继续完整锁定构建；不放宽目录权限、不读取或改写用户数据。
- `tests/test_linux_release.py` 覆盖受保护回执的降级路径。
- 版本和前端构建元数据同步至 `0.43.7`。
- 保留 0.43.6 的 Gateway 显式认证、`question.list`/`question.get`/`question.resolve` 问答桥接和 pending 卡片保留逻辑。
