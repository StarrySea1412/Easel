# 模型消耗图标修复 0.14.1

用户在138用量页面指出，`deepseek-v4.1-flash`被显示为OpenAI或未知图标。模型消耗卡片此前仅将用量记录的provider传给图标组件；兼容渠道的provider不一定是实际模型厂商。

本修复优先按同一条历史用量记录中的模型名称识别品牌，无法识别模型时仍回退到已记录的provider。使用既有DeepSeek品牌资源，不根据当前渠道配置倒推历史模型；happycoding、未命名渠道、muyuan.do及openai的渠道名称、分组、Token和费用不变。其他调用图标未传入模型时保持原有行为。

从已推送0.14.0提交`bd2fca535338cb2f3f8825b9fa97b27a3317e481`继续，兼容修复patch升至0.14.1，前端版本继续从`pyproject.toml`生成。新增回归覆盖截图中的四种DeepSeek渠道、Claude/Gemini/GPT、旧记录的provider回退和未知模型。

本轮用户已授权将此修复连同网页文件下载及桥接能力部署138。部署使用本分支固定提交，应用及browser sidecar整体更新；先隔离后正式，保留数据、认证、模型配置和回滚点。当前为部署准备，实际版本/SHA及服务器、真实浏览器验收结果以[部署回执](release-138-0.14.1-2026-10-22.md)为准。

GPT/Gemini全自动及便携执行器按用户要求暂缓；本修复不宣称真实平台附件或自动成片已完成，不发布安装器。
