# 界面小白化：复杂度盘点与分层方案

日期：2026-10-17。对应用户要求“考虑一下，如何将我们复杂的界面变得更加小白”。本文只做盘点与方案，**不改界面**；每层都给出可验收的完成定义，实施范围由用户选择后另行开工。

## 现状盘点（2026-10-17 的代码与 7880 实况）

| 维度 | 现状 | 小白视角的问题 |
| --- | --- | --- |
| 一级页面 | 17 个（工作台/对话/生图工坊/定时任务/趋势/选题/日历/发布/拆解/技能库/内容库/运行记录/Agent 办公室/账号/内容分析/画像/设置） | 名词多、分工不清（选题 vs 趋势 vs 拆解；内容库 vs 运行记录） |
| 侧栏入口 | 常驻 6 个 + “更多”菜单 5 个 + 底部 4 个（账号/通知/主题/设置） | 13 个点击目标，第一次打开不知道从哪开始 |
| 输入框工具栏 | 12 个控件（素材/目标/技能/上下文/引擎/模型/思考强度/发送/停止…） | 个个都要问“这是干嘛的”；引擎/上下文/思考强度是行话 |
| 设置 | 模型与渠道（6 个通道 tab）+ 更多设置（4 卡）+ 其他设置（环境安装/通知中心/员工角色卡） | 配置项与使用场景脱节，“环境安装/员工角色卡”像开发者页 |
| 高级项 | 88 处折叠块（多数是合理分层，少数是解释与行话的藏身处） | 折叠让新手不知道里面有什么；解释型折叠上一轮起已开始转 ⓘ 悬浮 |
| 术语 | 渠道（出现在 20 个组件文件）、回执（12）、产物（8）、网关（7），另有档位/准入/幂等 | 用户界面出现工程口径词 |
| 工作台首屏 | 标题 + 大输入框 + 快速按钮 + 统计 + 趋势 5 个区块 | 首屏不是“一个动作”，而是“五个区块” |

（另：统计/趋势等区域还用 6 处 `dash-more` 折叠；空态分散且详略不一，自动化页是现有做得最好的一处。）

## 小白化的五条原则

1. **渐进披露**：只先给最重要的选项，高级功能“应请求出现”（NN/g《Progressive Disclosure》：“Initially, show users only a few of the most important options. Offer a larger set of specialized options upon request.”）。
2. **每屏一个主行动**：首屏先让用户完成一件事（“今天想创作什么”），统计与趋势是回头再看的东西。
3. **场景词优先于功能词**：“我要发小红书”优于“图像工坊”；行话保留在 ⓘ 悬浮与设置里。
4. **默认值要健康**：模型/限额等安全默认已经做好（不改）；要砍的是“默认出现的入口数量”。
5. **空态教一次**：每个空页面三句式——这页干什么 → 三步怎么用 → 点这里试一条。

## 分层方案

### P0 · 语言与空态层（不动结构，低风险，建议先做）

- **术语白话表 + 全站用户文案替换**：渠道→“模型来源”、网关→“服务连接”、产物→“生成的文件”、回执→“处理结果”、运行记录→“任务记录”、画像→“账号人设”；档位/准入/幂等不出现在界面。术语原文保留在 ⓘ 悬浮与设置页。
- **解释型折叠清零**：延续上一轮 ⓘhover 的做法，把剩余解释型 `details` 全部转为 ⓘ；记录型折叠（验收与执行记录、触发历史、运行记录）保留。
- **空态统一模板**：以自动化页为范本补齐 选题/趋势/拆解/内容库/任务记录 等空页。
- **完成定义**：用户可见文案中行话为 0（可 grep 核对）；每个空页有三句式空态；界面截图前后对照。

### P1 · 信息架构层（动结构，见效最大）

- **侧栏收敛为 3+1**：**创作**（工作台，吸收生图工坊与视频——工作室内部已有模式切换）、**对话**、**任务**（定时任务+目标）、**更多**（技能库/内容库/内容分析/任务记录/账号/画像 按“常用/工具”两组）。Agent 办公室、拆解、趋势降级进“更多”。常驻从 13 个点击目标降到 4 个。
- **工作台首屏只留**：标题行 + 大输入框 + 3 个场景按钮（写文案 / 做卡片 / 口播脚本）+ 最近一条结果；统计与趋势收进“数据概览”一行，按需展开。
- **设置按频率重排**：模型与渠道（唯一高频）置顶；“环境安装/通知中心/员工角色卡”收进“高级设置”。
- **实验能力标注**：Agent 办公室、ClawHub 打“实验功能”标，避免被当主流程。
- **完成定义**：新手从打开到完成一次创作 ≤3 次点击；侧栏与首屏前后截图对照。

### P2 · 向导与场景层（新用户路径）

- **首次启动 3 步向导**：这工作台能干什么 → 选一个场景（内容创作/账号分析/自动化）→ 试跑一条预置任务；可跳过，不再出现。
- **场景模板**：文案/卡片/口播/选题预置提示词与默认参数，直达输入框（复用现有示例卡）。
- **定时任务向导化**：选场景 → 选时间 → 保存（现有表单默认值已就绪，只缺“一条路径”的成型）。
- **状态语言白话**：运行/需要处理/待验收 → “正在做 / 要你确认 / 等你检查”（悬浮保留原始状态）。
- **完成定义**：新人走查脚本（3 分钟完成第一条内容产出）可复现通过。

## 实施建议顺序

1. P0（纯文案与空态：零回归风险，一天内可见效果）；
2. P1 的“侧栏 3+1 + 首屏简化”做成可回退版本，配新手走查；
3. P2 向导放最后，依赖前两层稳定后的入口形态。

## 边界

- 本盘点基于 2026-10-17 的代码与 7880 实际页面；**未改动任何界面**，等待用户选择实施层。
- 简化不删能力：所有功能保留可达（更多菜单 / 高级设置 / ⓘ 悬浮），后端语义与既有安全边界（显式模型选择、fail-closed、停止屏障、预算上限）不变。
- “小白”验收以任务走查为准，不以截图观感为准；每层实施时沿用既有回归与浏览器验收流程。
