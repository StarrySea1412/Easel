# Easel 二次开发总方案（草案）

> 基线：2026-09-26，Easel `main` / `3fe2d99`（v0.2.1）。本文是实施方案，不代表功能已经完成。开工前重新同步上游并复核差异。

## 1. 目标与边界

面向首次使用 Easel 的个人创作者，交付四项可以独立验收的能力：

1. 基于**自己的小红书账号**数据，解释哪些内容主题和词语表现较好，并给出下一步选题建议。
2. 将 Skill 说明转成新手能理解的用途、准备材料、操作步骤和示例，同时保留原文入口。
3. 让 AI 服务配置支持服务商预设、获取可用模型并选中填入；可选择性地从本机已有配置导入。
4. 提供 Windows EXE 安装入口，显示进度、诊断和可恢复的失败状态。

不包含自动发布内容、抓取其他人的私有账号数据、绕过平台验证、无限重试安装、无提示复制凭证或把所有第三方依赖塞进单个离线 EXE。现有发布确认门禁保持不变。

## 2. 已核对的起点

| 领域 | 当前已有 | 关键缺口 |
| --- | --- | --- |
| 小红书 | `web/app.py` 的账号登录与 `/api/analytics/{platform}`；`account_stats.py` 能读取本人账号概览及近期笔记；`skill-xhs-analyzer` 已有 CLI 账号报告和关键词矩阵 | Web 的小红书近期笔记 `stat` 仍为空，CLI 报告未接入本人账号工作台；逐篇数据来源与建议证据尚未归一，也没有 Web 端小红书公域热榜 |
| Skill | `/api/skills`、`/api/skill/{name}`，以及 `SkillPage.tsx` / `SkillDrawer.tsx` 的检索、中文名称和原文展示 | 缺少统一的面向新手的任务解释与示例 |
| 模型 | `SettingsPanel.tsx` 可编辑六类通道，`web/app.py` 可保存配置并自测 | 缺少按服务商发现模型、选中填入和可审阅的本机配置导入 |
| 安装 | `setup.ps1`、`easel doctor` 及 Web 环境安装页 | 首次安装仍需脚本与交互；没有 EXE 发行包和整项目的断点恢复 |

事实依据见 [README](../README.md)、[贡献指南](../CONTRIBUTING.md)、[账号数据脚本](../skills/shared/scripts/account_stats.py)、[小红书分析 Skill](../skills/openclaw/skill-xhs-analyzer/SKILL.md)、[模型设置页](../web/frontend/src/components/SettingsPanel.tsx) 和 [安装脚本](../setup.ps1)。CC Switch 仅作为交互参考，不直接复制它的代码或账号凭证。

## 3. 功能设计

### A. 小红书本人账号热词建议

**用户路径**：在“账号”连接本人账号 → 选择数据实际覆盖的时间窗 → 查看笔记表现与候选词 → 查看每条建议对应的原笔记、指标和采集时间 → 将选中的建议加入选题库。

- 先做数据可得性验证：核对 `skill-xhs-analyzer/src/cli.ts` 已有 `account-report` 的逐篇点赞、评论、收藏、分享字段，确认账号归属、登录态及 Windows 可用路径；现有 Skill 依赖 macOS 的 `redbook`，不能直接作为 Windows Web 的数据入口。优先采用平台明确提供的本人账号数据或用户主动导出的数据；复用现有登录态读取本人创作者页面时保留节流、错误提示和人工验证边界。将“本人历史表现”和“公域趋势”分为两类来源，不合成一个模糊的热度分数。
- Web 当前只取最近 8 篇且标题最多 60 字，没有标签和发布时间。数据 PR 要验证分页、历史覆盖、完整标题、标签、发布时间及逐篇指标是否可得；只开放真实覆盖的时间窗。无法取得某字段时记录缺失原因，并让分析在较少字段下仍可读。
- 建立规范化记录：账号、笔记标识、标题/标签、发布时间、采集时间、指标及其时间窗、数据来源、缺失原因。复用被 Git 忽略的 `outputs/_analytics/`，增加逐篇快照的版本、去重及清理机制；默认本机保留最近 12 个月，并提供“清除分析历史”入口。旧账号汇总快照保持可读；采集失败标记上次成功时间为过期，不填零冒充实际值。
- 从实际可得的标题/标签提取候选词，合并同义词与停用词；有逐篇指标时按发布时间和曝光机会做可解释的比较。公域趋势词若有可靠来源，单独标来源与采集时间，再与本人账号主题匹配；没有逐篇指标或公域来源时，仅给出相应证据范围内的探索性建议，不声称某词能带来增长。
- 每条建议展示“为何建议、引用哪几篇笔记、数据时间窗、样本数、可信程度”；样本不足或指标缺失时明确降级。账号画像用于判断相关性，不替代实际表现证据。
- 后端分析与页面展示分层，复用 `account-report` 的数据模型与关键词矩阵方法，衔接 `account_stats.py`、`/api/analytics/{platform}` 和现有 Dashboard/选题入口；页面不直接运行抓取脚本或存储浏览器凭证。
- 选中建议后调用现有 `createIdea`：标题用候选选题，说明写入建议理由与数据时间窗，来源标为本人小红书分析，状态设为待做；按来源和标题检测重复，成功后可跳到选题库，失败时保留当前建议并提示重试。

**验收**：在模拟账号数据下，推荐词能追溯到原笔记和指标；分页/时间窗覆盖、逐篇快照去重与清理、缺失指标、过期数据、小样本、登录失效均有测试；选题写入、去重、导航和失败反馈可验证。单元测试不调用真实小红书。真实账号验证只在用户主动连接后进行，记录可复现的样本和字段，不把一次页面成功当作稳定接口承诺。

### B. 小白版 Skill 解析

**用户路径**：从技能库点开 Skill → 首屏看到“能做什么 / 适合谁 / 需要什么 / 具体怎么开始 / 会得到什么” → 可展开原始 `SKILL.md`、依赖和运行命令。

- 首版使用 `docs/SKILL-SPEC.md` 的 frontmatter、现有 Skill API 和正文标题做结构化提取；来源不够时显示“原文未说明”，不补造步骤、成本或平台权限。
- 为常见术语提供短解释和可复制的示例输入；根据是否需要账号、API Key、额外工具标出前置条件和可能费用。
- 可选的 AI 解释由用户点击触发，引用被总结的原文片段；模型不可用时静态摘要仍可工作。解释过程不能执行 Skill 内命令。
- 优先改进 `SkillDrawer.tsx` 和必要的 Skill API 返回结构，保留现有 Skill 文件格式、原文和搜索分类。

**验收**：抽样覆盖写作、图片、视频、发布类 Skill；原文缺字段有稳定回退；示例与真实脚本参数一致；未配置模型也能阅读核心说明。

### C. AI 配置的“获取并填入”

这里将需求拆成三种明确动作：**选预设填端点**、**从服务商获取模型列表并填模型**、**从本机已有配置导入候选项**。三者分别可用，用户始终在保存前看到拟修改的字段。

- 在当前六通道设置页增加服务商预设。预设只放公开的端点、协议和字段模板，不附带任何 Key 或声称所有服务商都支持同一接口。
- 对支持模型枚举的服务商，使用已填的地址和 Key 请求模型列表，展示返回时间、来源、失败原因和手动输入选项；没有统一模型接口时采用服务商适配器，不猜模型名。
- 可选“从本机配置导入”：只读取用户主动选择的 CC Switch / OpenClaw 配置，先展示来源、目标通道、协议兼容性和覆盖预览；OAuth 会话、刷新令牌及不兼容配置不导入。保存失败不改动现有配置。
- 复用 `web/app.py` 已有的 URL 校验、脱敏、配置写入和自测机制。模型发现接口需限制目标地址与重定向，避免服务端请求任意内网地址；Key 不出现在日志、异常或模型列表缓存中。

**验收**：预设、获取成功、401/403、404、不支持、超时、空列表、恶意 URL 和手动输入均有测试；保存后重开设置仍显示正确模型；导入只在预览确认后写入，且能保持原有未选择的配置。

### D. Windows EXE 安装与有限重试

**用户路径**：运行安装器 → 检查系统及已有 Easel → 展示待安装组件、路径与空间 → 分阶段安装 → 配置模型 → 运行 `easel doctor` → 给出启动入口或清楚的修复步骤。

- 先把 `setup.ps1` 中的检查、依赖下载、虚拟环境、前端构建、Chromium、Skill 同步、OpenClaw 配置与验证拆成可重入阶段，提供无交互参数及结构化阶段结果；交互式脚本继续作为开发者入口。统一 README 与脚本的 Node 版本要求，固定发行版使用的 OpenClaw 和 Python 依赖版本；前端构建使用锁文件及 `npm ci`，把构建产物装进发行包。
- 首版 EXE 是在线引导安装器：内置 Easel 版本及发行包 SHA-256，从该版本的官方 Release 下载源码/预构建前端归档，校验后解压到 `%LOCALAPPDATA%/Easel/versions/<version>`，再运行同一安装核心。用户无需先 `git clone`。后续升级按版本并排安装，验证成功后切换启动入口；失败保留旧版本。
- 当前 `.env`、`profiles/`、`outputs/` 和登录态依赖源码根目录。安装核心要先支持独立、持久的用户数据目录（默认 `%LOCALAPPDATA%/Easel/data`），验证从已有仓库安装迁移时不覆盖账号、配置和产物；升级前备份受影响的数据。开发者直接运行源码时仍可沿用原目录。
- EXE 展示阶段进度、日志路径、当前失败原因和“继续/重试”操作；不会静默反复改写 PATH、profile 或已有配置。发行包保留各第三方许可证；签名发布取决于是否有可用证书。
- 只对网络断开、下载超时和包源暂时不可用等临时故障自动重试，最多 2–3 次并逐次延长等待；每次先检查该阶段是否已成功。权限不足、版本不兼容、配置无效、构建错误和路径冲突应停在具体阶段并保留可恢复状态。
- 首次发行先证明在线安装可复现；离线包和代码签名是独立后续工作，签名发布以有可用证书为前提。安装完成后运行 `easel doctor`，Web 可启动及页面可访问才标记成功。

**验收**：干净 Windows 虚拟机无源码全新安装、发行包校验失败、断网重试、半途退出后继续、已有安装升级与旧版可回退、现有用户数据迁移、安装失败后修复均通过；日志不含 Key；同版本重复执行不重复安装已满足的组件。

## 4. 分支、Issue 与 PR 顺序

当前方案放在本地 `docs/secondary-development-plan` 分支，先供审阅。正式贡献遵循 [CONTRIBUTING.md](../CONTRIBUTING.md)：先查重并提出功能 Issue；若上游允许，再从最新 `main` 建功能分支，一个 PR 只做一件事。没有上游写权限时，在自己的 fork 中开同名分支并向上游提交 PR。不要把四项功能堆在一个长期分支。

| 顺序 | 建议分支 / PR | 可独立交付的结果 | 合并前关口 |
| --- | --- | --- | --- |
| 0 | `docs/secondary-development-plan` | 本方案及数据可得性问题清单 | 上游方向、范围和许可证边界确认 |
| 1 | `feat/skill-guide` | 静态新手摘要、示例与原文入口 | 技能抽样、字段缺失回退、前端构建 |
| 2 | `feat/model-discovery` | 服务商预设与可用模型获取/填入 | 协议适配、URL/Key 安全与失败回退 |
| 3 | `feat/model-config-import` | 本机配置的选择、预览和导入 | 不读取或覆盖未授权配置；兼容性测试 |
| 4 | `feat/xhs-account-data` | 本人笔记字段、实际时间覆盖、逐篇快照与清理 | 来源可复核；登录失效、限速、历史覆盖及隐私测试 |
| 5 | `feat/xhs-keyword-insights` | 带证据的词语表现、选题建议及入库 | 小样本及缺指标降级；选题去重与人工样本核对 |
| 6 | `feat/installer-core` | 可重入的 Windows 安装阶段、数据目录迁移和诊断 | 版本矩阵/锁定依赖、重复执行、断点恢复及有限重试 |
| 7 | `feat/windows-installer` | 固定发行包的 EXE、发行流程、安装日志和启动入口 | 无源码干净 Windows 虚拟机安装/升级烟测 |

第 2、4、6 项可以并行开发；第 3 依赖第 2 项的配置模型，第 5 依赖第 4 项的数据契约，第 7 依赖第 6 项的安装核心。任何阶段都不以“页面有按钮”替代端到端验收。

## 5. 共同完成标准

- 后端与 Skill：运行 `python scripts/validate_skills.py`、`python scripts/validate_skill_commands.py`、`python -m pytest`；增加针对新数据契约、配置安全或安装状态机的定向测试。
- 前端：在 `web/frontend` 运行 `npm run lint` 和 `npm run build`，检查空状态、失败状态和窄屏阅读。外部模型、平台与安装测试使用模拟输入；真实连通性另做明确标注的手动验证。
- 安全与隐私：`.env`、Cookie、OAuth 会话和真实账号数据不提交 Git；本人账号分析快照仅存在本机、可清除并按保留期裁剪。外部数据读取以本人账号或用户主动提供的数据为界；任何保存、覆盖或发布行为都由用户明确触发。
- 文档：每个 PR 更新对应用户说明、测试方法和已知限制；引入第三方素材/代码时在 `docs/ACKNOWLEDGMENTS.md` 登记来源和许可，保留各自许可证。
- 交付记录区分“已实现并自动测试”“已人工验证”“尚依赖平台/服务商”的状态；不能以模拟测试通过宣称真实小红书或模型服务稳定可用。

## 6. 开工前需要确定的事项

1. 小红书本人账号能稳定取得哪些逐篇指标、时间窗和导出格式。若无法取得曝光等分母，首版只做有依据的内容主题回顾与探索性建议。
2. “像 CC Switch 一样”是否还包括直接读取其本地配置；默认先交付服务商预设和模型获取，把跨应用导入作为单独 PR。
3. EXE 首版是否接受联网下载依赖；默认采用在线引导安装，以降低发行包体积和更新成本。
4. Windows 发布是否已有代码签名证书；没有时先做可验证的测试版，不宣称已签名。

以上事项影响后续范围，但不阻碍先启动 Skill 新手说明、模型预设和安装核心的独立开发。
