# 0.50.5 · 模型导入与测试体验修复

## 用户要求与范围

2026-11-13用户反馈：“模型导入和测试体验，真的是太糟糕了！”本轮检查现有设置页的来源读取、替换保存和实际模型检测，按兼容修复递增patch至0.50.5。没有替换执行引擎、自动重启网关或更新138。

## 查到的问题与调整

1. **导入入口缺少定位。** 打开导入后滚动并聚焦到原导入面板，避免停在供应商列表找不到下一步。说明来源文件位于运行Easel的设备，服务器看不到用户电脑上的本地配置；支持按渠道、模型和地址筛选候选。
2. **覆盖内容没有显示。** 后端已返回覆盖预览，旧页面没有展示。空通道仍可一次导入并保存；已有通道先展示当前/导入的地址、模型及脱敏Key，再确认替换。取消不保存，目标通道草稿的替换范围明确，其他供应商草稿保留。确认时展开列表高度，避免手机内层滚动裁切操作。
3. **导入完成与测试脱节。** 成功后展示刚保存的模型，提供“测试刚导入的模型”和“查看供应商配置”。导入本身不触发推理；测试使用该次保存的精确provider/model。后续修改该配置时，旧成功结果隐藏，旧导入卡片禁止测试已变化的目标。剩余候选按“条配置”计数，不再冒充模型总数。
4. **“测试”可能先保存但未说明。** 未保存目标标成“保存并测试”，只保存该供应商，保留其他草稿。保存失败在折叠卡片外也显示原因，并明确尚未发送模型请求；保存不等于测试通过，测试也不等于运行中网关已加载配置。
5. **等待和回执不完整。** 显示已等待秒数、停止等待、实际响应预览及耗时；响应按普通文字展示并限制长度。停止等待只终止浏览器等待，服务端/供应商可能继续完成，不能承诺取消费用；晚到结果不会覆盖取消状态或当前新配置。
6. **错误与限流反馈不足。** 对鉴权、权限、地址/模型/协议、网络/代理、超时和无效响应分别给出下一步，不回显供应商私有错误体或Key。工作台共享限额429显示全局倒计时；供应商429仅暂停对应供应商。倒计时结束后需手动重试，没有自动重放或降低原每60秒2次限额。
7. **读取可能永久等待。** 来源探测、只读预览和模型列表发现分别在15/20/35秒内结束等待并中止传输。测试覆盖忽略abort的传输和晚到响应；这些读取没有写入配置。导入保存仍沿用预览指纹、十分钟有效期和源/目标变化校验，不把客户端停止等待当成撤销服务端写入。
