# 对话渠道请求协议设置 · 0.3.1

2026-10-19，修复用户指出的“没有自动路由，也没有协议设置入口”。本轮提供手动协议配置，不按供应商名称猜测协议，不在失败后换协议重试。

## 使用方式

设置 → 模型与渠道 → 对话与脚本 → 编辑供应商、协议、地址与密钥 → 展开渠道 → 请求协议。

- **OpenAI Chat Completions**：使用渠道 Base URL 下的 `/chat/completions`，Bearer 鉴权。
- **Anthropic Messages**：使用 `/v1/messages`（Base URL 已以 `/v1` 结尾时追加 `/messages`），`x-api-key` 与 `anthropic-version` 鉴权。
- 选择后仍是草稿；点击“保存并使用”写入配置，刷新后回读保存值。模型列表采用当前草稿协议，真实测活和后续 OpenClaw 请求采用已保存协议。
- 本地模型网关管理的渠道显示协议及说明，在网关配置中修改上游协议；面板不提供假生效的覆盖。无法识别的现存 API 保留原值显示，必须明确选择支持项后才能保存，不静默改成 OpenAI。
- 原生 Responses 不是本次新增支持项。协议选择不证明该地址、模型与密钥支持相应协议，仍需以服务商接口说明及执行回执为准。

## 原因与修复

原前端仅在 `custom` 卡片显示协议选择；内置 `openai/anthropic/relay` 的保存和模型发现还按槽位名限制协议。现在所有可编辑对话渠道复用共享 Select；内置和自定义均从所选模型/供应商实际 API 回读，旧配置缺省才沿用历史默认值。

保存写入 OpenClaw `models.providers.<provider>.api`，清理所选模型遗留的 API 覆盖，避免 provider 已变而模型继续走旧协议；其他渠道不改，其他模型的显式覆盖保留。旧客户端未传协议时保留当前协议。导入兼容检查改为对照当前保存协议。

模型发现不再按槽位拒绝显式选择；自定义渠道发送实际供应商身份，以读取准确的已保存 Key/Base URL。协议变更清理旧列表和迟到结果；未保存配置仍阻止使用旧配置测活。批量模型列表检查按保存协议选择路径与鉴权头。原换地址需重填 Key、SSRF、禁止重定向、限流和保存失败回滚保护保留。

390px 检查还修正了紧凑卡片标题与快捷操作争抢宽度的问题：窄卡标题改为网格、状态单独横排、快捷按钮另行显示，字段维持单列。
