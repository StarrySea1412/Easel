## 从哪里使用

后续按用户截图纠正为[当前对话目标模式](conversation-goal-mode-2026-10-16.md)。本文下方的95/1048测试数是首版历史快照，最新纠正的专项及浏览器证据见新记录。

本机工作台：`http://127.0.0.1:7880/`。在当前对话输入 `/` 或 `/goal` 设置目标，右侧紧凑面板持续显示目标/真实步骤/耗时和暂停；左侧时钟入口改为“定时任务”。刷新后工具栏与会话列保持折叠。当前工作台没有管理员认证，本轮没有新增账号系统。

1. 当前对话输入 `/goal`，写目标正文，核对执行模型和折叠的执行上限；“仅保存”不执行，“设置并开始”才启动。无需跳转管理页或再选择结果对话。
2. 文件及其本地依赖按真实字节核验，文字标准检查当前轮输出；内容与视觉质量选择“由我验收”。自动项通过后等待用户确认，不能由模型自行宣告质量通过。
3. 每轮结果和产物留在对应对话，显示目标来源及轮次。复用已有图片、HTML预览、下载和刷新机制；刷新读取已保存文件，不触发重新生成。
4. 点击停止先持久化暂停状态，再请求停止精确会话/轮次；后台未确认结算时保持占位，不能重复启动或抢占发送消息。恢复保留累计轮次、时长、工具和生图预留。
5. 新建计划支持单次、固定间隔、每天、工作日和每周，提供时区及下三次预览。保存为暂停状态，需要明确启用；编辑前先暂停。立即运行一次不改变原周期，触发历史可回到对应对话。

目标首版使用支持原生运行身份回执的 OpenClaw；Codex 普通对话保留既有执行路径，尚未提供 Codex 目标模式。包含服务端目标记录的对话暂用归档收纳，删除入口会明确提示；归档不会停止目标或计划，请在任务界面分别停止。

## 执行与持久化

| 对象 | 实现及语义 |
| --- | --- |
| 目标 | SQLite持久化目标、验收证据、状态、累计限额；同会话仅一个非终态目标；完成/取消后保留历史 |
| 计划 | 时间规则、启停、模型配置快照、漏跑处理、最近100次触发记录；编辑保留历史 |
| 运行 | 每轮独立turnId、worker身份和租约；`BEGIN IMMEDIATE`与唯一约束保证跨进程认领不重复 |
| 原对话 | 服务端保存目标说明和assistant交付；前端按turnId合并，不替换已有标题、用户消息、草稿或导入备份 |
| 调度 | Easel为唯一调度权威，不向OpenClaw重复注册cron；单个服务进程首版串行执行自动目标 |
| 漏跑 | 默认跳过过期周期；可选15分钟内最新周期合并一次，不补一串积压；夏令时缺失时刻跳过、重复时刻一天只运行一次 |
| 人工接管 | 轮次间人工发送先暂停自动推进；正在运行或结果未知时，需先停止并确认结算 |
| 重启与未知 | 失去worker租约的运行转为待核实；仅从既有运行账本正面结算，不自动重发。无法确认的记录可能持续阻塞，需要核查执行器 |
| 停止屏障 | stopEpoch、revision及owner检查拒绝过期结果续跑；已停止目标的排队生图不再提交供应商 |
| 自动验收 | 文件内容哈希包含HTML/CSS本地依赖；文件变更撤销旧质量确认；核验异常停止，连续两轮无新证据停止 |

数据库位于项目数据目录的 `outputs/_automation/tasks.sqlite3`。保护作用域位于其 `scopes` 子目录，自动化私有路径禁止通过产物/媒体接口访问。管理页展示最近300个目标、200个计划、500轮记录及最近300个任务会话；这些显示上限不限制到期计划调度。原对话查询先按会话筛选，避免其他对话历史将其挤出窗口。

后端存活时浏览器可关闭。电脑休眠、后端退出时不会继续工作；恢复后执行漏跑规则。未新增系统服务安装器、后台常驻托管或跨设备同步。

## 模型与限额的真实边界

- 必须明确选择已配置模型，不静默回退；创建时冻结配置哈希，每轮重新核对。配置变化会阻断，需重新建立目标确认配置。
- 原生网关工具保护必须就绪且数据目录匹配；启动只读检查不调用模型。工具调用由可信会话和provider runId匹配，不接受模型参数冒充身份。
- 默认最多5轮、1200秒、40次工具、0张生图；可配置上限20轮、7200秒、200次工具、16张图。默认关闭付费生图，图片按n张预留；幂等重试不重复计数，失败预留也计入。
- 时长达到阈值会请求停止，外部执行器或供应商不保证即时中断；未知结果继续占位，不把本地超时冒充取消成功。
- 子Agent、嵌套cron、跨会话派发和网关修改工具在目标执行中被拦截。工具上限不是Shell沙箱；不能承诺阻断Shell内部所有外部调用。
- **Token及金额不提供硬封顶**。本轮没有接入供应商余额/实时账单或逐请求价格预扣，不将执行限额描述为金额预算保障。普通聊天用量账本继续沿用既有能力。
