## 原因与修复

- 旧实现只查 `agents/main/sessions/sessions.json`。当前隔离运行时已经使用 `agents/main/agent/openclaw-agent.sqlite`，前者不存在，导致实际记录被遗漏。现按本项目会话标记，只读查询匹配会话的 `session_nodes.entry_json`；SQLite 为迁移后的权威来源，不回填已删除会话的旧 JSON。旧版 JSON 仍兼容。
- 旧分类要求总占用及全部分类字段同时齐全，任意字段缺失会抹掉全部分类。现在逐项展示已知字符数、估算 Token 和来源；只有完整且一致的报告才计算消息余量，未知项保留未知。估算开销超过总量时保留原始字符数、停止计算占比，不强行归一化。
- 技能区同时区分本项目已安装数量、会话技能快照记录数、当次运行报告列出的目录项数。会话 `skillsSnapshot.prompt` 存在时可直接统计目录字符数，即使模型尚未返回总占用；字符统计遵循运行时的 UTF-16 计数约定。没有会话快照的新会话仍显示本机技能数量。
- 模型切换后保留带模型名称的上次会话总量，单独显示，不沿用旧模型占比。所选模型没有配置容量且无匹配运行时容量时继续引导设置，不从名称猜测上下文窗口。

技能目录与按需读取的 SKILL.md 正文不同。目录是系统注入的索引；读取后的正文、参考文件与其它工具回执继续属于消息上下文，不把所有已安装技能全文重复加入。这里的字符数是已记录值，Token 分类仍按字符数÷4粗估，尤其中文、代码及不同模型的分词会有差异；它不等于供应商实际分词或账单。原有累计消耗、缓存计价与费用弹窗保持独立。
