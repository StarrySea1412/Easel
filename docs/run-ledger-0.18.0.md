# Easel 0.18.0 候选：事务运行账本与恢复游标

更新：2026-10-26。基于 `f5eae40f`，继续完整大版本的P0-R；不部署138、不发布安装器、不调用付费模型。

## 本批行为

普通OpenClaw聊天的同一逻辑轮次，现在通过SQLite事务首次受理，读取旧记录和建立新记录不再分离。重复提交返回已有运行/终态冲突，不能再次进入后续产物登记或模型派发。已受理仅证明本机登记成功，不等于供应商接受、完成或已收费；本轮没有验证供应商真实计费。

运行状态与生命周期事件一起提交，多个进程追加事件不会互相覆盖。快照仍保留最近200条，新的游标接口可分页读取本版保留的全部生命周期事件。已结算终态及SSE游标保持单调，迟到运行状态不能把已停止/完成的记录改回运行中。比较修订号更新可拒绝基于旧快照的写入。

已有聊天SSE回放仍使用原JSONL内容日志：逐行独立解析，单条损坏不丢弃周围有效内容；未完成JSON/UTF-8末行下次重读，合法但缺末尾换行的旧终态仍可读取。该内容日志与生命周期事件的游标是两个不同序列，不能互相比较或替代。

异步接口及任务服务的账本读写移到工作线程，避免数据库等待直接阻塞服务事件循环；同步回调仍按原顺序处理。

本批不增加界面说明块、按钮或嵌套卡片；保留0.16.0紧凑目标工具栏和0.17.0会话删除行为。

## 存储与接口

- 位置为活动会话目录内的 `ledger.sqlite3`，通常是数据目录 `outputs/_sessions/ledger.sqlite3`。存储结构使用 `PRAGMA user_version=1`；运行快照的既有 `schemaVersion=1` 是另一份数据契约。
- `runs` 保存轮次快照，`events` 保存按turn/seq唯一的生命周期事件，`legacy_snapshots` 保存导入原始字节、SHA-256与时间；只保存既有身份及生命周期信息，不新增提示词、正文、凭据或工具参数存储。
- 旧 `runs/<turn>.json` 首次读取或受理时按需导入，原文另存于数据库；没有整包扫描或清空历史。数据库已有记录后成为事实来源，旧JSON只作为兼容投影。损坏/不支持的旧记录和未来数据库版本不作为新请求受理。
- 新写入仍尽力更新兼容JSON；投影由同一数据库写锁串行导出最新快照。投影文件失败不抹掉已经提交的受理事实；没有完整的投影失败自动重试队列，降级前必须单独检查投影。
- `GET /api/chat/runs/{turnId}` 返回当前快照；`GET /api/chat/runs/{turnId}/events?after=0&limit=100` 返回事件、next/revision/hasMore、firstAvailableSeq及historyTruncated。两者均no-store。只读接口不创建模型请求。
- 旧JSON只保留了最近200条时，导入明确报告前部缺口，不补造丢失历史；新数据库也没有把旧SSE正文、工具记录或Codex原生条目整包迁入。

## 升级、备份与回退

升级前停止旧服务写入并备份整个数据目录，保留会话、JSON/JSONL、文件、任务数据库与认证配置。在隔离副本验证后再切换；本轮只更新本机隔离7891。

`web.run_ledger.backup(root, target)` 使用SQLite在线备份API，核对目标数据库quick_check，并拒绝覆盖已有目标。它只备份已导入的运行数据库，不代替整个数据目录备份。原文可从备份的legacy_snapshots核对，未导入旧文件仍须随数据目录一起保存。

不混跑新旧写入器：旧程序不知道SQLite是事实来源。回退前先停写、保存当前完整快照、核对JSON投影与数据库修订一致，再在隔离副本演练旧程序读取；没有自动回退/清库命令。恢复升级前备份会丢失之后的事件与其他变更，不能静默执行。本批schema机制只适用于运行账本，不代表全系统迁移与回滚框架已完成。
