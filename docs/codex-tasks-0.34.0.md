# Codex 目标与定时计划 · 0.34.0候选

2026-10-27。Codex 对话原先只能普通聊天和核对失联结果，现在可以创建目标，或在定时任务编辑器选择 Codex。计划保存为暂停状态，显式启用或手动运行后才派发；模型来自后端主机实际的原生模型列表，不回退到其他引擎或模型。

## 执行契约

- `engine=openclaw/toolBudgetMode=admission` 为旧记录的默认值。Codex 必须明确记录 `engine=codex/toolBudgetMode=observed`，并选择 `codex/…` 模型。会话引擎、模型、配置摘要不匹配时拒绝派发，编辑并保存计划后才接受新配置。
- Easel 是唯一轮次和角色调度者，复用现有顺序阶段、固定并行图、结构化规划、一次自动返工、累计预算及人工验收。原生 goals、multi_agent、multi_agent_v2、image_generation 和 memories 在任务线程配置中关闭；保留原生安全 hooks，启用的可信/受管理 Stop 或 SubagentStop hook 会导致任务拒绝启动，避免另一个续跑循环。
- 原生工具 started/completed 事件按原生轮次与调用 ID 幂等计数；达到观察上限请求中断，已发出、并行或晚到的操作仍计入真实消耗，可能超额。它不提供原生工具的执行前硬封顶。Easel 动态工具继续经过 TaskStore 准入，图片沿用累计图片预留。原生计划更新映射步骤，不等于质量通过。
- 原生完成和资源结算分开：客户端关闭、浏览器操作及图片任务均结算后，才核验文件和推进后续阶段。取消/暂停/删除和版本栅栏阻止晚到交接与自动续跑；未知运行只读核对原线程、原轮次，不能重发，也不重放交付或审批。

## 文件交接

工作会话使用原生 session workspace，不构成操作系统权限隔离。上游仅复制已核验且版本一致的声明文件与本地依赖。任务在工作目录按验收条件的相对路径保存文件，调用 `easel_task_deliver`，宿主核对原轮次、阶段、目标修订和停止版本后复制到共享证据目录。不能借依赖覆盖其他阶段证据。

原生旧线程恢复协议不支持添加动态工具，故保留命令输出标记 `EASEL_TASK_DELIVER {"files":[{"path":"声明的相对路径"}]}`；该路径仍通过同一校验。普通 `easel_present` 仅展示文件，不能代替任务交接。一次交接最多16个声明文件、含依赖最多64MiB；每个文件临时写入后替换，不声称整个文件系统事务原子性。共享证据目录应由单一受信后端管理。

## 升级与回退

产品版本单一来源为 `pyproject.toml`，前端构建与后端必须使用同一固定提交。任务记录增加可选引擎/预算模式，旧记录无需迁移。回退前暂停全部 Codex 计划，等运行资源结算；旧版本不理解原生目标，不应继续调度此类记录。保留数据和备份，恢复新版本后重新核对原运行，不通过清数据库恢复执行。

本机协议基于 Codex 0.147.0，参考已读取的[App Server 文档](https://learn.chatgpt.com/docs/app-server)和[Hooks 文档](https://learn.chatgpt.com/docs/hooks)。原生安全 hook 的任意失败不能视为确定阻断，因此没有用它冒充工具硬上限，也没有取消用户对 hook 的信任要求。

Windows 状态读写共用进程内锁，防止读取时替换状态文件失败。OpenClaw 保护辅助进程冷启动实测约7秒，原5秒期限会误拒；改为20秒有界等待，外层 hook 22秒，失败仍拒绝执行。
