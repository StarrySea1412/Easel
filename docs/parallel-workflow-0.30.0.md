# Easel 0.30.0候选：依赖图与并行角色

2026-10-26，继续完整竞品对标与大版本目标。本批实现固定依赖图的双前置分支及汇合，完整动态层级调度和真实模型质量评估仍未完成。

## 行为与范围

目标工具栏新增紧凑“并行协作”选项，对应独立协议`parallel-reviewed-delivery`：研究依据与约束验收并行，二者文件都核验后进入制作→结构化审查→整理交付→人工验收。旧`reviewed-delivery`、`research-delivery`和自定义顺序阶段继续原行为，不隐式迁移。

每阶段有稳定的内部工作会话与独立轮次、角色、步骤和回执。原TaskService和SQLite事务统一认领，同一目标最多两个未结算运行；工具仍不能派生Agent、创建嵌套计划或修改网关。阶段提示带入明确总目标、验收条件、预算及依赖祖先的交接材料，不自动复制父对话完整历史。制作阶段可实现用户目标中的实际产物，只有两个前置分支被要求只写自己的交接文件。

内部会话隔开运行上下文和身份，不是操作系统或文件权限沙箱；工作文件仍在同一数据目录。固定图只让两个前置角色并行，其余阶段按依赖推进。同渠道的现有供应商队列可能继续串行处理模型请求，不能据此保证供应商侧并发或缩短真实耗时。

工具和图片预算按目标累计；时长按各运行累计执行秒数计算，同时运行的时长相加。认领时分配并预留剩余时长，两个初始分支各取得一半可用预算，结算后归还未使用部分，后续阶段使用剩余额度。不是每个角色各有一份总预算；停止待确认仍保留占位，不分配新阶段。

暂停、取消、删除、失败和未知运行阻止下游派发，停止使用实际工作会话与turnId；删除父对话也屏蔽子会话晚到更新。已经确定的失败原因不会被另一个分支晚到的结算覆盖。外部运行/图片资源未确认时不冒充停止完成，也不自动重发。

## 返工与页面

指定阶段重做、结构化审查和一次自动返工沿用现有服务。新图仅重置所选节点及依赖后继：重做研究时保留已核验的约束分支、其文件证据、尝试次数和原回执。所有已完成分支均重新核对文件版本，即使它们在数组中不连续。事务同时保存旧回执、递增revision和重置依赖状态；累计轮次、工具、图片、时长和自动返工次数不清零，不恢复工作文件的历史字节。

阶段列表显示等待上游、阶段独立步骤和多阶段执行数量；细节仍折叠，不新增常驻说明卡片。重做确认只列实际受影响阶段。最终人工质量确认独立保留，模型建议通过与文件核验不能替代它。

任务执行记录中的核验和办公室入口使用实际工作会话。两页面从任务回执临时派生检查目录，工作会话不进入侧栏或持久聊天列表；返回对话指向父对话，内部工作会话没有另发任务的编辑入口。缺少真实模型/工具记录时保留未知或无记录，不根据合成阶段补造Agent证据。

## 升级与回退

产品单一版本来源`pyproject.toml`、前端包及锁文件同步0.30.0，前端构建读取产品版本。沿用原任务SQLite表；目标JSON增加新workflow和dependsOn，运行增加parentSessionId、maxRunSeconds与独立steps，阶段保留独立steps及turnId。内部会话使用独立scope标记；旧记录无这些字段仍兼容。没有通用用户可编辑DAG或新增操作系统进程隔离器。

升级前暂停排期、结束并核对在途运行，停止写入后备份完整数据目录、一致SQLite快照、scope和工作文件；前后端从同一提交构建。旧程序不理解新并行协议，不得与新版共用可写数据。回退使用升级前配套程序、数据及工作文件备份；只回退任务数据库不会恢复旧工作文件。本批不自动部署138或发布安装器。
