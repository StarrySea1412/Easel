# 社媒发布回执与提醒（2026-10-08，R25）

用户要求：内容发布到小红书、B站等平台后，自动提醒并附作品链接。本轮补齐 Web 发布页的持久回执、跨页提醒和可选邮件，修正把上传结束、提交审核和公众号草稿混成“发布成功”的行为。不同平台能提供的凭据不同，不能据此宣布全平台自动发布已经验收。

## 如何使用与验收

1. 在「发布中心」准备内容并确认发布。工作台顶部「发布回执」会保留处理进度；需要短信验证的任务可从该入口继续处理。
2. 平台确认公开后，回执显示「已发布」及平台提供或由已验证作品 ID 生成的公开链接。切页或刷新后仍可查看；没有可信地址时会明确提示，不生成猜测链接。
3. 「已提交」「草稿」「待核实」「失败」分别展示。已提交不等于审核通过；待核实应先到平台确认，避免重复发帖。只有已发布回执才写入已发布日历。
4. 希望收到邮件时，在「设置 → 通知中心」配置收件人和 SMTP，开启自动通知并保存。未开启时只使用站内回执；手动测试邮件仅验证邮箱设置，不代表真实发布成功。
5. 发布成功邮件包含回执编号；有可信公开地址时附作品链接，否则明确说明未取得地址。排队、已交给 SMTP、失败独立显示。SMTP 接受不保证收件箱送达，仍可能被邮件服务拦截或进入垃圾邮件。

站内提醒在工作台打开时更新。后端运行期间，离开发布页面不会主动取消执行；关闭整个工作台服务会中断后台任务。重启后，未完成任务改为待核实，排队邮件改为发送结果未确认，不自动重新发布或重发。

## 本轮平台范围

| 平台 | 公开成功的判断 | 当前限制 |
| --- | --- | --- |
| B站 | 上传前作品快照、上传后读回匹配新作品；状态明确公开且 BV 号有效才显示成功并生成作品链接 | 首次读回仍审核中时显示已提交；无读回、未知状态或仅 AV 内部号时待核实 |
| 抖音 | 作品读回明确公开、合法作品 ID；区分视频和图文地址 | 审核中/定时发布只报已提交；私密和未知状态不能报公开成功 |
| 快手 | 作品读回明确公开且作品 ID 有效；仅可分享的作品 ID 生成公开链接 | 有效的内部数字 ID 可对应已发布结果，但不猜成公开 URL；没有可信地址时说明缺失 |
| 知乎文章 | 发布操作后观察到精确的公开文章 `/p/<id>` 地址 | 本次未验知乎回答的独立 CLI 发布链路 |
| 小红书 | 当前只能根据提交提示或表单复位确认已提交；不明确时待核实 | 现有作品列表能取得 ID/标题/日期，但缺少经实际样本确认的公开/审核/私密状态解析，**尚未完成发布后附作品链接的闭环** |
| 视频号 | 提交提示只报已提交，其余待核实 | 尚无公开作品读回和稳定公开 URL |
| 微信公众号 | 成功创建草稿显示草稿 | 当前接口没有代替用户在公众号后台正式群发，不发送公开发布成功提醒 |

审核后自动转为公开的持续回查尚未实现。已经提交的任务不会仅因时间过去而升级为已发布；审核较久的平台需要到平台查看结果。既有定时队列的执行命令仅派发发布计划，不是独立常驻的自动发布执行器。

## 回执与恢复边界

- 回执存于当前产出目录的 `_publish/receipts.json`；默认产出目录位于数据目录的 `outputs`。页面默认读取最近 50 条，接口最多选择 200 条历史，活动任务另外保持可见。状态读接口不重新发布或发邮件。
- 每次任务有独立随机编号、进度及短信文件；同平台已有活动任务时拒绝重复启动。验证码只提交给当前对应任务。
- 公开成功须来自版本匹配、平台与任务编号匹配的结构化回执，退出码 0、日志文字和用户正文中的地址不是成功证据。
- 公开链接在脚本、后端及前端校验平台与路径，拒绝平台控制台、伪造域名、非 HTTPS 和携带认证字段的链接。
- 平台执行结果与邮件结果分开保存。存储故障时保留当前进程已知结果并显示警告，不能承诺该结果在服务重启后仍能恢复。
- 成功邮件按回执编号去重，不再让 60 秒内发布的不同作品互相吞掉；已安排的任务不自动重发。
- 直接运行技能 CLI 会输出结构化回执；本轮常驻站内与持久邮件状态接在 Web 发布页，不能将 CLI 或队列派发当成同一链路已经验收。

## 验证记录

本轮使用隔离数据和模拟的平台响应，未登录或代发用户内容，未向 SMTP 发信。前端重新运行 **697/697**、lint、TypeScript 与生产构建通过；原有 Three.js 大块提示保留。发布脚本、后端、邮件、记录存储与便携启动器联合回归 **258 项通过**（含脚本 102 项及启动器 39 项，不重复相加）。五个既有脚本自检通过，B站自检所在 shell 没有 `biliup`，上传依赖在便携运行环境另验。

独立审查已复现并修复自动邮件关闭不生效、最终邮件状态保存失败后被列表隐藏两个问题。另收紧发布读回：缺少可靠时间或出现同标题歧义时待核实；空快照仅给 1 秒时间精度容差，避免将此前旧作错当本次成功。Windows 嵌入 Python 的重定向输出实际复现 GBK 编码失败，六类 Python 发布入口改用显式 UTF-8 模式。

联合回归后最后校正了内容清单的通知接线：只有显式进入 `ready` 才提醒生成完成，重复状态或手动标记 `published` 不发送发布成功邮件。该追加改动另跑邮件模块 **32 项通过**，不与联合回归重复计数。
