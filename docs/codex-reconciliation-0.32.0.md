# Easel 0.32.0候选：Codex原生结果核对

2026-10-27。本批延续完整项目对标和大版本目标，只覆盖Codex后端重启后的结果核对；不是138部署、安装器发布或完整目标结项。

## 行为

通过本机App Server `thread/read`及`thread/turns/list`只读检查原生线程。新建线程历史使用完整轮次分页读取；旧线程读取完整`thread/read`历史。核对绑定线程ID、工作目录和确切原生轮次ID，只接受完整items及`completed`、`interrupted`、`failed`状态。执行中、空页、分页异常、摘要视图、标识缺失/不符、协议异常均维持`unconfirmed`，保存最近一次核对原因，不释放待处理状态或解除会话发送屏障。

明确原生终态后，将回复、摘要、工具记录、耗时和失败/中断状态投影到原Codex轮次；不把历史重放进事件消费处理器，避免再次审批、调用动态工具、生成图片或交付文件。不`thread/resume`，不接管活跃执行、不派发新轮次，也不把最终文件系统状态冒充工具回执。重复核对幂等。

对同一会话，跨进程排他锁覆盖运行启动、Codex及浏览器资源清理、服务重启时的未知状态标记、结果核对与线程绑定。所有历史未结算轮次都参与发送屏障，较新的`lastTurnId`不能覆盖旧未确认轮次。浏览器刷新或核对HTTP响应丢失后，前端观察到已持久化的恢复回执，会将原结果更新至该轮助手消息；不匹配的会话/轮次和已删除会话不被改写。

界面只在既有Codex执行行提供“核对结果”，恢复后显示短状态和原始回复。Codex goal runner仍未接通预算、工具权限及控制契约。

## 升级与回退

产品版本从0.31.0候选升至0.32.0候选，`pyproject.toml`与前端包/锁版本同步。应用使用原本地Codex JSON/JSONL记录，无新增数据库迁移；每个Codex会话新增操作系统释放锁文件。共享数据目录需允许服务账户创建及锁定此文件，不能清理锁文件来绕过正在执行的会话锁。不要并行运行不同版本服务读写同一数据目录。回退需先停止新旧实例，再按原有应用与数据备份流程回退；锁文件可留存，持锁进程退出后由操作系统释放。

完整大目标仍继续；138和安装器不自动更新。
